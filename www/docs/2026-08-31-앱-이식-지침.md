# 웹을 만들면서 앱 이식을 안 깨는 법

> **상태:** 지침 · 2026-08-31 · **담당:** 백성검 (프론트·웹)
> **순서:** 지금은 **웹을 먼저 대부분 만든다.** Flutter 이식은 그 뒤다.
> 이 문서는 "그때 가서 재설계할 일을 지금 안 만들기 위한" 규칙만 적는다.
> 이식 계획서가 아니다 — 그건 웹이 어느 정도 굳은 뒤에 따로 쓴다.

## 0. 결론

**앞으로 만들 페이지도 앱으로 옮길 수 있다.** 다만 저절로 되는 게 아니라
아래 6개를 지켜야 된다. 이미 한 건이 어긋나 있다(§4).

## 1. 왜 대체로 되는가 — 어려운 건 이미 앱 것이다

지금까지 방향은 **Flutter → 웹**이었다. 값도 앱에서 가져왔고, 웹에서 제일
애먹은 렌더링도 앱엔 원본이 있다.

| 웹 | Flutter 원본 |
|---|---|
| `GlitchIntro` 의 WebGL 잉크 | `shaders/ink_bleed.frag` — **웹이 이걸 이식한 것** |
| `feTurbulence`+`feDisplacementMap` 굴절 | `shaders/liquid_glass.frag`, `refractive_glass.dart` |
| `backdrop-filter` 유리판 | `glass_panel.dart` · `glass_surface.dart` · `glass_strength.dart` |
| 배경 인물 | `figure_background.dart` |
| `--ss-*` 토큰 | `app_theme.dart` · `login_screen.dart` · `home_screen.dart` |

웹에서 데인 두 가지(`backdrop-filter` 를 Lightning CSS 가 떨어뜨리는 것,
헤드리스 스크린샷이 검게 뭉개지는 것)는 **CSS 고유의 함정이라 Flutter 엔 없다.**

### 크기 잡는 방식이 이미 같다

`flutter/lib/core/design_scale.dart`:

```dart
double d(double designPx) => MediaQuery.sizeOf(this).width * designPx / 1080;
```
> 세로 좌표도 폭으로 환산한다 — 목업의 비율을 지키려면 한 축으로만 재야 한다

웹도 같은 길로 갔다. `globals.css` 에 브레이크포인트가 아니라 **폭 비례값**이
박혀 있다 (`--ss-display-size: clamp(2.25rem, 5.56vw, 6rem)`,
`calc(max(-120px, 21.333vw - 423px) + 255px)`). **`vw` ↔ `context.d()` 는
일대일 대응이다.** 이게 이식 가능성의 절반을 떠받치고 있다.

## 2. 🔴 지킬 것 여섯

### 1) 크기는 폭 비례로 — 브레이크포인트로 화면을 갈아끼우지 않는다

`vw`·`%`·`clamp()` 로 매면 `d()` 로 그대로 옮겨진다. `md:` 에서 배치가 통째로
바뀌는 식이면 **어느 쪽을 앱으로 옮길지부터 정해야 한다** — 그게 재설계다.
지금 홈·스쿼드·선수 카드에 브레이크포인트가 0개다. 이 상태를 유지한다.

### 2) 좌우로 펼치지 않는다 — 세로 화면에서도 성립하는 배치로

폰은 세로다. 오른쪽에 판을 펼칠 자리가 없다. 무언가를 더 보여줘야 하면
**옆이 아니라 같은 자리 위**로 간다 — 오버레이·시트·화면 전환. 그러면
웹에서는 넓은 화면을 활용해 옆에 두더라도, 앱에서는 같은 컴포넌트를
시트로만 바꿔 달면 된다.

### 3) 웹 전용 기교에 **레이아웃을 의존시키지 않는다**

`backdrop-filter`·SVG 필터·`-webkit-text-stroke` 는 **장식 레이어로만** 쓴다.
그걸 빼도 글자가 읽히고 자리가 맞아야 한다. 판단 기준: **그 한 줄을 지웠을 때
화면이 성립하는가.** 성립하면 이식 시 Flutter 셰이더로 갈아 끼우면 되고,
성립 안 하면 그 화면은 앱에서 통째로 다시 짜야 한다.

### 4) 무작위는 **씨앗**으로 — 웹과 앱이 같은 무늬여야 한다

선수 카드 붓자국이 `public_slug` 를 씨앗으로 그리는 이유는 웹에선
하이드레이션이지만, **앱엔 하이드레이션이 없어도 씨앗은 그대로 둔다** —
같은 카드가 웹과 앱에서 다른 무늬면 같은 카드로 안 보인다.
`Math.random()` 은 여기서도 금지다.

### 5) 새 토큰을 만들면 **앱 대응 여부를 한 줄 적는다**

`--ss-*` 는 대부분 `flutter/lib/` 에서 온 값이다. 웹에서 새로 만든 것은
주석에 **앱에도 필요한 값인지 / 웹 전용인지**를 남긴다. 지금까지:

| 토큰 | |
|---|---|
| `--ss-field-radius`, `--ss-radius-arch` | 앱에도 필요 — 이식 때 `app_theme.dart` 로 |
| `--ss-google-btn-h` (40px) | **웹 전용.** 구글 SDK 가 iframe 버튼에 강제하는 높이라 앱엔 해당 없음 |

### 6) 마우스 전용 상호작용은 **보조**여야 한다

터치에는 hover 가 없다. 지금 마우스에 매인 곳:

| | 앱에서는 |
|---|---|
| `HomeNav` 의 `onMouseEnter`(글자에 얹으면 카드가 뜸) | 탭으로 같은 결과에 닿아야 한다 |
| `HomeStage` 의 `useMouseParallax` | **앱엔 대응이 없다.** `figure_background.dart` 는 가만히 있는다 — 움직이게 해봤다가 걷어냈다(주석에 이유가 있다). 웹 전용 덤으로 두고, 여기에 아무것도 의존시키지 않는다 |
| `GlassPanel` 의 `onMouseMove` | 위와 같다 — 없어도 유리는 유리여야 한다 |

## 3. 앱에 아직 없는 화면

이식 때 **새로 만들** 것들이다. 만들면서 §2 를 지키면 그때 옮기기만 하면 된다.

| 웹 | Flutter |
|---|---|
| `PlayerCardView` / `PlayerCardBrush` | 없음 — 누끼(`player_cutout.png`)는 그대로 재사용 |
| `SquadPanel` / `SquadSuggest` | 없음 |
| `HomeNav` / `HomeStage` | 홈은 있으나 구성이 다르다 (`home_screen.dart` 400줄) |
| 회원가입 | `login_screen.dart` 만 있다 |
| `/c/[slug]` 카드 공유 | 없음 |

**카드에 수치를 그리지 않는다**(부록 D.5)는 앱에서도 같다.
`PlayerCardView.test.tsx` 가 지키는 것을 **위젯 테스트로 같이 옮겨야**
그 방어가 유지된다.

## 4. 지금 알려진 재설계 1건

**스쿼드 판의 AI 추천이 오른쪽으로 펼쳐진다.** 1440px 기준이라 세로 폰에는
자리가 없다 — §2-2 를 어긴 유일한 곳이다. 웹을 더 만지는 김에 **같은 자리
위로 덮는 구조**(오버레이/시트)로 바꿔두면 이식 때 재설계가 사라진다.
급하지 않다. 스쿼드 판을 다음에 손볼 때 같이 하면 된다.

# 레슨 · 상점 설계

> **상태:** 설계 확정 · 2026-09-01 · **담당:** 백성검 (프론트·웹)
> **범위:** `www/` 화면만. 계약(`fastapi/docs/api-contract.md`) · DB(부록 D) · 제안서는 건드리지 않는다.
> 화면이 먼저 가고 **그것이 규격의 근거가 된다** — 영상 분석 화면이 리포트 조회 규격의
> 근거가 된 것과 같은 방식이다.

## 0. 한 줄

레슨은 **코치와 연결**해 주고 성사에 수수료를 받는다. 상점은 **제휴 브랜드로 내보내는
링크**이고, 그 링크가 어떤 영상에서 나갔는지를 기록해 **영상 주인에게 수수료를 나눈다.**

## 1. 정한 것과 그 근거

### 1-1. 상점은 우리가 결제하지 않는다 (링크 모델)

```
① 우리 화면      영상에 태그된 상품 → [브랜드에서 보기 ↗]
                    링크에 우리 ID + 영상 주인 ID 가 박혀 있다
② 브랜드 사이트   구매자가 여기서 결제한다      ← 돈은 브랜드가 받는다
③ 정산(월 1회)   브랜드 / 제휴 네트워크 → 우리
④ 분배           우리 → 영상 주인에게 그중 몇 %
```

**우리가 결제를 받아야 수수료를 줄 수 있는 것이 아니다.** 링크에 누가 보냈는지가 박혀
있어서 브랜드 쪽에서 귀속이 된다(링크프라이스 · 아이라이크클릭 · 쿠팡파트너스, 해외는
Impact · CJ 같은 제휴 네트워크가 그 추적과 정산을 대신한다).

우리가 결제를 받으면 그건 어필리에이트가 아니라 **입점몰(위탁판매)** 이고, PG · 재고 ·
배송 · 반품 · 세금계산서가 다 따라오며 전자상거래법상 통신판매업자 책임도 우리에게 온다.
10주에 무리이고, 무엇보다 하려는 것이 그게 아니다.

| 선례 | 무엇으로 버나 |
|---|---|
| Strava 등 스포츠 앱 | 브랜드 스폰서 캠페인 (어필리에이트 프로그램 자체가 없다) |
| **YouTube 쇼핑 제휴 · LTK · 인스타그램** | **영상에 태그 → 링크 → 크리에이터 수수료** ← 우리가 하려는 것 |
| 무신사 · 쿠팡 | 직접 결제(입점몰) |

우리는 **스포츠 앱인데 영상이 중심**이라 가운데 줄을 따른다. Strava 에는 영상이 없어서
못 하는 것을 우리는 할 수 있고, 그게 차별점이다.

### 1-2. 레슨은 신청까지(A) — 결제(B)로 갈 수 있게

| | 걷는 방식 | 이탈 위험 | 선례 |
|---|---|---|---|
| **A. 신청까지** ← 채택 | 성사되면 청구 | 높음 | 숨고 · Superprof |
| B. 예약 · 결제까지 | 결제에서 자동 차감 | 낮음 | CoachUp |
| C. 코치가 연결권을 미리 삼 | — | 없음 | 숨고(견적 발송 건당 2,700원) |

**A 를 고르되 화면을 B 로 갈 수 있게 짠다.** 목록 · 상세 · 신청서는 그대로 두고
"연락처가 열린다"를 "시간을 고르고 결제한다"로 바꾸기만 하면 된다.

수수료 자체는 이 바닥의 표준이다(탈잉 30~40% · 크몽 15~20% · 우리 안 5~10%). 걱정할
것은 요율이 아니라 **이탈(disintermediation)** 이다 — 연결해 주고 나면 둘이 밖에서
만나 두 번째 레슨부터 우리가 못 본다.

🔴 **우리의 이탈 방지 장치는 감시가 아니라 영상 분석이다.**

```
레슨 전   영상 분석 → 리포트   "디딤발이 공보다 앞서 있습니다"
              ↓ 이 리포트를 들고 코치에게 간다
레슨                           코치가 그 항목을 본다
              ↓
레슨 후   다시 분석 → 리포트   "무릎이 더 덮입니다"
```

밖에서 만나면 이 before/after 가 없다. 코치도 "내 레슨으로 이만큼 좋아졌다"를 증명할
데가 여기밖에 없다. 수수료를 받아도 떳떳한 근거가 이것이고, **화면에 그게 보여야 한다.**

### 1-3. 코치를 고르는 "우리만의 기준"

| | 기준 | 다른 곳 |
|---|---|---|
| **간판** | **코치 본인의 분석 데이터** — 코치도 영상을 올려 같은 잣대로 잰다 | 없음 |
| 받침 | 자격 · 경력 · 신원 확인 | CoachUp |
| 자리만 | 가르친 사람들의 레슨 전/후 변화 | 없음 |
| 곁들임 | 후기 · 평점 | 어디나 |

다른 데는 "국가대표 출신"이라고 **본인이 적고**, 우리는 **같은 잣대로 잰 리포트**를
보여준다. 형식은 영상 분석 화면과 똑같이 — 사용자가 자기 리포트에서 이미 본 모양이라
읽는 법을 새로 배울 것이 없다.

🔴 **코치에게도 수치를 그리지 않는다.** 카드에 능력치 컬럼을 두지 않는 원칙(부록 D.5)이
그대로 적용된다 — 호칭과 문장과 장면뿐이다. `PlayerCardView` 를 재사용하면 그 방어
(테스트)도 같이 따라온다.

🔴 **"가르친 사람들의 변화"를 비워 두는 것이 설계다.** 레슨이 쌓이면 그 자리에 들어오고,
자리를 미리 만들어 두면 나중에 화면을 다시 안 짠다.

## 2. 화면

내비 항목은 `레슨 · 상점` 하나지만 두 갈래는 **의도가 다르다**(배우러 옴 vs 사러 옴).
입구는 하나, 안에서 갈라진다 — 목록으로 바로 보내면 한 항목에 두 화면이 걸려 어느 쪽이
열릴지 예측이 안 된다(홈에서 알약 셋을 나눈 것과 같은 이유).

```
/market                      레슨 · 상점 입구
├─ /market/coaches           코치 목록      종목 · 지역 · 수준 · 가격
│   └─ /market/coaches/[id]  코치 상세      ← "우리만의 기준"이 사는 곳
│        └─ 레슨 신청(시트)
└─ /market/shop              상품 목록      브랜드 · 종목 · 갈래
    └─ /market/shop/[id]     상품 상세      → [브랜드에서 보기 ↗]

/v/[slug]                    공개 영상 — 영상 + 뼈대 + 리포트 + 상품 캐러셀
/me/lessons                  내 레슨 신청 내역
/me/earnings                 내 수익 — 클릭 · 구매 · 정산
```

### 🔴 `/v/[slug]` 가 없으면 어필리에이트가 성립하지 않는다

영상은 지금 분석 화면 안에서 **내가 볼 때만** 존재한다(브라우저 안에서만 재생, 서버 저장
없음 — 계약 5장 ASM-003). 그런데 수수료는 **남이 내 영상을 보다가** 링크를 눌러야 생긴다.
YouTube 쇼핑도 LTK 도 영상이 공개되는 자리가 먼저 있고 그 아래에 상품이 붙는다.

### 코치 상세의 뼈대

```
김OO · 축구 · 강남                          [ 레슨 신청 ]
① 이 코치의 분석     선수 카드 + 리포트 요약 + 이렇게 본 장면 + [영상 보기 ↗]
② 확인된 것         신원 확인 · 지도자 자격 · 선수 이력
③ 가르친 사람들의 변화   (아직 데이터가 쌓이지 않았습니다)
④ 후기   ⑤ 레슨 정보(장소 · 시간대 · 가격)
```

### 레슨 신청서에 **내 리포트가 붙어서 간다**

```
무엇을 고치고 싶으신가요?
 ☑ 디딤발이 공보다 앞서 있습니다      ← 내 분석 리포트에서 고른다
 ☐ 측면으로 벌리는 움직임이 많습니다
 + 직접 적기
희망 날짜 · 시간대 · 장소 · 하고 싶은 말
```

숨고에는 "축구 배우고 싶어요"가 오지만, 우리는 **코치가 무엇을 봐야 하는지 알고 시작한다.**
A 안이 남들보다 나은 지점이 여기다.

### 상점은 "우리가 파는 게 아니다"를 숨기지 않는다

구매 · 배송 · 교환 책임이 브랜드에 있으니 화면에서도 그렇게 읽혀야 한다. 감추면 문제가
생겼을 때 우리에게 온다.

상품 목록의 `영상 12` 는 그 장비가 나온 영상 수다 — **상품 ↔ 영상 양방향**이 우리만
가진 것이다. 브랜드가 쓴 설명 대신 그 장비를 신고 뛴 영상이 붙는다.

### 영상 태그는 **시각과 함께** 단다

우리 영상엔 이미 `이렇게 본 장면 0:04 · 0:07 · 0:11` 이라는 시간 문법이 있다. 태그도 같은
결로 붙고, 재생하다 그 시각이 오면 아래 캐러셀에서 그 상품이 살아난다.

### 수익은 **확정과 대기를 나눠** 보여준다

어필리에이트는 구매 즉시 확정이 아니라 반품 기간이 지나야 확정된다. 안 보여주면 "왜 돈이
줄었냐"는 말이 나온다.

## 3. 이 설계가 계약서에 요구하는 것

화면만 만들지만 나중에 정어진 · 정상호에게 넘길 규격이 이만큼 나온다.

| 무엇 | 지금 상태 |
|---|---|
| `coach` 프로필 조회 · 코치의 분석 리포트 연결 | 테이블은 있다(부록 D ⑥) · 엔드포인트 없음 |
| `coach_referral` 생성(신청) · 수락 · 연락처 공개 | 테이블은 있다 · 엔드포인트 없음 |
| 브랜드 · 상품 목록(제휴 카탈로그) | **테이블 없음** |
| 영상–상품 태그 `(video_id, product_id, at_ms)` | **없음** |
| 추적 링크 발급(우리 ID + 영상 주인 ID) | **없음** |
| 클릭 · 구매 집계와 정산 상태 | **없음** |
| 공개 영상 조회(영상 + 리포트) | **리포트 조회 규격 자체가 미결** |

아래 넷은 부록 D.8 이 *"브랜드 제휴는 본 개발 기간 범위 밖이므로 테이블을 두지 않는다"*
고 적어 둔 부분이다.

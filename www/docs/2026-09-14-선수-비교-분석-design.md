# 선수 비교 분석 — 설계 (2026-09-14)

> 분석 화면의 「선수와 비교하기」를 **자세 비교**로 키운다. 선수를 고르면 두 영상에서
> 관절을 뽑고, **세 순간(직전 · 임팩트 · +1초)** 의 뼈대를 겹쳐 보여 주고, 무엇이
> 다른지를 **코드 규칙 문장**으로 정리한다(2026-09-14 결정 — Gemini 는 나중에 얹을 수 있다).
>
> 🔴 **이번 것은 데모다** — 계산을 브라우저가 대신한다(아래 「방식」). 최종 모습은
> 에이전트가 계산한 값을 서버에서 받는 것이고, 그때 **바꾸는 자리는 `source.ts` 하나**다.

## 0. 범위

| 한다 | 안 한다 |
|---|---|
| `www/` 안: 화면 · 브라우저 계산 · 규칙 문장 요약 | `fastapi/` · `agent/` · S3 · 배포 · `flutter/` |
| 미결 항목에 서버 쪽 요청 올리기(§6) | 서버 쪽 코드를 대신 짜기(정어진 부재 — 오늘은 요청만) |

선수 영상은 지금 `www/public/compare/` 의 **Pexels 무료 영상 둘**이다(15436954 ·
15436958). 저작권은 문제없다. 다만 Pexels 라이선스가 「영상 속 사람이 보증하는 것처럼
보이게 하지 말 것」을 요구하므로 화면에 **「데모 영상(Pexels)」** 을 표기한다.

## 1. 결정 요약 (사용자와 정한 것)

| 무엇 | 정한 것 | 왜 |
|---|---|---|
| 방식 | **A — 전부 브라우저에서** | 지금 데모가 된다. 서버로 옮길 때 바꿀 곳이 하나다 |
| 임팩트 | 차는 다리 **무릎 신전 각속도가 최대인 프레임** | 에이전트 `segment_phases` 의 `extension_peak` 과 같은 정의 — 서버 값으로 바꿔도 뜻이 안 갈린다 |
| 직전 | 🔴 **정정 (2026-09-15)** — **임팩트 0.3초 전**(그 프레임에 그 다리 무릎각이 없으면 가장 가까운 잡힌 프레임) | 처음엔 「임팩트 전에 차는 다리 무릎이 가장 굽은 프레임」(0.5초 안 최소각)이었는데, 그 프레임이 구조상 임팩트 바로 한 프레임 전으로 쏠려(실측 두 데모 클립 다 59/60·52/53) 직전·임팩트 두 카드가 거의 같은 자세로 보였다. 사용자 결정으로 고정된 0.3초 전으로 바꿨다 |
| +1초 | 임팩트 + 1.0초 | 영상이 먼저 끝나면 마지막 프레임 + 「영상 끝」 표시 |
| 겹침 기준 | **골반 중심 + 몸통 길이** | 키 · 카메라 거리 차이를 지우고 자세 차이만 남긴다 |
| 좌우 | **차는 방향이 다르면 선수 쪽을 자동으로 뒤집어** 사용자에 맞춘다 + 되돌리는 토글 | 방향 판별이 틀릴 수 있다(에이전트 실측에서도 다리 판별이 약했다). 차는 **발**만 다를 때는 안 뒤집는다 — 뒤집으면 방향이 오히려 갈린다 |
| 리포트 | **코드 규칙 문장**(처음엔 「각도 수치만 Gemini 에」로 정했다가 바꿨다) | 목적이 「수치가 뭐가 다른지」라 LLM 이 필요 없다 — 키 · 비용 · 지연 · 실패 처리가 없고 숫자가 늘 정확하다. 코칭 조언을 원하면 같은 순간별 각도 표(`SummaryRequest`)를 Gemini 에 넘기는 층을 얹는다 |
| 카드 누르기 | 위 두 영상이 **그 순간으로 이동해 멈춤**, 다시 누르면 재생 | 겹친 뼈대가 실제 장면 어디인지 바로 보인다 |

## 2. ① 데이터 흐름과 모듈

```
선수 선택 → 「찾고 있는 중」(지금 그대로) → 영상 칸이 반으로 갈림(지금 그대로)
  └ source.getMotion(선수 영상) ┐  나란히, 진행률은 둘을 합친 값
  └ source.getMotion(내 영상)   ┘
       ↓ Motion ×2
  moments(Motion)  → 세 순간 프레임 (각자)
  align(선수, 나)   → 겹칠 좌표 · 반전 여부
  angles(...)       → 순간별 각도 표
       ↓
  화면 전환(§3) + 규칙 문장 요약(§4)
```

### 모듈 (`www/src/lib/motion/`)

| 파일 | 하는 일 | 순수? |
|---|---|---|
| `types.ts` | `Motion` · `Moments` · `MetricRow` | — |
| `source.ts` | 🔴 **교체 지점.** `getMotion(input, onProgress) → Promise<Motion>` | 아님 |
| `extract.ts` | 브라우저 구현 — 보이지 않는 `<video>` 를 넘기며 검출 | 아님 |
| `moments.ts` | 차는 다리 · 임팩트 · 직전 · +1초 | **순수** |
| `align.ts` | 골반 중심 · 몸통 길이 정규화 · 좌우 반전 | **순수** |
| `angles.ts` | 순간별 각도 | **순수** |

```ts
type Motion = {
  fps: number                  // 실제로 잰 간격(초당 장수)
  aspect: number               // 영상 가로/세로 — 좌표가 0~1 로 따로 눌려 있어 각도를 잴 때 되돌린다
  frames: (Point[] | null)[]   // 프레임마다 COCO 17점, 못 잡은 프레임은 null
  measuredBy: 'browser' | 'agent'
}
type Moments = { kickingLeg: 'left' | 'right'; direction: 1 | -1; before: number; impact: number; after: number; afterClipped: boolean }
```

`Point` · 관절 순서는 기존 `lib/pose.ts` 그대로다(COCO 17점 — 에이전트와 같은 형식).

### 뽑기 (`extract.ts`)

- **보이지 않는 `<video>`** 를 따로 만든다 — 화면의 영상은 계속 재생된다.
- **초당 15장**으로 `currentTime` 을 옮기고 `seeked` 를 기다려 검출한다. 검출은 기존
  `detectPeople` + `refinePose`(2단계) 그대로.
- **누구를 뽑나**: 선수 영상은 **가장 큰 사람**(에이전트 `_largest_person_box` 와 같은
  규칙). 내 영상은 **처음 묶은 사람**(`subject.box` · `subject_at_ms`)에서 시작해 기존
  추적기(`createPersonTracker`)로 **앞뒤 양쪽**으로 이어 간다.
- 선수를 바꾸거나 닫으면 **중단**한다(돌던 검출이 새 화면에 끼어들지 않게).
- 내 영상 결과는 같은 영상이면 **다시 쓴다** — 선수만 바꿔 볼 때 다시 훑지 않는다.

### 세 순간 (`moments.ts`)

1. 무릎 각도 시계열(엉덩이–무릎–발목)을 다리마다 만든다. 못 잡은 프레임은 비워 둔다.
2. **차는 다리** = 신전 각속도 최대치가 더 큰 쪽.
3. **임팩트** = 그 다리의 신전 각속도 최대 프레임.
4. 🔴 **정정 (2026-09-15)** — **직전** = `max(첫 잡힌 프레임, 임팩트 − round(0.3 × fps))`.
   그 프레임에 그 다리 무릎각이 없으면 `[첫 잡힌 프레임, 임팩트 − 1]` 안에서 가장 가까운
   잡힌 프레임(동률이면 이른 쪽)을 대신 쓴다 — 대체값이 늘 있다: 임팩트의 각속도를 재려면
   `임팩트 − 1`이 반드시 잡혀 있어야 하므로 그 구간엔 후보가 항상 있다.
   (예전엔 「임팩트 앞 0.5초 안에서 그 다리 무릎 각도가 최소인 프레임」이었는데, 그 프레임이
   구조상 임팩트 바로 한 프레임 전으로 쏠려 직전·임팩트 두 카드가 거의 같은 자세로 보였다.)
5. **+1초** = 임팩트 + fps. 넘치면 마지막 유효 프레임, `afterClipped = true`.
6. 🔴 에이전트와 같이 **임팩트가 유효 구간 경계에서 2프레임 안이면 실패**로 돌려준다
   (동작이 잘린 영상 — 지어내지 않는다).

### 겹치기 (`align.ts`)

- 순간마다 두 뼈대를 **골반 중심을 원점**, **몸통 길이(어깨 중점–골반 중점)를 1**로 맞춘다.
- **차는 방향** = **임팩트 바로 한 프레임 전(임팩트 − 1)** → 임팩트 사이 차는 발목의 가로
  이동 부호(🔴 정정, 2026-09-15 — 예전엔 「직전→임팩트」였는데, 직전이 이제 0.3초 앞이라
  되접는 도중일 수 있어 그 구간의 이동 부호가 실제 차는 방향과 반대로 나올 수 있다.
  `임팩트 − 1`은 펴는 도중의 마지막 한 걸음이라 안정적이다). 두 사람의 **방향이 다르면**
  **선수 쪽을 좌우 반전**하고 `mirrored = true`. 사용자 토글이 이 값을 뒤집는다.
- 가로 좌표에는 `aspect` 를 곱해 화면 비율을 되돌린 뒤 잰다.

### 각도 (`angles.ts`) — 루브릭 이름을 그대로 쓴다

| 순간 | 항목(루브릭 id) | 계산 |
|---|---|---|
| 직전 · 임팩트 | 디딤발 무릎 굽히기(`plant_knee_flexion`) | 디딤발 엉덩이–무릎–발목 각 |
| 직전 · 임팩트 | 차는 다리 뻗기(`swing_knee_extension`) | 차는 다리 엉덩이–무릎–발목 각 |
| 직전 · 임팩트 · +1초 | 상체 기울기(`trunk_lean`) | 어깨 중점→골반 중점 선과 수직선의 각(차는 방향 쪽이 +) |
| +1초 | 차고 난 뒤 마무리(`follow_through`) | 차는 다리 엉덩이 굴곡(몸통 선–허벅지 선 각) |

**넣지 않는 것**: 골반 돌리기(`hip_rotation`) — 2D 옆모습에서 회전량이 거의 안 보인다 ·
디딤발 위치(`plant_foot_position`) — 공 위치가 필요하다(루브릭도 공 검출에 묶어 둠).

## 3. ② 화면 전환과 레이아웃

**1단계 — 선수를 고른 직후 (지금 화면 그대로)**: 두 영상 + 뼈대. 오른쪽 판의 비교 문장
자리에 「두 영상에서 자세를 뽑는 중 · 42%」.

**2단계 — 다 뽑히면**

```
┌──────── 선수 ────────┬───────── 나 ─────────┐  ← 틀 안 위쪽 약 55% 로 줄어듦
├──────────────────────┴──────────────────────┤
│  [직전]          [● 임팩트]         [+1초]    │  ← 아래에서 올라옴
│  하늘(선수)+초록(나) 겹친 뼈대                 │
│  디딤발 무릎 142° / 158°                       │
│  선수 ━  나 ━  · 좌우 반전됨 ⇄ · 브라우저에서 잰 값 · 데모 영상(Pexels) │
└──────────────────────────────────────────────┘
```

- 전환은 약 0.6초, 영상 칸 키와 카드 줄이 **한 동작**으로 움직인다. **틀 전체 크기는
  그대로** — 오른쪽 판 · 머리줄이 안 흔들린다.
- 카드를 누르면 두 영상이 그 프레임 시각으로 가서 멈춘다(선택 카드 표시). 다시 누르면 재생.
- 🔴 **나중에 붙는 것에 지연 연출을 걸지 않는다**(09-11 에 세 번 밟았다). 카드는 결과가
  오는 순간 붙는다. `prefers-reduced-motion` 이면 연출 없이 바뀐다.
- 닫기 · 다른 선수 → 역순으로 되돌린다. 뽑기 중이면 중단.

**실패**

| 상황 | 화면 |
|---|---|
| 순간을 못 찾음(어느 한쪽이라도) | 2단계로 안 간다. 「이 영상에서 슈팅 순간을 찾지 못했습니다」. 영상 비교는 그대로 |
| 검출기를 못 올림 | 뼈대 없이 영상만 + 같은 안내 |

## 4. ③ 비교 요약 — 코드 규칙 문장

> 🔴 **정정 (2026-09-14)** — 처음엔 Gemini 서버 라우트로 정했으나 사용자와 다시 정해 **규칙
> 문장**으로 바꿨다. 순간별 각도 표(`SummaryRequest`, `lib/motion/summaryContract.ts`)는 그대로라
> Gemini 를 나중에 얹을 때 그 표를 넘기면 된다. 그때 쓸 응답 파싱 · 숫자 검사(입력 값이나 차이 ±1
> 만 허용)는 이미 같은 파일에 있다.

- **어디서**: `lib/motion/describe.ts` — 서버를 부르지 않는다. 키 없이 로컬에서도 보인다.
- **줄 하나**: `{항목} 선수 N° · 나 M° — {말}`. 차이가 **5° 미만**이면 「비슷합니다」.
  말은 항목마다 방향이 다르다(무릎각이 크면 「덜 굽혔습니다」, 뻗기가 크면 「더 폈습니다」,
  상체 기울기가 크면 「차는 방향으로 더 기울었습니다」, 마무리가 크면 「더 높이 들었습니다」).
- **순간**: 그 순간에 잰 항목이 없으면 「이 순간은 잴 수 없었습니다」.
- **총평**: 5° 이상 차이 중 **가장 큰 것** 하나를 짚는다. 모두 5° 미만이면 「세 순간 모두 선수와
  비슷합니다.」, 잰 것이 없으면 「잴 수 있는 순간이 없어 비교하지 못했습니다.」
- **자리**: 오른쪽 판 **내 분석 리포트 바로 아래** 「비교 — 선수 이름」 절. 순간 줄을 누르면 §3
  카드와 같은 동작. 아래 작은 글씨 「브라우저에서 잰 값 · 차이 5° 미만은 비슷함으로 봅니다」.
- **순간을 못 찾음**: 절에 이유와 「슈팅 순간을 찾지 못해 비교하지 않았습니다」.

## 5. 확인 방법

- **순수 함수**(가짜 관절로 먼저 실패시키고 고친다): 차는 다리 · 임팩트 = 각속도 최대 ·
  직전 = 최소 각 · +1초 넘침 · 경계 실패 · 차는 방향 · 정규화(골반 원점 · 몸통 1) ·
  반전 조건 · 각도 값(화면 비율 보정 포함).
- **규칙 문장**: 비슷함 경계(5°) · 항목별 방향 말 · 빈 순간 · 총평 세 갈래.
- **화면**: 뽑는 중 → 카드 · 카드 누르면 두 영상 `currentTime` 이동 · 요약 절 · 반전 토글.
- **실물**: 로컬엔 백엔드가 없어 **전체 흐름은 배포에서만** 본다. 그 전엔
  임시 페이지(커밋하지 않음)로 두 데모 영상의 뽑기 · 세 순간 · 겹침을 헤드리스로 잰다.

## 6. 최종(B)으로 가는 길 — 미결 항목에 올릴 요청(초안)

`paik` 구역에 올린다(28번 「선수와 비교하기」와 연결). **바꾸는 쪽은 `source.ts` 하나** —
아래 모양의 `Motion` 을 서버가 주면 화면 · 리포트는 그대로 쓴다.

**정어진 — 선수 영상과 그 분석 결과를 읽는 경로**
- 만족할 성질: 선수 영상 목록(이름 · 재생 주소) · 영상 하나의 **프레임별 관절(COCO 17점) +
  fps + 세 순간**을 읽을 수 있을 것. 내 영상도 같은 모양으로 읽을 수 있을 것(지금 리포트
  경로는 점수 · 근거 위주).
- 확인: 분석이 끝난 영상으로 불러 `frames.length / fps ≈ 영상 길이`.
- 하지 말 것: 관절을 화면용으로 줄이거나 다시 뽑기 — 에이전트 결과 그대로.

**정상호 — 결과에 관절 시계열과 세 순간 싣기**
- 만족할 성질: 분석 결과에 프레임별 관절 · fps 와 **임팩트(`extension_peak`) · 직전(🔴 정정,
  2026-09-15 — 임팩트 0.3초 전. 그 프레임에 무릎각이 없으면 가장 가까운 잡힌 프레임) · +1초**
  프레임 번호가 실릴 것. 선수 영상 두 편(15436954 · 15436958)도 같은
  파이프라인으로 분석.
- 확인: 같은 영상에서 데모(브라우저)가 찾은 임팩트와 **0.2초 안**에서 만나는지 — 더 갈리면
  데모 쪽 정의를 고친다(서버가 정본이다).

## 7. 넣지 않는 것 (YAGNI)

선수 관절 미리 계산해 파일로 두기(C안 — 느리다고 느껴질 때 캐시로 얹는다) · 골반 회전 ·
디딤발 위치 · Gemini 코칭 문장(나중에 얹는다) · 모바일 앱 이식.

### 🔴 "도메인이 안 열린다"의 정체 — 웹이 아니라 백엔드였다

`supersub-ai.com` 이 **This page couldn't load / A server error occurred** 를
냈다. 그런데 `curl` 로는 200 이 나왔다 — **쿠키가 없었기 때문**이다.

| 어떻게 부르나 | 무슨 일이 나나 |
|---|---|
| 쿠키 없이 | 307 → `/login` → 200. `x-nextjs-prerender: 1` 인 **미리 구운 페이지**라 백엔드를 안 부른다 |
| **쿠키를 들고** | `/` 가 `requireUser()` → 백엔드 `GET /me` → **500** |

`GET /api/me` 가 `BACKEND_UNREACHABLE` 을 돌려줬고, API 호스트는 DNS 는 풀리는데
**ping · TCP 22 · 80 · 443 · 8000 이 전부 무응답**이었다(refused 가 아니라
timeout — 프로세스가 죽은 것이 아니라 기계가 안 떠 있다는 뜻이다). 그날 안에
살아났다.

- 🔴 **"Vercel 에 올라가 있는데 왜 안 뜨나"의 답**: 올라간 것은 HTML 이 아니라
  **코드**다. `/` 는 서버 컴포넌트라 요청마다 Vercel 에서 실행되고, 그 실행이
  백엔드를 부른다. 재료를 못 가져오면 HTML 이 안 만들어진다
- ⚠️ **남은 구멍**: `requireUser()` 가 401(썩은 토큰)만 `/login` 으로 보내고
  **503(서버 불통)은 그대로 던진다.** 그래서 팀원 눈에는 "웹이 깨졌다"로 보인다.
  안내 화면으로 떨어뜨리는 것은 아직 안 했다

### 🔴 챗봇에 글을 쓰다가 화면이 넘어갔다 — 스페이스가 「내려가기」였다

「안녕하세요. 」까지 치면 영상 모음으로 넘어갔다(사용자 지적). 홈이 자판으로도
오갈 수 있게 `ArrowDown`·`PageDown`·**스페이스**를 「내려가기」로 받는데,
**어디서 눌렀는지를 안 봤다.** 그 셋은 하필 글 쓰는 사람에게도 오는 것들이다 —
스페이스는 **띄어쓰기**이고 화살표는 **글자 사이를 오가는 것**이다.

굴림 쪽은 이미 `onOwnPanel` 로 갈라 놓았는데(1.2 절), **자판에는 그 검사가
아예 없었다.** 셋을 세웠다.

| 검사 | 왜 |
|---|---|
| `isTyping(e.target)` | 입력칸 · textarea · `contenteditable` — **판 밖**에 생긴 입력칸도 막아야 해서 판 검사로는 부족하다 |
| `onOwnPanel(e.target)` | 굴림과 같은 판단. 판 안의 단추에 초점이 있을 때 스페이스가 새는 것을 막는다 |
| `e.isComposing` | 🔴 **한글**. IME 가 글자를 맞추는 동안의 스페이스는 조합을 끝내는 신호지 「내려가기」가 아니다. 조합 중인 IME 창에서 오면 위 둘에 안 걸린다 |

**빈 자리에서 누르면 여전히 넘어간다** — 자판으로 오가는 길을 막으면 굴림이
없는 사람에게 다른 길이 없다.

#### 확인 — 시험이 먼저 빨개지는 것을 보고 고쳤다

되는 시험이라는 뜻이라 그다음에 고쳤다.

그리고 **jsdom 은 한글 IME 를 흉내내지 못하므로** CDP 로 실물에서 다시 쟀다 —
진짜 마우스로 AI 단추를 누르고, 입력칸에 진짜 글쇠를 넣고, `Input.imeSetComposition`
으로 조합 중까지 만들었다.

```

✅ 입력칸 ArrowDown       기록: home
✅ IME 조합 중 스페이스   기록: home
✅ 빈 자리 ArrowDown      기록: feed   ← 길은 막지 않았다
```

### 스쿼드 판 — 골키퍼 줄은 한 칸, 포지션 글자는 잔디색

- **골키퍼 줄(행 3)은 가운데 한 칸뿐이다**(사용자 요청). 축구에서 골키퍼는
  하나이고 골대 앞 가운데에 선다 — 양옆 칸을 두면 판이 "골키퍼가 셋일 수도

  하프라인 위, GK 가 골 에어리어 위에 얹힌다. 잔디색으로 바꿔 봤다가 **같은 날

#### 🔴 글자 색이 아니라 선의 무게가 문제였다 — 되돌리고 다시 고쳤다

이름표를 잔디색으로 칠했는데, 사용자가 **글자는 흰색으로 두고 선을 물리라**고
정정했다. 맞는 진단이었다 — 겹쳐 보인 원인은 글자 색이 아니라 **경기장 선이
글자와 같은 무게의 흰색**이어서 둘이 서로를 갉아먹은 것이다.

| | |
|---|---|
| 포지션 글자 | **온전한 흰색**으로 되돌림 — 읽혀야 하는 쪽이다 |
| 판 **바깥 테두리** | 온전한 흰색 그대로 — 흐리면 판이 어디까지인지 안 보인다 |
| **안쪽 선 전부** | **흰색 30%** — 하프라인 · 센터서클 · 가운데 점 · 페널티/골 에어리어 넷. 카드가 얹히는 바탕이다 |

바깥 `<rect>` 에만 이름(`.ss-squad-pitch-edge`)을 주고 나머지는 SVG 의 기본
`stroke` 를 물렸다 — 안쪽 것이 늘어나도 자동으로 같은 무게가 된다.

#### 🔴 「이동 못하게」를 어디까지로 볼지 — 물어보고 정했다

처음에 **자리를 통째로 잠그는** 쪽으로 만들었더니 **시험 넷이 빨개졌다.** 모든
포메이션에서 골키퍼는 `row 3, col 1` 한 자리라, 잠그면 3:3 에서 셋 다 윗줄로
올리는 **「전원 FW」가 불가능**해진다 — **같은 날 아침에 요청받아 만든 동작**이다.

같은 말이 두 가지로 읽히고 둘의 결과가 다른 자리라 물었고, **「양옆으로만 못
가게」**로 정했다(사용자 결정). 위아래는 그대로 된다.

> ⚠️ 시험이 그 충돌을 먼저 잡아 줬다. 잠금을 그냥 넣고 시험을 고쳤으면
> 아침에 만든 동작이 조용히 사라졌을 것이다.

#### 확인


> 처음에 `rgba` 로 기대했다가 멀쩡한 값을 실패로 셌다 — 재는 쪽이 틀렸던 것이다.

### 글자 줄이 뒤집혔다 — 아이콘이 글자 위로, 유리판은 사라졌다

전에는 **글자가 버튼이고 떠오른 유리 카드가 링크**였다. 지금은 반대다(사용자 요청).

| | 전 | 후 |
|---|---|---|
| 아이콘 | 떠오르는 유리 카드 **안** | **글자 위**, 같은 링크 안 |
| 이동 | 떠오른 카드를 눌러서 | **아이콘 · 글자**를 눌러서 |
| 떠오르는 것 | 유리판 + 아이콘 + 설명 | **설명 글자만**(알약 줄이 이미 쓰던 `bare`) |

🔴 **뒤집어도 한 항목에 링크는 하나다.** 둘 다 링크로 두면 같은 곳으로 가는
링크가 둘이 되어 낭독기에서도 시험에서도 어느 쪽인지 모호해진다 — **원래 글자를
버튼으로 둔 이유가 정확히 그것**이었고, 이제 반대쪽(설명)이 버튼이다.

- 🔴 **갈 곳이 없으면 링크가 아니라 버튼이다.** `<a>` 를 href 없이 두면 Tab 으로
  닿지도 않고 눌러도 아무 일이 없어 "왜 안 되나"만 남는다. 아직 안 열린 목적지가
  있어 `Trigger` 가 그 둘을 가른다
- 🔴 **「로그인이 필요합니다」는 판이 없어져도 남긴다.** 개발 진행 상태가 아니라
  **사용자가 할 일**이라, 못 들어가는 곳을 눌러 보고 나서야 알게 하면 안 된다
- ⚠️ **눌러서 고정하는 장치를 걷어냈다.** 누르는 것이 이동이 되면서 고정할 자리가
  없어졌고, 그것을 풀던 문서 전역 리스너(바깥 클릭 · Esc)와 시험 둘도 함께 뺐다 —
  풀 것이 없는 자리를 지키는 코드였다
- 아이콘 20 → **24px**, 글자 0.8125 → **0.875rem**(사용자 요청: "살짝씩만 키워줘")

### 알약이 「팀장 · 팀원」이 됐고, 팀원 판은 **진짜 서버 목록**이다

「용병 찾기 · 팀 찾기」를 **「팀장 · 팀원」**으로 바꿨다(사용자 요청). 두 알약이
*무엇을 찾는가*가 아니라 **내가 어느 쪽인가**를 고르는 자리가 됐다.

「팀원」을 누르면 **스쿼드 판이 물러나고 그 자리에** 아직 사람을 못 채운 팀들의
명단이 선다(`TeamSeek`). 나란히 안 세운다 — 스쿼드 판은 *내 팀을 짜는* 자리이고
그 판은 *남의 팀에 들어가는* 자리라, 같이 보이면 무엇을 하고 있는지가 흐려진다.

- 🔴 **스쿼드 판을 `hidden` 으로 빼지 않는다.** 통째로 빼면 자리가 접혀 새 판이
  설 크기를 잃는다. 그 크기(518×702)는 카드 폭 · 칸 간격에서 **계산되는** 값이라
  숫자를 베껴 오면 카드 크기를 바꿀 때 어긋난다 — `visibility` 로 감춰 자리는
  남기고 접근성 트리에서만 뺀다. 실측으로 두 판의 어긋남이 **최대 0.22px**
- 「팀원」도 **한 번 더 누르면 닫힌다**(토글). 스쿼드 판을 대신 서므로 닫을 길이
  판의 × 뿐이면 되돌릴 방법이 없다 — 「팀장」과 같은 규칙이다

#### 🔴 이 판은 붙박이가 아니다 — 계약 `GET /matches` 를 그대로 부른다

지인 판 · AI 추천 판이 아직 붙박이인 것과 갈리는 점이다(그쪽은 계약에 자리가
없다). 이건 **정어진 님이 2026-09-03 에 이미 열어 둔 경로**이고 미결 `jin` 15번이
"화면을 그려 달라"고 올린 것이었다 — 그 항목에 진행 상황을 적었다.

| 층 | 무엇 |
|---|---|
| 타입 | `OpenMatch`(= `Match` + 팀 이름 · 지역 · 종목) · `MatchSearch` 페이지 봉투 |
| 접점 | `searchMatches(token, {sport_code, region, page, size})` |
| BFF | `GET /api/matches` |
| mock | `OPEN_MATCHES` 넷 — **내 팀 경기(`DEMO_MATCHES`)와 갈라 뒀다.** 한 배열로 뭉치면 내 팀이 내 팀에 지원하는 목록이 된다 |

🔴 **빈 값을 실어 보내지 않는다.** `sport_code=` 는 "전체"가 아니라 **없는 종목**
이라 422 `UNKNOWN_SPORT` 로 튕긴다(계약이 그렇게 정했다 — 오타와 "그 종목 경기가
없다"가 같아 보이면 안 되니까). mock 도 같은 422 를 낸다.

⚠️ **아직 안 한 것 둘** — 종목 · 지역으로 **거르는 자리**(접점과 BFF 는 이미
받는다, 단추만 붙이면 된다) · **지원(신청)**(계약엔 있지만 이번 요청은 명단까지).

### 고른 영상이 올리자마자 돈다 — 그리고 시작 단추는 이미 눌리고 있었다

미리보기에 `loop` 은 있었는데 **첫 프레임에서 멈춰 있었다** — 무엇을 올렸는지
보려면 재생을 한 번 눌러야 했다. `autoPlay` 를 붙였다.

🔴 **`muted` 가 같이 붙어야 한다.** 브라우저 정책이 소리 있는 자동 재생을
막아서, `autoPlay` 만 주면 `play()` 가 거부되고 **조용히 멈춰 있는다** — 실패가
아무 데도 안 남아서 원인을 못 찾는다. React 는 `muted` 를 속성이 아니라
프로퍼티로 놓으므로 `onLoadedData` 에서 한 번 더 못박고 직접 튼다.

⚠️ **「분석 시작하기가 안 눌린다」는 확인해 보니 이미 눌리고 있었다.** 종목을
걷어내면서 `ready = Boolean(file && sport)` 의 `sport` 가 늘 참이 됐기 때문이다.
실측으로 확인했다 — `disabled: false · pointer-events: auto · opacity: 1`.
**옛 화면을 보신 것이라 코드는 안 건드렸다.**

#### 확인 — jsdom 은 재생을 흉내만 낸다

`paused` 가 실제로 갈리지 않아 시험은 **틀에 무엇이 적혀 있는지**(`autoplay` ·
`loop` · `muted`)만 붙든다. 진짜로 도는지는 CDP 로 쟀다 — `DOM.setFileInputFiles`

- 자판(방향키)은 **일부러 안 막았다** — 휠까지 막힌 상태에서 자판마저 막으면
  마우스 없이 쓰는 사람은 화면을 아예 못 넘긴다

머리 띠(간판 줄 + 거름망 줄)는 **붙여 두어 안 움직인다**(`sticky`). 아래 줄이 설
자리는 위 줄의 키인데 그 값이 `clamp` 라 CSS 에 못 적는다 — `MarketGates` 가
`ResizeObserver` 로 재서 `--ss-md-topline-h` 로 넘긴다(창 크기만 듣지 않는 이유는
**글꼴이 늦게 실려 띠가 한 번 더 커져서**다).

### 🔴 이번에 데인 것 — 다시 밟지 말 것

- **`sticky` 는 테두리 상자가 아니라 바깥 여백까지 가둔다.** 음수 여백으로 판 끝에
  닿아 있는 띠에 `top: 0` 을 주면 그 여백만큼 **아래로 밀려** 위에 초록 띠가 생긴다.
  걷어낸 값을 `top` 에 그대로 되돌려 준다
- **`top` 은 굴림 칸의 안쪽 여백 *안쪽*에서 센다.** 두 번째 줄에 `top: <띠 키>` 만
  주면 여백만큼 더 내려가 띠가 두 장으로 갈라진다(실측 77 자리에 105 로 섰다)
- **고무줄 굴림(macOS)은 굴림 값이 안 바뀌어 코드로 안 잡힌다.** 붙여 둔 띠도 같이
  딸려 내려간다 — `overscroll-behavior: none`(`contain` 은 고무줄을 안 막는다)
- **카드 안을 `--ss-accent` 로 칠하지 말 것.** 그 값이 판 바탕과 같은 `#33483c` 라
  사진 자리가 통째로 사라졌다(테두리도 같은 초록이라 카드 윗부분이 없어 보였다)
- **`aspect-ratio` 와 flex 늘어나기를 같이 쓰지 않는다**(또 나왔다). 사진 자리는
  `flex: 1` 로 남는 자리를 먹고, 키는 카드의 `min-height` 가 정한다

⚠️ 아랫줄이 잘린다고 **카드를 깎지 말 것.** 230px 까지 내렸다가 되돌렸다 — 짧은
창에서 두 줄이 다 안 들어오는 것은 **다음 자리로 한 걸음 더 가면 되는 일**이다.
대신 상자만 32px 위로 당겼다(간판 · 카드 크기는 그대로).

### 영상 모음 — 목록을 오른쪽에 박고, 댓글창을 붙였다

목록이 **영상의 오른쪽 끝을 따라다니던 것**을 늘 화면 오른쪽 끝으로 옮겼다. 넘길
때마다 목록이 좌우로 움직여 고정된 차림표로 안 읽혔다. 세로 영상은 목록에 안 닿으
므로 여전히 **한 픽셀도 안 움직인다**.

댓글 단추에 **댓글창**. 목록과 **같은 자리**를 쓰므로 한 번에 하나만 뜬다(`side` 가
셋 중 하나). 나오는 차례를 지킨다 — 가로 영상이면 영상이 먼저 비켜서고, 목록이 나와
있었으면 그것이 오른쪽으로 나간 뒤에 들어온다. 넘길 때 다음 영상은 **왼쪽에서
오른쪽으로** 짧게(7%) 미끄러져 들어온다. 목록에서는 **지금 보는 줄만 밝다**(전에는
반대였다 — 되돌리지 말 것).

⚠️ 댓글은 **전부 mock 이고 아무 데도 안 보낸다**(계약 5장에 댓글이 없다). 쓴 것은
이 화면 안에서만 붙는다 — 좋아요와 같은 규칙.

### 🔴 이번에 데인 것 — 다시 밟지 말 것

- **두 판이 자리 변수 하나를 같이 보면, 나가는 중인 판이 옆으로 툭 뛴다.** 폭이
  다르니 서는 자리도 다르다 — 번갈아 누를 때 버벅이던 원인이다(실측 50px)
- **기다리는 시간을 effect 에서 재면 늦는다.** 첫 프레임이 옛 값(0ms)으로 그려져
  영상과 판이 같이 움직인다 — 재는 일을 함수로 빼서 **여는 손짓에서 먼저** 부른다
- **판이 비켜설 수 있는 거리보다 넓으면 모자란 만큼 영상 위로 겹친다.** "영상은
  왼쪽으로 비켜설 뿐 화면 밖으로 안 나간다"는 규칙이 거리를 정해 두기 때문이다
  (댓글창 360px 에서 32px 겹쳤다 → 290px)
- **애니메이션과 전환이 같은 속성을 쥐면 전환이 진다.** 들어오는 칸의 미끄러짐은
  `transform` 만 잡고 불투명도는 건드리지 않는다 — 안 그러면 교차 흐리기가 죽는다

### 이 회차에서 확인한 방법 하나

바꿔 재고, 부드러움 자체는 사람이 봐야 한다.

- **`inline-block` 하나로 두 가지가 풀린다** — 상자가 글자 폭으로 줄어 `left: 100%`

- **접혀 있는 서랍도 flex 틈을 두 번 만든다.** 신청서가 키 0으로 남아 간판 상자

  고리만 보여 "왜 흰 테두리가 생기냐"가 된다. 지울 때는 `:focus` 와
  `:focus-visible` 을 **둘 다** 지우고, 대신 다른 표시(줄이 커지는 것)를 남긴다.

### BFF — 브라우저는 FastAPI 를 모른다

화면 코드는 **같은 오리진의 `/api/*` 만** 부르고, Next.js Route Handler 가 서버에서 FastAPI 로 중계한다. 두 가지를 얻는다:

- **CORS 설정이 필요 없다.** 서버끼리의 호출에는 CORS 가 없다
- **액세스 토큰이 JS 에 노출되지 않는다.** 계약상 refresh 토큰이 없어 액세스 토큰 하나가 전부인데, `httpOnly` 쿠키에 두면 XSS 로 새지 않는다

### mock ↔ 실제 전환

`server/backend/index.ts` 의 `getBackend()` 가 환경변수 **`USE_MOCK`** 로 고른다. **`NEXT_PUBLIC_` 을 붙이지 않는다** — 클라이언트 번들에 박힌다.

FastAPI 가 배포되면 `USE_MOCK` 을 끄고 `BACKEND_BASE_URL` 을 주면 된다. **`fastapiBackend` 구현체는 아직 안 만들었다** (앞 계획의 Task 11).

## 4. 지켜야 하는 것들 — 어기면 설계가 무너진다

### 카드에 수치를 그리지 않는다

DB 설계(부록 D.5)가 `player_card` 테이블에 능력치 컬럼을 **아예 두지 않는** 방식으로 이걸 막아뒀다. 화면에서 되살아나면 그 설계가 통째로 무의미해진다.

`PlayerCardView.test.tsx` 가 `점`·`등급`·`★`·`%`·소수·`<progress>`·`<meter>` 를 검사한다. **맨 숫자는 검사하지 않는다** — "10경기 연속" 같은 정당한 호칭 라벨이 걸리기 때문이다.

호칭은 **받은 것만** 그린다. `earned: false` 같은 미달 표식을 만들지 않는다.

### 접근성 접점

기존 테스트가 이걸로 요소를 집는다. 마크업을 바꾸더라도 유지해야 한다:

- `getByLabelText('이메일')`, `('비밀번호')`, `('닉네임')`
- `getByRole('button', { name: '로그인' })`, `{ name: '가입하기' }`, `{ name: '저장' }`
- `role="alert"`(에러), `role="status"`(저장 완료)

> ⚠️ `Field.tsx` 는 한때 `<label>` 암묵적 래핑이었는데, 비밀번호 보기 토글을 넣자 **버튼의 `aria-label` 이 입력칸의 접근성 이름에 섞여** 라벨 매칭이 깨졌다. **jsdom 테스트로는 안 드러나고 실제 브라우저에서만** 나타났다. 지금은 `htmlFor`+`id` 명시적 연결이다. 되돌리지 말 것.

### 색·크기는 토큰으로

리터럴(`#70ed88`, `text-white/60`) 금지. `var(--ss-*)` 를 쓰고, 불투명도는 `color-mix(in srgb, var(--ss-fg) NN%, transparent)`.

`--ss-*` 값 대부분은 **Flutter 소스에서 그대로 옮겨와 줄 번호까지 대조 확인한 것**이다(`globals.css` 주석 참고). 웹 전용으로 추가한 것은 `--ss-field-radius`, `--ss-radius-arch`, `--ss-google-btn-h` 정도다.

## 5. 인트로 — 앱과 같은 연출

앱(`flutter/lib/features/intro/presentation/screens/glitch_intro_screen.dart`)을 옮긴 것이다. 처음에는 "검은 화면에 글자가 떨리는" 것으로 잘못 만들었다가 다시 만들었다.

- **민트 종이(`#70ED88`) 위에 검은 잉크가 번지고**, 같은 민트색 글자가 그 대비로 드러난다. 글자는 나타나는 게 아니라 처음부터 거기 있었다
- 진행 곡선 `p = 1.6u − 0.6u²` — 선형이 아니다. 참조 영상에서 잰 값이라 임의로 바꾸지 말 것
- 글꼴이 도중에 갈린다: 가지런한 **Rubik** → 진행도 0.795 에서 **RubikGlitch**. RubikGlitch 만으로는 "멀쩡했다가 깨지는" 변화를 못 만든다
- 흔들림은 **버스트 3회**(0.62~0.71 / 0.76~0.83 / 0.88~0.93), **사이에는 완전히 정지**한다. 가로 **7개 띠**를 각각 다르게 어긋내고 값을 **45ms 유지**한다 — 매 프레임 새로 뽑으면 글리치가 아니라 지글거림이 된다

### 웹만 앱과 갈린 값 (2026-08-28)

| | 앱 | 웹 |
|---|---|---|
| 구간 길이 | 민트만 700 / 번짐 2400 / 머묾 500 = **3600ms** | 민트만 **300** / 번짐 **3000** / 머묾 500 / **걷힘 700** = **4500ms** |
| 글자 크기 | 52px 고정 | `clamp(52px, 5vw, 62px)` — 넓은 화면에서 1.2배 |
| 흔들림 폭 | 14**px** 고정 | `14/52` **em** — 글자가 반응형이라 단위만 바꿨다. 52px 에서는 앱과 같은 14px |
| 끝맺음 | 없음(바로 끊긴다) | 잉크가 걷히고 워드마크가 날아간다(아래) |

구간 길이는 `introInk.ts` 의 `DRY_MS` · `WET_MS` · `SETTLE_MS` **세 상수가
원본**이고 비율(`DRY_END`·`WET_END`)과 `TOTAL_MS` 는 전부 거기서 계산된다 —
타이밍을 손볼 땐 거기만 고치면 된다.

#### 🔴 흔들림은 앱 그대로다 — 다르게 두 번 시도했다가 둘 다 되돌렸다

"밋밋하다"는 말에 손댔다가 오히려 어색해져서 앱 값으로 복귀했다. 같은 길로
다시 가지 않도록 남긴다:

1. **번지는 내내 연속으로 흔들기** → 글리치가 아니라 **진동**으로 보였다.
   45ms마다 7개 띠가 전부 매번 움직이면 규칙적인 떨림이 된다 — 버스트 사이의
   정적이 있어야 터지는 순간이 산다
2. **확률로 드문드문 터뜨리기**(얇은 띠 22개 + `r³` 분포) → 몇 번 터질지가
   통제되지 않아 **어수선했다.** 게다가 띠를 얇게 하면서 어긋남을 그대로 뒀더니
   3px 두께의 선이 30px 씩 밀려나 **글자에서 떨어져 나간 조각**으로 보였다

정리하면 — **횟수는 못박고(3회), 사이는 완전히 정지시키고, 어긋남은 띠 두께에
어울리는 크기로.** 참조 영상에서 잰 앱 표가 이미 그렇게 되어 있다.

실측(1440px): 흔들리는 덩어리 **3개**(270 / 270 / 225ms), 그동안 7개 띠가 모두
움직이고 최대 어긋남 18.4px(72px 글자). 52px 에서는 앱과 같은 12.9px 이다.

부산물 하나는 남겼다. `GlitchIntro` 는 **어긋남이 전부 0이면 글자를 자르지 않고
통짜로 그린다** — 자르기만 해도 조각 경계가 가는 가로줄로 보이기 때문이다(아래
참고). 앱 모델에서는 버스트 밖이 늘 0이라 그 구간이 항상 통짜로 그려진다.

#### 끝맺음 — 잉크가 걷히고 워드마크가 제자리로 날아간다

예전엔 인트로가 **뚝 끊기고** 화면이 나타났다. 지금은 마지막 700ms 동안 두
동작이 **함께** 일어난다:

1. **잉크가 역으로 걷힌다.** 셰이더에 원래 있던 `uErase` 를 켜면 알파가
   뒤집혀(`a = 1 − inked`) 번질 때와 **같은 알갱이**로 사라진다 — 점 단위로
   흩어지며 밑의 화면이 드러난다. CPU 폴백도 같은 자리에서 뒤집는다.
   진행 곡선은 `eraseProgress`(`1 − (1−e)²`) — 앞이 빠르다
2. **워드마크가 `BrandMark` 자리로 날아가 앉는다**(FLIP). 목적지는
   `[data-brand-mark]` 로 찾는다 — 반응형으로 사본이 둘 이상이면(AuthShell 의
   34px/48px) 실제로 보이는 것을 고른다

같은 시간(`ERASE_MS`)을 쓰는 게 중요하다. 따로 두면 글자만 먼저 앉아 있고
배경이 남거나 그 반대가 되어 두 동작이 하나로 안 읽힌다.

**구조상 지켜야 하는 것 셋**

- **잉크 레이어와 글자 레이어가 나뉘어 있다.** 끝에서 잉크만 걷어내고 글자는
  남겨야 해서다 — 한 겹으로 합치면 이 연출이 불가능하다
- **걷힘이 시작될 때 민트 배경을 치운다.** 그 순간 화면은 아직 완전히 검어서
  (진행도 1에서는 모든 픽셀이 불투명) 눈에 띄는 변화가 없다. 안 치우면 걷힌
  자리로 실제 화면이 아니라 민트가 보인다
- **날아가는 동안 목적지 워드마크를 감춘다.** 안 그러면 같은 글자가 둘로
  보인다. 도착하면 되살리는데 둘이 픽셀 단위로 겹쳐 있어 바뀌는 게 안 보인다.
  비행 도중 언마운트될 때도 되살려야 한다(감춰진 채 남는다)

두 워드마크가 글꼴·자간 공식(`BrandMark.letterSpacingFor`)을 공유하기 때문에
**균등 확대·축소 하나로 정확히 겹친다**. 실측으로 확인한다 — 비행이 끝난
글자의 상자가 목적지 `BrandMark` 의 상자와 **x·y·폭·높이까지** 같아야 한다
(1440px: `925.1, 210, 284.8, 48`. 375px: `86.6, 165, 201.7, 34`).

##### 🔴 깨진 뒤의 글자는 `BrandMark` 와 한 글자도 달라선 안 된다

날아가 앉는 자리에 원래 있던 워드마크와 겹쳐야 하므로, `SWAP_AT` 이후의
스타일은 `BrandMark` 와 같아야 한다. 두 번 어긋났었다:

- **`font-weight: 900`.** RubikGlitch 는 굵기가 하나뿐인 장식 글꼴이라 900 을
  주면 브라우저가 **가짜 굵게(synthetic bold)** 를 입힌다. **자간도 폭도 안
  변해서 측정으로는 안 잡히고 획 두께만** 굵어진다 — 날아가 앉은 글자가 원래
  워드마크보다 두꺼워 보였다. 900 은 가변 글꼴인 Rubik(깨지기 전)에만 뜻이 있다
- **비행 기준 상자의 줄높이.** 감싸는 `inline-block` 에 `lineHeight: 1` 이
  없으면 상자가 글꼴 기본 줄높이(1.18배)로 커진다. 그러면 **상자 중심은 맞아도
  글자 중심이 어긋난다** — 폭만 재서는 절대 안 드러나는 종류의 어긋남이다

그래서 착지 검증에 **높이까지** 넣는다. 폭만 보면 비행 코드가 폭 비율로
크기를 맞추므로 **언제나 통과한다**(자기 자신을 검증하는 셈이다).

##### ⚠️ 글자에 가로줄이 보이면 이것부터 본다

**어긋난 띠가 하나도 없으면 자르지 않고 통짜로 그려야 한다.** 자르기만 해도
조각 경계가 가는 가로줄로 보인다 — 글자 높이를 7로 나눈 자리가 정수 픽셀에
안 떨어져 그 사이로 배경이 비친다. 흔들림을 잠시 드문드문하게 바꿨을 때
**"진폭은 있는데 이번 칸은 조용한" 순간**이 생기면서 드러났던 문제인데, 앱
모델로 되돌린 지금도 버스트 밖 구간이 전부 그 경우다.

두 겹으로 막는다:

1. `GlitchIntro` 가 **어긋남이 전부 0이면 통짜 `<span>`** 하나로 그린다
2. 조각의 clipPath 아래쪽을 **0.5px 넘겨** 이웃과 겹친다 — 실제로 어긋나는
   동안에도 경계에 틈이 안 생긴다

실측으로 확인한다 — "조각냈는데 하나도 안 움직인 프레임"이 **0**이어야 한다.

흔들림이 **정확히 0으로 끝나는 것**이 중요하다. 다 번진 뒤 `BrandMark` 와 같은
워드마크로 굳어야 해서다(`RubikGlitch`, 진행도 0.795 에서 이미 바뀌어 있다).
실측으로 확인한다 — 마지막 프레임의 띠 이동량이 0px 이어야 한다.

### 잉크 구현이 세 번 바뀐 이유

1. canvas 2D(CPU) → 알갱이가 굵어서 반려
2. **WebGL 이식** → GPU 가 픽셀마다 계산
3. 지도(`ink_field.png`)를 `cover` 로 늘리던 것을 **1:1 거울 반복**으로 → 지도 무늬 자체가 확대되던 문제 해결
4. 마지막으로 **가운데부터 번지게**: 순서는 화면 중심 거리(`r`)가 정하고 지도는 경계를 흐트러뜨리는 데만 쓴다 (`order = r + detail * uDetail`, `uDetail = 0.28`, 지도 배율 0.6)

`ink_field.png` 는 **이어지는 텍스처가 아니다.** 그냥 `REPEAT` 하면 밝기가 끊기는 선이 보인다. 셰이더에서 **거울처럼 접어**(`fract` + 삼각파) 반복한다.

### 재생 규칙

`lib/intro.ts` 의 `shouldPlayIntro(pathname, seen)` — **`/` 와 `/login` 에서만, 세션당 1회.**

**`/c/{slug}` 에서는 절대 재생하지 않는다.** 메신저로 받은 카드 링크를 3.6초 막으면 공유가 성립하지 않는다.

## 6. 구글 로그인 — 실제로 동작함

- 계약: `POST /api/v1/auth/google` 에 **`id_token`** 을 보낸다. `access_token` 이 아니다 (계약서가 굵게 경고한다)
- 클라이언트 ID 는 `NEXT_PUBLIC_GOOGLE_CLIENT_ID` (`.env.local`, git 에 안 올라감). **공개되는 값이라 비밀이 아니다** — 비밀인 것은 클라이언트 시크릿이고 그건 백엔드에만 있다
- Vercel(Production)과 구글 콘솔의 Authorized JavaScript origins(`https://supersub-ai.com`)에도 들어가 있다

> ⚠️ **`NEXT_PUBLIC_*` 은 빌드 시점에 번들에 구워진다.** Vercel 에 변수를 추가하는 것만으로는
> 이미 배포된 빌드가 바뀌지 않는다 — **재배포까지 해야 한다**(빌드 캐시는 끄는 편이 안전).
> 2026-08-28 에 이걸로 프로덕션에서 버튼이 아예 안 떴다. 값이 실렸는지는 이렇게 확인한다:
>
> ```
> curl -s "https://supersub-ai.com/login?cb=$RANDOM" | grep -o '"/_next/static[^"]*\.js"' | tr -d '"' \
>   | while read p; do curl -s "https://supersub-ai.com$p"; done | grep -c apps.googleusercontent.com
> ```

### 왜 지금 모양이 됐나

1. `google.accounts.id.prompt()`(One Tap) → **FedCM `AbortError` 로 실패.** 버튼 클릭에 반응하는 용도로 부적합하다. 돌아가지 말 것
2. `google.accounts.oauth2`(implicit) → 주는 게 `access_token` 이라 계약(`id_token`)에 안 맞는다
3. 한때 **구글 버튼을 `opacity: 0` 으로 우리 `PillButton` 위에 포갰다** — 겉모습은 우리 것, 클릭은 구글 것. **이 방식은 죽었다(아래 참고).**
4. 지금: **`renderButton` 이 그린 버튼을 그대로 보여준다.** 감싸지도 덮지도 않는다

### 🔴 구글 버튼은 감추면 클릭이 죽는다

**구글은 자기 버튼이 실제로 눈에 보이지 않으면 클릭을 통째로 무시한다** — 클릭재킹 방지
장치(가시성·가림 감지)다. **콘솔에 에러 한 줄도 안 남고 그냥 아무 일도 안 일어나서** 원인을
찾기가 아주 어렵다. 2026-08-28 에 배포본을 헤드리스 크롬으로 실측해 확인했다 — 같은 좌표를
클릭했을 때 `opacity-0` 이면 무반응, **그 클래스 하나만 지우면** 정상적으로 팝업이 떴다.
스케일·좌표·origin 등록·클라이언트 ID 는 전부 무죄였다.

그래서 반대로 간다 — 구글 버튼을 그대로 두고 **우리 버튼 높이를 구글에 맞춘다.**
구글 버튼은 `size: 'large'` 에서 **높이 40px · 반경 20px 고정**이고 우리가 정할 수 있는 값이 아니다(실측).

- `--ss-google-btn-h: 40px` (globals.css) 가 그 값을 한 곳에 적어 둔 것 — 바깥 래퍼가 아니라 **눈에 보이는 알약**(`.nsm7Bb-HzV7m-LgbsSe`)의 크기다
- `AuthShell` 이 폼 열에서만 `--ss-btn-h`·`--ss-btn-r` 을 이 값으로 덮는다.
  **전역 `--ss-btn-h`(54px, 앱의 `_kButtonHeight`)는 건드리지 않는다** — 다른 화면이 쓴다
- 회귀 방지 테스트가 `GoogleSignInButton.test.tsx` 에 있다(`opacity-0`·`aria-hidden` 장식·형제 요소 금지)

"우리 디자인에 맞추겠다"고 다시 덮으러 가는 순간 같은 함정에 빠진다. 폭·문구·테마(`outline`)는
바꿀 수 있지만 **보이게 두는 것**은 협상 대상이 아니다.

### 구글이 계정 이름을 띄우는 것은 정상이다

구글에 로그인해 둔 채로 보면 버튼이 **"○○(으)로 로그인 / 이메일"** 로 바뀐다
(개인화 버튼). **우리 코드에 그 계정이 박힌 게 아니라** 구글이 자기 iframe 안에서
**보는 사람 본인의 세션**을 읽어 그리는 것이다 — 다른 사람은 자기 계정을, 구글에
로그인 안 한 사람은 일반 버튼을 본다. cross-origin iframe 이라 우리 JS 는 그 값을
읽지도 못하고, 누르기 전에는 서버로도 가지 않는다.

**끄는 방법은 없다.** 공식 레퍼런스에 `initialize`·`renderButton` 어디에도 개인화를
끄는 옵션이 없다(`auto_select`·`button_auto_select` 는 자동 로그인 여부지 표시
방식이 아니다). 세션 상태로만 결정된다.

> 남은 것: 개인화 버튼은 두 줄이라 40px 보다 높다. 그래서 그 사람 화면에서는
> `로그인` 버튼과 높이가 안 맞는다. **버튼을 잘라서 맞추면 안 된다** — 가리면
> 구글이 클릭을 막는다(위). 자리(줄 높이)를 넉넉히 잡는 쪽으로 풀어야 한다.

## 8. 다음 사람이 알아야 할 함정

- **헤드리스 브라우저로 스크린샷이 안 된다.** `backdrop-filter`/`color-mix` 를 쓰는 화면은 전부 검게 뭉개진다(여러 GL 백엔드로 재현). 시각 검증은 **`getBoundingClientRect()` 로 좌표를 재서 단언**하는 방식으로 해야 한다. 이걸 몰라서 레이아웃 결함이 여러 번 새어 나갔다.
  **단 스크린샷만 안 되는 것이지 나머지는 다 된다** — 콘솔 로그·DOM·`elementFromPoint`·실제 클릭까지 헤드리스로 잡을 수 있다. 2026-08-28 구글 버튼 무반응은 배포본에 헤드리스 크롬을 붙여 **클래스 하나만 바꿔가며 A/B 클릭**해서 원인을 특정했다. playwright 는 시스템 크롬을 쓰면 된다(`executablePath: '/Applications/Google Chrome.app/Contents/MacOS/Google Chrome'`)
- **`middleware.ts` 가 아니라 `proxy.ts` 다.** Next.js 16 에서 이름이 바뀌었다 — `middleware.ts` 로 만들면 **조용히 안 걸린다**(에러도 안 난다). 로그인 게이트가 여기 있다(§2)
- **`www/AGENTS.md`** 가 있다. 이 프로젝트의 Next.js 는 일반적인 것과 다를 수 있으니 `node_modules/next/dist/docs/` 를 먼저 읽으라고 되어 있다
- **`--ss-btn-h` 를 전역에서 바꾸지 말 것.** 앱의 `_kButtonHeight` 에서 온 값이고 여러 화면이 쓴다. 인증 화면만 구글 버튼 높이(`--ss-google-btn-h`, 40px)에 맞춰야 해서 `AuthShell` 의 폼 열에서 **국소로 덮는다** — 이게 그 방식의 본보기다
- **`GlassPanel.tsx` 는 로그인 카드와 홈 카드가 공유한다.** 고치면 양쪽을 다 확인해야 한다
- 이 저장소는 1인 1브랜치다. 백성검은 **`flutter/` 와 `www/`**, 브랜치는 **`paik`**

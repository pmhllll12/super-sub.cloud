# 결과 — **커버리지는 채워지는데 방향은 안 잡힌다**

**측정 2026.09.10 · 정상호** · 사전 등록 `PREREGISTRATION.md`(커밋 `b1fba98`,
코드보다 먼저) · 재현 `uv run python eval/pending37_facing/measure_facing.py`
(GPU 불필요)

## 한 줄

**귀 신뢰도 비대칭은 39클립 중 38클립(97%)에서 값을 낸다. 그런데 독립 큐와의
일치가 46% — 우연이 50%다. 그리고 클립 안에서 부호가 뒤집히는 것이 3분의 1이다.
값이 나온다는 것과 맞다는 것은 다르다.**

## 사전 등록 기준

| | 기준 | 결과 |
|---|---|---|
| **A** | 커버리지 — 한 큐가 70%+ | ✅ **97%** (귀) · 74% (눈·이동) |
| **B** | 일치 — 귀↔이동 70%+ | 🔴 **46%** (13/28) |
| **C** | 시간 안정 80%+ | 🔴 **66%** (25/38) |
| **D** | 구조적 비순환 | ✅ 두 큐 다 `trunk` 벡터를 안 쓴다 |

**A·D 만족, B·C 불만족 → (나)의 전제가 이 표본에서 서지 않는다.**

## 🔴 정정 — 판정 문장이 A 만 보고 있었다

첫 실행의 마지막 판정 문장이 **기준 A 만 보고** 「(나)의 전제가 선다」를
찍었다. 사전 등록은 「(나)가 살아 있는가」에 **A·B·C·D 를 다** 걸었다.

**기준이 아니라 출력의 구현 오류라 고쳤다 — 바를 움직인 것이 아니다.**
`measure_facing.out` 은 고친 뒤 것이다. 🔴 안 잡았으면 이 회차는 **정반대
결론으로 기록될 뻔했다.**

## 1) 커버리지는 넉넉하다 — 그게 함정이었다

| 큐 | 판별된 클립 | 비율 |
|---|---:|---:|
| 큐 1a **귀** 신뢰도 비대칭 | 38/39 | **97%** ✅ |
| 큐 1b 눈 신뢰도 비대칭 | 29/39 | 74% ✅ |
| 큐 2 골반중심 x 변위 | 29/39 | 74% ✅ |

세 큐 전부 바(70%)를 넘는다. **A 만 보면 「된다」로 읽힌다.**

## 🔴 2) 그런데 서로 안 맞는다 — **우연 수준이다**

| 대조 | 일치 |
|---|---|
| 귀 ↔ 눈 (⚠️ 둘 다 얼굴이라 완전 독립이 아니다) | 21/28 (75%) |
| **귀 ↔ 이동** ← 🔴 **이것이 독립 대조다** | **13/28 (46%)** |
| 눈 ↔ 이동 | 10/19 (53%) |

**우연이 50%다.** 독립인 두 큐가 **동전 던지기와 구별되지 않는다.**

귀↔눈이 75%로 높은 것은 **둘 다 얼굴 가시성**이라 같은 잡음을 공유해서지,
방향을 같이 짚어서가 아니다 — 사전 등록에 「완전 독립이 아니다」라고 미리
적어 둔 이유다.

## 🔴 3) 시간 안정도 못 넘었다 — 클립 안에서 뒤집힌다

| 큐 | 한 부호가 80%+ 인 클립 |
|---|---|
| 귀 | **25/38 (66%)** |
| 눈 | 21/29 (72%) |

**사람은 한 스윙 안에서 돌아서지 않는다.** 그런데 귀 큐는 **3분의 1의
클립에서 부호가 뒤집힌다.** 그 자체로 「이 큐가 방향이 아니라 잡음을
따라간다」는 증거다.

## 🔴 4) 분석하다 찾은 것 — **이동 큐도 기준이 못 된다**

*(사전 등록에 없다. 판정에 쓰지 않았다.)*

B 의 46%를 **「귀 큐가 틀렸다」로 읽으면 안 된다.** 이동 큐 자체가 못 믿을
것이기 때문이다.

> **화면 안에서 골반중심이 움직인 것과 피사체가 실제로 이동한 것을
> 구분하지 못한다.** 표본이 Kinetics **방송 영상**이라 **카메라 팬**이 흔하다.
> 카메라가 따라가면 피사체는 제자리인데 좌표가 움직이고, 반대로 카메라가
> 피사체를 따라가면 실제로 이동해도 좌표는 안 움직인다.

**그래서 정확한 결론은 「귀가 틀렸다」가 아니라 「둘 다 방향을 짚는다고 말할
근거가 없다」**다. 46%는 **둘 다 잡음**일 때 나오는 값이기도 하다.

## 5) 관찰 — 큐와 `trunk_lean` 부호의 일치 (판정에 쓰지 않는다)

| 큐 | `trunk_lean` 부호와 일치 |
|---|---|
| 귀 | 14/38 (37%) |
| 눈 | 10/29 (34%) |
| 이동 | 18/29 (62%) |

🔴 **이 값이 높다고 순환이 아니고, 낮다고 큐가 틀린 것도 아니다** — 실제
자세가 섞여 있어서다. 적어 두는 이유는 **어느 큐도 `trunk_lean` 과 강하게
정렬되지 않았다**는 사실 자체다.

## 6) 판별이 안 된 사유

| | |
|---|---|
| 귀 | 실패 **1클립** — 문턱을 넘는 프레임이 0개 |
| 눈 | 실패 10클립 — **전부** 문턱을 넘는 프레임이 0개 |
| 이동 | 실패 10클립 — 변위 중앙 **0.21 어깨너비**(문턱 0.5). **타자는 제자리에 있다** — 사전 등록이 예측한 대로다 |

## 🔴 두 번째다 — 커버리지를 성과로 읽지 말 것

**같은 형태의 결과가 오늘 두 번 나왔다.**

| | 커버리지 | 내용 |
|---|---|---|
| 미결 18번 7회차 | 잃은 프레임의 **93%** 를 채웠다 | 채운 것 중 맞은 것 **1%** |
| **여기** | **97%** 에서 방향 값이 나온다 | 독립 큐와 일치 **46%**(우연 50%) |

🔴 **「값이 나온다」와 「맞다」는 다르다.** 두 회차 다 **커버리지만 보는
기준이었으면 성공으로 적혔을 것**이고, 둘 다 **짝 기준이 막았다.**
앞으로 커버리지 단독 기준을 세우지 않는다.

## 이 회차가 얻은 것

1. 🔴 **(나)의 전제가 이 표본에서 서지 않는다** — 커버리지 97%인데 독립 큐와
   46% 일치, 시간 안정 66%. **실패가 아니라 결론이다**
2. 🔴 **이동 큐도 기준이 못 된다** — 카메라 팬과 피사체 이동을 구분 못 한다.
   그래서 「귀가 틀렸다」가 아니라 **「둘 다 근거가 없다」**가 정확하다
3. 🔴 **판정 문장의 구현 오류를 잡았다** — A 만 보고 정반대 결론을 찍고 있었다
4. 🔴 **커버리지를 성과로 읽는 실수가 오늘 두 번째다** — 짝 기준이 두 번 다 막았다

  **「안 된다」가 아니라 「이 둘로는 안 됐다」**다

# 사전 등록 — **방향을 판별할 수 있는가**: 처방 (나)의 전제를 먼저 잰다 (미결 `ho` 37번 3회차)

**작성 2026.09.10 · 정상호 · 측정 코드보다 먼저 고정한다.**

## 왜 이것을 먼저 하나

1·2회차로 **결함의 크기와 구조**는 다 나왔다. 남은 것은 처방 선택이다.

| | 처방 | 대가 |
|---|---|---|
| **(가)** | 밴드를 0 대칭으로 | 임계값 이동(미결 2번·34번) · 🔴 **앞뒤 구분을 포기한다** |
| **(나)** | 지표를 **방향 인식**으로 | 🔴 **B-6 전 구간 재실행** · 밴드는 안 건드린다 |

**(나)가 원인에 가깝다.** 그런데 (나)에는 전제가 하나 있다 —
**피사체가 어느 쪽을 보고 있는지를 우리가 알아낼 수 있어야 한다.**

> **못 알아내면 (나)는 죽고 (가)가 기본값이 된다.**
> 이건 **정답 없이 잴 수 있는 질문**이라 지금 한다.

🔴 **이 회차는 처방을 고르지 않는다.** (나)가 **가능하기는 한가**만 답한다.

## 🔴 후보에서 먼저 빼는 것 — **코 오프셋은 순환이다**

가장 먼저 떠오르는 방향 큐는 `nose_x - hip_center_x` 다. **쓰면 안 된다.**

우리가 부호를 정하려는 값이 `trunk = shoulder_c - hip_c` 인데, 앞으로 기울면
**코도 같은 방향으로 간다.** 그 큐로 부호를 정하면 `trunk_lean` 이 **항상
양수**가 되어 지표가 통째로 죽는다.

**구조적 순환이다** — 결과를 보고 판단할 것이 아니라 **지금 배제한다.**
얼굴 중심 좌표를 쓰는 큐(코·눈 **위치**)는 전부 같은 사유로 뺀다.

## 두 큐 — 둘 다 `trunk` 벡터를 입력으로 쓰지 않는다

| | 큐 | 왜 비순환인가 |
|---|---|---|
| **1. 얼굴 가시성 비대칭** | `conf(L_ear) - conf(R_ear)` (보조: 눈) | **신뢰도**만 쓴다. 좌표를 안 쓰므로 기울기와 무관하다. 옆을 보면 먼 쪽 귀가 가려져 신뢰도가 떨어진다 |
| **2. 이동 방향** | 분석 구간 동안 골반중심 x 의 변위 | 몸통 **자세**가 아니라 **위치**의 변화다 |

두 큐는 서로도 독립이다 — 하나는 **가림**, 하나는 **운동**이다.

## 표본 — 🔴 있는 것뿐이고, 편향이 있다

`eval/phaseA/cache_target30/` 의 **39클립** (COCO-17 캐시).

⚠️ **전부 Kinetics 야구 타격이다.** 축구·농구 클립의 COCO-17 캐시는 저장소에
없고 새로 뽑으려면 GPU가 든다(1·2회차가 쓴 축구 실측은 **features 만** 있고
키포인트가 없다).

🔴 **그래서 큐 2 는 이 표본에서 불리하다.** 타자는 거의 제자리에 서 있고,
투구·킥처럼 **전진하는 동작**에서 훨씬 잘 들을 큐다. **큐 2 가 여기서 약하게
나와도 「투구에서도 안 된다」로 읽지 않는다.**

## 🔴 문턱 — 데이터를 보기 전에 박는다

| | 값 | 왜 그 자리인가 |
|---|---|---|
| 가시성 판별 | `|Δconf| ≥ **0.2**` | 포즈 신뢰도의 잡음폭보다 크다. 팔 최소 신뢰도가 0.6, 다리가 0.3 인 저장소 관례에서 **차이**의 문턱으로 0.2 는 보수적이다 |
| 이동 판별 | `|Δx| ≥ **0.5**` (어깨너비 배수) | 정규화 단위다. 반 어깨너비면 서 있는 흔들림이 아니다 |
| 시간 안정 | 유효 프레임의 **80%+** 가 한 부호 | 사람은 한 동작 안에서 돌아서지 않는다. 뒤집히면 큐가 못 믿을 것이다 |
| 프레임 유효 | 두 관절 모두 `conf > 0` | 미검출을 0 으로 세지 않는다 |

**결과를 보고 이 값들을 옮기지 않는다.**

## 합격 기준 — (나)가 살아 있는가

| | 기준 |
|---|---|
| **A** 🔴 | **커버리지** — 두 큐 중 **적어도 하나**가 39클립의 **70% 이상**에서 판별을 낸다. 못 넘으면 (나)는 **대부분의 클립에서 부호를 못 정한다** |
| **B** | **일치** — 둘 다 판별을 낸 클립에서 부호가 **70% 이상** 일치한다 |
| **C** | **시간 안정** — 판별을 낸 클립의 **80% 이상**이 시간 안정 |
| **D** 🔴 | **구조적 비순환** — 두 큐 어느 것도 어깨중심·골반중심의 **좌표차(= `trunk`)** 를 입력으로 쓰지 않는다 (코드로 확인) |

🔴 **A 를 못 넘으면 이 회차의 답은 「(나)는 안 된다」이고, 그건 실패가 아니라
결론이다.** 그때는 (가)로 가되 **앞뒤 구분을 포기하는 대가**를 명시해서 적는다.

## 반드시 보고할 것 (판정에 쓰지 않는다)

1. 큐별 커버리지·안정성을 **따로** — 하나만 되면 그것만 쓰면 된다
2. 🔴 각 큐의 부호와 **`trunk_lean` 부호의 일치율.** ⚠️ **높다고 순환이
   아니다** — 실제로 대부분 앞으로 기울면 정당하게 높다. 구조적 비순환은
   기준 D 가 본다. 이 값은 **관찰**로만 적는다
3. 판별이 안 된 클립의 사유 — 신뢰도가 낮아서인가, 차이가 작아서인가

| 큐 2 커버리지 | **낮을 것이다** — 표본이 타격이라 제자리 동작이다. 위에 적은 대로 불리한 조건이다 |
| 일치(B) | 커버리지가 낮으면 **분모가 한 자릿수**가 되어 판정이 무의미할 수 있다. 그러면 **판정하지 않고 분모만 적는다**(미결 6번과 같은 규칙) |
| C | 만족할 것 같다 — 한 동작 안에서 돌아서지 않는다 |

**빗나가면 빗나간 대로 적는다.**

## 하지 않는 것

- 🔴 **처방을 고르지 않는다** — 이 회차는 (나)의 **전제**만 본다
- 🔴 **`features.py` 를 고치지 않는다.** 방향 인식을 **구현하지 않는다** —
  구현은 별도 회차이고 **B-6 재실행**을 부른다
- 🔴 **코·눈의 위치를 큐로 쓰지 않는다** (구조적 순환)
- 🔴 **문턱을 결과 보고 옮기지 않는다**
- 🔴 **큐를 세 번째로 늘리지 않는다** — 안 되면 안 되는 대로 적는다.
  「하나 더 해 보면 될지도」는 사전 등록을 무의미하게 만든다
- **포즈를 다시 뽑지 않는다** — 있는 캐시만 쓴다

# 사전 등록 — 근거 문장이 **단위를 지어내는 것** (미결 `ho` 43번 ㉱, 2회차)

2026.09.16 · 🔴 **돌리기 전에 굳힌다.** 이 파일을 커밋한 뒤에 잰다.

1회차가 **프롬프트에서 코드 심벌**을 없앴고, 그 문서 끝에 *「출력을 재려면 LLM
회차가 필요하다. 그건 2회차로 남긴다」*고 적어 두었다. **이번이 그 회차다.**

## 결함 — 프롬프트가 **맨 숫자**를 준다

지금 `build_prompt` 는 이렇게 쓴다:

```
측정값 (이 숫자만 신뢰할 것):
- 임팩트 후 고관절 추가 굴곡: 41.5
- 팔로스루 지속 시간: 9
```

🔴 **단위가 없다.** 1회차가 일부러 뺐다 — `follow_through_duration_frames` 의
계약상 `unit` 이 `s` 인데 **`features` 의 실제 값은 프레임**이라, 그 단위를
붙이면 9프레임이 **「9초」**가 되기 때문이다. 그런데 **빼는 것으로는 안 막힌다**:
사람에게든 모델에게든 「지속 시간: 9」는 단위를 부르는 문장이고, 지어낼 단위로
가장 그럴듯한 것이 **초**다.

**1회차의 논리를 그대로 뒤집어 쓴다**: 「프롬프트에 없는 것은 베껴 쓸 수 없다」
→ **참인 단위를 프롬프트에 넣으면 그것을 베낀다.**

## 고치는 방법 — **새 선언 없이** 계약이 이미 아는 것을 쓴다

`contracts/metric_definitions.yaml` 이 이미 둘을 구분해 적고 있다:

| | 계약의 뜻 | 프롬프트가 쓸 단위 |
|---|---|---|
| `unit: deg` | 도 | **도** |
| `unit: ratio` | 무차원(`scale_ref` 에 무엇으로 나눴는지) | 붙이지 않는다 |
| `unit: s` + **`emitted_from: frame_metrics_seconds`** | **DB 로 나갈 때** 초 — 🔴 **`features` 안에서는 프레임** | **프레임** |

🔴 **새 키를 더하지 않는다.** `emitted_from` 이 이미 「이 값은 환산을 거쳐야
초가 된다」를 말하고 있으므로, 그것이 있으면 **프레임**이다.

## 🔴 초로 바꾸지 않는 이유 — 앵커가 같은 자에 있어야 한다

「그냥 초로 환산해서 보여주면 사용자에게 더 낫지 않나」가 자연스러운 다음
생각인데, **이번에는 안 한다.**

프롬프트에는 측정값과 **앵커**(`rubrics/*.yaml` 의 `measured`)가 함께 들어가고,
앵커의 `follow_through_duration_frames: 9` 는 **프레임으로 적힌 값**이다.
측정값만 초로 바꾸면 **모델이 두 다른 자를 나란히 보게 된다.** 앵커까지 환산하려면
그 앵커가 **어느 fps 격자에서 매겨졌는지**를 알아야 하는데, 🔴 **그것이 아직
안 닫힌 문제다**(미결 7번 「앵커의 프레임 수는 다른 격자에서 매긴 값이다」).

그래서 이번 회차는 **거짓을 없애는 데까지**다. 초 표기는 그 항목이 닫힌 뒤다.

## 판정 기준 — 결과를 보고 바꾸지 않는다

| | 기준 | 판정선 |
|---|---|---|
| **A** | 🔴 **계기 검사** — 재는 것이 **모델 출력**인가. 1회차는 프롬프트를 쟀고 이번은 출력이다. 그리고 **분모를 먼저 못박는다**: 「지속 시간을 언급한 문장」이 분모다 (언급 자체가 드물면 비율이 공허하다) | 분모가 **10 미만이면 판정하지 않고 표본을 늘린다** |
| **B** | **고치기 전** — 지속 시간을 언급한 문장 중 **시간 단위(초·분)를 붙인 것**이 몇 건인가 | 기록(0 이면 결함이 재현 안 된 것이므로 그대로 적고 C 를 판정하지 않는다) |
| **C** | **고친 뒤** — 같은 조건에서 같은 것을 센다 | 🔴 **0건이어야 합격** |
| **D** | 🔴 **짝 기준** — 단위를 넣어 **새 거짓말이 생기지 않는가**. 문장에 나온 단위가 그 지표의 참 단위와 다르면(예: 프레임 값에 「도」) 실패로 센다 | **0건** |
| **E** | **점수 비트 동일** — `build_prompt` 는 문장만 만들고 등급은 `grade_for` 가 정한다 | 하나라도 바뀌면 불합격(B-6 재실행이다) |
| **F** | 기존 검사 전부 통과 | `uv run pytest -q` |

## 표본 — 먼저 정한다

- 루브릭 **둘**(인스텝 슛 · 인사이드 패스) × `follow_through` 항목 × 등급
  **셋** × **5회 생성** = **30 문장**, 고치기 전·후 각각.
- 🔴 **같은 조건으로 두 번 돌린다** — 모델이 확률적이라 한 번의 차이는 처방의
  효과와 구분되지 않는다. 앞뒤를 **같은 표본 수**로 맞춘다.
- 값은 앵커와 겹치지 않게 **등급별로 하나씩 고정**해 둔다(아래 스크립트에 박는다)
  — 매번 다른 값을 넣으면 앞뒤 비교가 흔들린다.

## 🔴 하지 말 것

- **앵커를 초로 바꾸지 않는다** (위 이유 — 미결 7번이 먼저다)
- **등급 번호·기준 구간을 프롬프트에 되돌리지 않는다** (미결 23·24번)
- **모델 어투·문장 길이를 손보지 않는다** — 이번 회차는 **단위 하나**다
- **출력에서 정규식으로 단위를 지우는 후처리를 넣지 않는다** — 증상을 가리는
  것이고, 그러면 모델이 무엇을 믿고 썼는지가 사라진다
- 🔴 **`features` 를 바꾸지 않는다** (B-6 재실행)

## 예상 (틀리면 그대로 적는다)

**B 에서 시간 단위 오기가 나오고, C 에서 0 이 될 것**으로 본다.

🔴 **어떤 분포에서 나온 예상인가**: 근거는 ⑴ 1회차가 **같은 형태의 유출**(프롬프트에
있는 것을 그대로 베낌)을 실물 저널에서 확인했다 ⑵ 「지속 시간: 9」는 단위를
부르는 문장이다 — **둘 다 「그럴듯한 이야기」이고 이 지표에 대한 측정은 아니다.**
**틀릴 자리**: 모델이 애초에 지속 시간을 거의 언급하지 않으면 분모가 작아
B 가 0~1 건에 그칠 수 있고, 그러면 **C 의 0 은 아무것도 증명하지 않는다** —
그 경우 기준 A 대로 **판정하지 않고 표본을 늘린다.**

# 사전 등록 — 미결 20번 **아래쪽 끝**의 크기 재기

**작성 2026.09.09 · 정상호 · 데이터를 보기 전에 고정한다.**

미결 20번은 상한 쪽을 2026.09.08에 전 루브릭으로 쟀고
(`eval/pending20_band_ceiling/`), 그 회차가 스스로 이렇게 적어 두었다:

> ⚠ **하한 쪽(아래 절)은 이번에 재지 않았다.**

아래쪽 근거는 아직 **실클립 4건**뿐이다(`support_elbow` 5.4도 ·
`plant_knee` 24.3도 · `swing_knee` 29.0도). 여기서 그 크기를 잰다.

## 🔴 이 회차가 하지 않는 것

| | |
|---|---|
| **하한값을 고르지 않는다** | 「팔꿈치는 몇 도 아래가 불가능한가」는 **임계값 검수(미결 2번)의 성격**이다. 여기서 정하면 분포에 맞춰 긋는 것이 되고 그것은 이미 기각된 경로다(`ho` 34번) |
| **`src/` 를 고치지 않는다** | 조사 회차다. `PLAUSIBLE_RANGE` 를 좁히면 `features` 가 달라져 **B-2\~B-6 과 비교가 끊긴다**(미결 11번) |
| **처방을 고르지 않는다** | (가)·(나)·(다)는 상한 회차와 같은 이유로 열려 있다 |
| **포즈를 다시 뽑지 않는다** | 이미 있는 실측 위에서만 센다. GPU 불필요 |

## 무엇을 재는가

**하한을 하나 고르는 대신 후보 하한 `L` 에 대한 민감도 곡선을 낸다.**
검수자가 `L` 을 고를 때 필요한 숫자를 미리 준비해 두는 것이 이 회차의 목적이다.

### 대상 지표 — **관절각 4개만** (데이터를 보기 전에 고정)

`PLAUSIBLE_RANGE` 의 하한이 `0.0` 인 지표는 여섯인데, 그중 **넷만** 이 문제에
해당한다. `joint_angle`(arccos 기반)이라 0이 **기하학적 최소**이고 사람 관절이
갈 수 없는 값이기 때문이다.

| 대상 | 왜 |
|---|---|
| `plant_knee_angle_at_impact` | 관절각 |
| `swing_knee_angle_at_impact` | 관절각 |
| `swing_elbow_angle_at_impact` | 관절각 |
| `support_elbow_angle_at_impact` | 관절각 |

**제외 — 0이 정당한 값이라 하한 문제가 성립하지 않는다:**

| 제외 | 왜 |
|---|---|
| `swing_hip_flexion_after_impact_deg` | 관절각이 아니라 **증분**이다(`max_additional`). 임팩트 뒤에 더 굽히지 않았으면 0이 맞다 |
| `swing_shoulder_flexion_after_impact_deg` | 같음 (`max(after) - at_impact`) |
| `hip_rotation_range_deg` | **회전 범위**다. 안 돌았으면 작은 값이 맞다. 지어낸 0.0 은 미결 21번에서 이미 없앴다 |
| `hip_shoulder_separation_deg` | 두 축의 **차이**다. 정렬돼 있으면 0이 맞다 |
| `trunk_forward_lean_deg_at_impact` | 부호 있는 기울기이고 하한이 `-90` 이다. 0은 **똑바로 선 것**이다 |

### 후보 하한 격자 — **데이터를 보기 전에 박는다**

```
L ∈ {5, 10, 15, 20, 25, 30, 35, 40}  (도)
```

🔴 **결과를 보고 격자를 늘리거나 줄이지 않는다.** 곡선의 모양이 마음에 드는
지점을 고르게 되기 때문이다. 격자 밖이 궁금하면 **별도 회차**로 사전 등록한다.

### 각 `L` 에서 보고할 것 셋

| | 무엇 |
|---|---|
| **(a) 걸리는 값의 수** | `값 < L` 인 측정이 몇 건인가. 지표별·루브릭별 |
| **(b) 그중 지금 0등급인 것** | 「제외됐어야 할 것이 감점이 된」 건수. 상한 회차의 `below` 중 이쪽에서 설명되는 몫이다 |
| **(c) 빼면 등급이 어떻게 되는가** | 그 값을 **빼고**(키 제거) 다시 채점했을 때 총점·등급 변화. 미결 21번 `football_path.py` 와 같은 **실측 위 반사실**이다 |

(c)는 `features` 사본을 지우고 production `aggregate` 를 다시 부르는 것이고
**`src/` 도 저장된 CSV 도 건드리지 않는다.**

## 입력 — 상한 회차와 **같은 것을 쓴다**

나란히 읽히게 하려고 일부러 맞춘다.

| 출처 | 표본 |
|---|---|
| `eval/jhmdb_batting/features_swing_baseball.json` | 야구 타격 **46** (draft 루브릭) |
| `eval/phaseA/eval_b6/selector_downstream_rubric_clips.csv` (baseline 행) | 축구 인스텝 **18** · 농구 점프슛 **1** · 농구 레이업 **1** |

⚠ **`baseball/pitching` 은 이번에도 못 잰다** — Track 2 의 해당 행이
`features_ok=0` 이라 표본이 0이다. 상한 회차와 같은 한계이고, **조용히 빠지면
「문제 없음」으로 읽히므로 출력에 명시한다.**

⚠ **농구 둘은 표본이 각 1편이다.** 0이 나와도 「안 샌다」는 뜻이 아니다.

## 판정 — 이 회차는 합격/불합격이 아니다

크기 재기라 사전 등록할 「합격선」이 없다. 대신 **어떤 결과가 무엇을
뜻하는지를 미리 적어 둔다** — 결과를 보고 해석을 지어내지 않으려고.

| 나오는 값 | 그때 말할 수 있는 것 | 🔴 말할 수 **없는** 것 |
|---|---|---|
| (a)가 `L=30` 에서도 **0건** | 이 표본에서는 하한 결함이 **드러나지 않는다** | 「결함이 없다」 — 4건의 실클립 증거는 그대로 남는다. 표본이 다른 것뿐이다 |
| (a)는 있는데 (b)가 0건 | 걸리는 값이 있지만 **감점으로는 안 간다** — 급하지 않다 | 「무해하다」 — 근거 문장에는 그 값이 그대로 실린다 |
| (b)가 있고 (c)에서 등급이 움직인다 | **크기가 있다.** 검수 때 하한을 함께 볼 근거가 된다 | 어느 `L` 이 옳은지 |

🔴 **어느 경우에도 「정확해졌다」고 쓰지 않는다.** 정답이 없으므로
달라지는 것이지 나아지는 것이 아니다.

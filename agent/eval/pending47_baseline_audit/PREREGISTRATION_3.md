# 사전 등록 — **GPU 를 누가 같이 쓰면 값이 달라지나** (미결 `ho` 47번 3회차 · (가-2))

2026.09.15 · 🔴 **돌리기 전에 굳힌다.** 결과를 보고 이 문서를 고치지 않는다.

## 왜

2회차가 창을 **09-08 \~ 09-15** 로 좁혔다. 그 창에서 **입력·코드·의존성·
드라이버·가중치가 전부 같다.** 남은 자리는 **실행 시점의 기계 상태**뿐이고,
`RERUN.md` 가 N-2·N-3 으로 경고해 둔 것이 정확히 그것이다 — **다른 프로세스가
GPU 를 쓰고 있었는가.**

이 기계는 vLLM(`supersub-vllm`)도 띄운다. **여유 VRAM 이 다르면** 커널·워크스페이스
선택이 달라질 수 있고, 검출의 **문턱 0.5 절벽**이 그 미세차를 **박스 하나**로
증폭한다 — 1회차가 본 `detected_frames` 80→81 이 그 모양이다.

## 계기

**Track 2 만** 돌린다(약 120초). 비교 대상은 **오늘 깨끗한 GPU 에서 돌린 같은
산출**(`rerun_at_HEAD_track2.csv`, 95행 × 40열)이다.

| 수준 | 점유 | 남는 여유 (대략) |
|---|---|---|
| **L0** | 없음 (이미 있다 — 오늘 산출) | 약 7.5 GiB |
| **L1** | **4 GiB** | 약 3.5 GiB |
| **L2** | **6 GiB** | 약 1.5 GiB |

점유는 **별도 프로세스**가 텐서를 잡고 자는 것으로 만든다 — 계산을 하지 않으므로
**메모리만** 다르게 만든다(다른 변수를 섞지 않으려는 것이다).

## 판정 기준

| | 내용 | 합격선 |
|---|---|---|
| **A** | 🔴 계기 검사 — 실행 시작 시 **여유 VRAM 이 실제로 줄어 있다** | L1·L2 의 `free` 가 L0 보다 각각 **3 GiB·5 GiB 이상** 적을 것. 아니면 **회차 무효** |
| **B** | L1 산출을 L0 와 **전 열 대조** | 불일치 **0** 이면 「안 바뀐다」 · 하나라도 다르면 「바뀐다」 |
| **C** | L2 산출을 L0 와 **전 열 대조** | 같은 규칙 |
| **D** | 배치 폴백이 일어났는지 **보고** | `oom_events`·`min_batch` |
| **E** | `src/`·`rubrics/`·보존 자산 무변경 | 0줄 |

🔴 **L2 에서 실행이 아예 죽으면**(폴백이 batch 1 까지 가서 raise) 그것도 결과다 —
「그 조건에서는 회차가 성립하지 않는다」로 적고 C 를 비운다.

## 🔴 예측

**L1·L2 모두 L0 와 불일치 0 — 즉 안 바뀐다.** 근거: `cudnn.benchmark=False` 라
자동탐색이 꺼져 있고, Track 2 의 포즈 배치는 **한 프레임당 박스 1\~3개**라
`MAX_BATCH`=24 를 넘지 않아 **쪼개지지도 않는다**(1회차에서 확인).

🔴 **예측이 맞으면 이 후보는 닫힌다** — 그러면 09-08\~09-15 의 원인은
**「기록되지 않은 무엇」으로 남고, 그 이상 좁힐 수단이 지금은 없다.**
**닫는 것도 결과다.** 예측이 틀리면(값이 움직이면) **원인 규명**이다.

## 🔴 하지 말 것

- **점유 프로세스가 계산을 하게 두지 않는다** — 메모리 말고 다른 것이 섞인다.
- **결과를 보고 점유량을 바꿔 가며 「움직일 때까지」 돌리지 않는다.** 수준은
  위 둘로 고정이다.
- **`agent/data/`·보존 자산·`src/` 를 건드리지 않는다.**
- 🔴 **안 움직였다고 「비결정성은 없다」로 넓히지 않는다.** 이 회차가 재는 것은
  **여유 VRAM 하나**다.

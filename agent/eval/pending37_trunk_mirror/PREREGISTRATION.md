# 사전 등록 — 상체 기울기의 **촬영 방향 의존**: 크기를 잰다 (미결 `ho` 37번)

**작성 2026.09.10 · 정상호 · 측정 코드보다 먼저 고정한다.**

## 어디서 나왔나

미결 36번의 **4축 표**를 채우다 나왔다. `trunk_forward_lean_deg_at_impact`
하나를 **여섯 루브릭이 두 방식으로** 읽고 있었다 — 야구 타격만 「기울기의
크기」로 보고 나머지 다섯은 **부호를 그대로** 쓴다.

## 🔴 기전은 코드가 이미 답했다 — 이 회차는 **크기**를 잰다

```python
trunk = shoulder_c - hip_c                              # 골반중심 → 어깨중심
trunk_lean = degrees(arctan2(trunk[0], -trunk[1]))      # trunk[0] = 이미지 x
```

`normalize()` 는 **평행이동(골반중심→원점)과 스케일(어깨너비)만** 한다 —
방향을 정규화하지 않는다. 그래서 좌우를 반전하면 `trunk[0]` 만 부호가
바뀌고 `trunk[1]` 은 그대로라, 각도가 **정확히 `-θ`** 가 된다.

> **이 지표는 「앞으로 기울었나」가 아니라 「이미지 오른쪽으로 기울었나」를
> 잰다.** 피사체가 어느 쪽을 보고 서 있는지는 보지 않는다.

**증명이 필요한 부분이 아니다.** 재야 할 것은 **그래서 등급이 얼마나
바뀌는가**다.

## 밴드가 갈린다 — 다섯은 비대칭이다

| 루브릭 | 2등급 | 0등급 | 반전 대칭 |
|---|---|---|---|
| 야구 타격 (draft) | `[-25, 25]` | `≤-42` · `≥42` | ✅ **대칭** |
| 야구 투구 **active** | `[15, 40]` | `≤0` · `≥55` | 🔴 |
| 농구 점프슛 **active** | `[-8, 12]` | `≤-20` · `≥25` | 🔴 |
| 농구 레이업 (draft) | `[-5, 20]` | `≤-15` · `≥35` | 🔴 |
| 축구 인사이드 (draft) | `[2, 15]` | `≤2` · `≥25` | 🔴 |
| 축구 인스텝 **active** | `[5, 20]` | `≤0` · `≥30` | 🔴 |

야구 타격 rationale 이 이유를 적어 두었다 — *"촬영 방향에 따라 같은 자세가
+와 -로 갈린다. 그래서 **기울기의 크기만** 본다."* **한 루브릭은 알고
처리했고 다섯은 안 했다.**

## 방법 — 실측 위 **반사실** (미결 21번이 축구에 쓴 방식)

포즈를 다시 뽑지 않는다. 이미 있는 실측에서 **`trunk_forward_lean` 만
부호를 뒤집고** 나머지는 그대로 두어 `aggregate` 로 다시 채점한다.

### 🔴 반사실이 성립하는 근거 — 반전에 다른 지표는 안 변한다

코드로 하나씩 확인했다. 이것이 틀리면 반사실 전체가 틀린다.

| 지표 | 반전 하에서 | 왜 |
|---|---|---|
| `trunk_forward_lean_deg_at_impact` | 🔴 **`-θ`** | `arctan2(x, -y)` 에서 x 만 부호가 바뀐다 |
| 무릎·팔꿈치 각 (4개) | 불변 | 반사는 각도를 보존한다 |
| `hip_rotation_range_deg` | 불변 | `_axis_deg` 가 mod 180 이라 `a → 180-a`, **범위(ptp)는 보존**된다 |
| `hip_shoulder_separation_deg` | 불변 | 두 축이 같이 반사돼 차이의 부호만 바뀌는데 `abs` 로 접는다 |
| `*_after_impact_deg` (2개) | 불변 | 관절각의 증분이다 |
| `follow_through_duration_frames` | 불변 | 속도의 **크기**를 쓴다 |
| `plant_foot_to_ball_offset` | 불변 | `abs(offset_x)` 다 |

**반전에 민감한 지표는 `trunk_forward_lean` 하나뿐이다.**

## 합격 기준 — 결과를 보기 전에 박는다

이 회차는 처방이 아니라 **측정**이라 「합격」이 성과를 뜻하지 않는다.
아래는 **측정이 성립했는가**를 보는 기준이다.

| | 기준 |
|---|---|
| **A** 🔴 | **자기 검사** — 야구 타격(대칭 밴드)은 등급 변동이 **0건**이어야 한다. 나오면 반사실 구현이 틀린 것이다 |
| **B** | 반사실 값이 원값의 **정확한 음수**임을 전 행에서 확인 |
| **C** | 나머지 지표가 **한 비트도 안 변함**을 전 행에서 확인 |
| **D** | 🔴 **`features.py`·`rubrics/`·앞 회차 스크립트를 안 고친다** (import 만) |

## 반드시 보고할 것

1. 루브릭별 **`trunk` 항목 등급이 바뀌는 건수** (분모와 함께)
2. 루브릭별 **최종 등급 문자가 바뀌는 건수** · 총점 변동 폭
3. 🔴 **반전 없이, 원 실측의 부호 분포** — 이것이 이 회차의 핵심이다.
   한쪽 부호만 나오면 「이론상 결함이지만 이 데이터에선 안 난다」이고,
   **양쪽이 다 나오면 이미 나고 있다**
4. 부호가 **0 근처**인 건수 — 0 을 경계로 쓰는 밴드(투구·인스텝·인사이드)는
   측정 잡음만으로도 등급이 갈린다

**빗나가면 빗나간 대로 적는다.**

## 하지 않는 것

- 🔴 **밴드를 고치지 않는다.** 대칭으로 만들거나 값을 옮기는 것은 **임계값
  이동**이고 미결 34번·2번의 자리다. 크기를 먼저 재는 이유가 그것이다
- 🔴 **`features.py` 에 방향 정규화를 넣지 않는다.** 그것은 `features` 를
  바꿔 **B-6 전 구간 재실행**을 부른다. 이 회차는 조사다
- 🔴 **「어느 부호가 옳은가」를 정하지 않는다** — 정답이 없다
- 🔴 **거울 반전을 「반대편에서 촬영」과 같다고 말하지 않는다** (아래 한계)
- **표본을 새로 만들지 않는다** — 있는 실측만 쓴다. 인사이드 패스는 없는 채로 둔다

## 한계 — 무엇을 못 말하는지 먼저 적는다

- ⚠️ **투구·레이업·점프슛 5건씩** — 분모가 한 자릿수다

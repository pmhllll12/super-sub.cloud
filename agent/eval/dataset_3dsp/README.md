## 무엇인가

**AutoSoccerPose: Automated 3D posture Analysis of Soccer Shot Movements**
(Yeung·Ide·Fujii, CVPRW 2024) 의 공개 데이터셋
[`calvinyeungck/3D-Shot-Posture-Dataset`](https://github.com/calvinyeungck/3D-Shot-Posture-Dataset).

| | |
|---|---|
| 규모 | **200 클립 × 20 프레임 = 4,000 프레임** (train) · test 10 클립은 tracklet 만 |
| 관절 | **H3WB(H36M-17)**, 사람이 손으로 붙인 2D + MotionAGFormer 로 리프팅한 3D |
| 프레임레이트 | `position_step = 40ms` → **25fps 확정** (200/200) |
| 임팩트 | `annotated_position` 이 **프레임 12** 에 온다 (200/200 동일) |
| 라벨 | Shots on target 110 · off target 90 · `visibility` 전부 `visible` |
| 영상 | **없다.** 100×100 크롭 `.jpg` 뿐 |
| 위치 | `/mnt/d/sports-pose/soccer/raw/` (415MB). 저장소에 **넣지 않는다** |

## 🔴 확인한 것 넷 — 전부 밟을 뻔한 함정이다

### (1) 3D 정규화는 **전역 스칼라**다. 각도는 보존된다

`z` 만 `[0,1]` 로 눌려 있고(4000/4000) `x·y` 범위는 각각 0.58·0.385 다.
축별 정규화면 세 축이 다 1.0 이어야 한다. **하나의 스칼라로 나눈 것이라
각도를 그대로 써도 된다.**

🔴 **뼈 길이 변동계수로 등방성을 판정하면 오독한다.** shot 안에서 대퇴 CV 가
0.108, 어깨너비 0.155 로 나오는데 이것은 **정규화가 아니라 3D 리프팅 오차**다.
CV 만 보면 "축별 정규화 → 각도 재설계 필요" 라는 정반대 결론이 나온다.

### (2) 크롭은 **리사이즈가 아니라 잘라내기**다

이미지가 대부분 100×100 이고 일부가 100×103, 101×127 로 제각각이다.
bbox 를 정사각으로 늘렸다면 크기가 균일하고 사람이 화면을 채워야 하는데,
관절이 차지하는 폭이 중앙값 63×74px 로 **화면을 안 채운다.** 고정 창을
잘라낸 것이라 **픽셀이 등방이고 2D 각도가 원본 프레임의 각도와 같다.**

### (3) 깊이 축은 `z` 가 아니라 **`y`** 다

이름만 보고 `z`를 깊이로 읽으면 **어깨 높이차를 방향 큐로 착각한다.**
추측하지 않고 프레임마다 `2D ≈ A·3D` 를 최소제곱으로 맞춘 뒤 `A` 의 영공간을
봤다 — 깊이 방향의 축 성분이 `x 0.40 · y 0.88 · z 0.18` 이다.
`z` 는 수직(2D y 와 r=-0.97), `x` 는 좌우(2D x 와 r=-0.92).
투영 잔차 중앙값 6.8% 로, **2D 는 이 3D 의 투영이 맞다.**

### (4) 관절 12개가 다 있다 — `analyze_keypoints.py` 로 그대로 들어온다

`features.py` 가 실제로 읽는 것은 좌우 × (어깨·팔꿈치·손목·엉덩이·무릎·발목)
**12개**뿐이고 H36M-17 에 전부 있다. 얼굴 관절(코·눈·귀)은 없지만 안 쓴다.

🔴 다만 **미결 37번 3회차의 「귀 큐」는 이 데이터에서 재현할 수 없다.**
귀가 없다.

## 이 데이터가 여는 것 / 안 여는 것

| | |
|---|---|
| ✅ **`trunk_lean` 실측 분포** | 인스텝 표본이 **18 → 200 클립**. 몸통 지터가 4.0도로 무릎(13.8/15.5도)의 1/4 이라 이 지표에는 쓸 만하다 |
| ✅ **시간 격자를 안다** | 25fps 가 `info.ini` 에 있다. JHMDB 경로가 `timebase.known=false` 인 것과 다르다 (미결 7번 E-3) |
| ✅ **임팩트 후보가 있다** | SoccerNet 주석이 프레임 12 를 가리킨다. `segment_phases` 의 독립 검산에 쓸 수 있다 (미결 5번) |
| 🔴 **무릎각 밴드 검증** | 안 된다. 선수 높이 중앙값 **63.5px**(5퍼센타일 45.6px)에 무릎각 지터가 13\~15도다. 루브릭 2등급 구간 폭이 20도(150\~170)라 **지터가 구간에 견준다.** 골든셋의 vru\_basketball(70px)을 「관절각 측정에 부적합」으로 뺀 것과 같은 영역이다 |
| 🔴 **`plant_foot_to_ball_offset`** | 공이 없다 |
| 🔴 **`follow_through`** | 임팩트가 프레임 12/20 이라 뒤가 **7프레임**뿐이다 |
| 🔴 **미결 37번이 「못 쟀다」고 적은 둘** | **여전히 0이다.** 야구 투구도, 축구 **인사이드 패스**도 없다 — 이건 전부 **슛**이다 |
| 🔴 **영상 경로** | 크롭 이미지뿐이라 `pose.py`(RT-DETR → ViTPose) 를 태울 수 없다. `pitchermotion` 과 같이 `features.py` 부터 들어온다 |
| 🔴 **자세 정답이 아니다** | 정답은 **관절 위치**지 자세 등급이 아니다. 미결 19번이 적은 네 층 중 열리는 것은 관절 층 하나다 |

## 🔴 라이선스 — 저장소 코드와 데이터의 출처가 다르다

저장소는 Apache-2.0 이지만 **이미지는 SoccerNet 방송 화면을 잘라낸 것**이다.
SoccerNet 은 연구용 한정이고 별도 동의가 필요하다 — 미결 15번·19번이 적어 둔
그 축이다.

- **내부 검증에는 쓴다.** 상용 경로·대외 공개에는 쓰지 않는다
- 🔴 **크롭 이미지와 어노테이션 JSON 을 이 공개 저장소에 커밋하지 않는다.**
  `3dsp_annotation/jsons/` 에는 (만료된) AWS presigned URL 이 그대로 들어 있다

## 잰 숫자 — 미결 37번과 이어지는 부분

전문은 [`probe_3dsp.out`](probe_3dsp.out), 해석은 미결 37번 4회차에 있다.

### `trunk_lean` 은 200클립에서도 **부호가 반반**이다

| | |
|---|---:|
| 음수 / 양수 | **100 / 100** |
| 중앙값 · 평균 | **-0.1도** · +0.1도 |
| `\|θ\| < 5도` | **73/200 (36%)** |
| 🔴 좌우 반전 시 인스텝 등급이 바뀌는 클립 | **192/200 (96%)** |

임팩트 프레임을 9\~16 어디로 옮겨도 **78\~98%** 다. 2회차가 정의역 전수로
낸 「인스텝 33% 뒤집힘」이 **발생률의 과소평가**라고 적어 둔 추론과 방향이
같고, 1회차의 18클립 100% 와도 같다.

### 방향(facing) 큐 — 3D 깊이가 생겼지만 **전제는 아직 안 선다**

3회차의 사전 등록 기준을 그대로 대 보면:

| | 기준 | 귀·이동 큐 (3회차) | 3D 깊이 큐 (여기) |
|---|---|---|---|
| A | 커버리지 70%+ | ✅ 97% | ✅ **100%** |
| B | 독립 큐와 일치 70%+ | 🔴 46% | ✅ **83%** (어깨 대 골반) |
| C | 시간 안정 80%+ | 🔴 66% | 🔴 **66% / 70%** |
| D | 구조적 비순환·독립 | ✅ | 🔴 **안 선다** |

🔴 **B 의 83% 를 그대로 믿으면 안 된다.** 어깨 큐와 골반 큐가 **같은 리프팅
모델 하나**에서 나온다 — 서로를 검증하지 못한다. 3회차의 귀·이동은 적어도
서로 다른 출처였다.

그리고 **C 는 여전히 떨어진다.** 사람은 한 슛 안에서 돌아서지 않는데
3분의 1의 클립에서 부호가 뒤집힌다.

> **말할 수 있는 것은 「3D 리프팅으로 방향 큐를 만들어도 시간 안정성은
> 안 나아졌다」까지다.** 커버리지와 일치도만 보고 (나)를 되살리면
> 3회차가 정정한 그 실수를 반복한다.

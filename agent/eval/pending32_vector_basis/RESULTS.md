# `player_vector` 의 축 — 세 후보의 실측 (2026.09.11)

미결 `jin` 28번의 「확인해 주실 것」(`ho` 32번 표의 인스텝 **7** vs 실물 **6**)에
답하다 나온 것이다.

🔴 **사전 등록된 실험이 아니다.** 가설도 합격선도 없는 **descriptive 계수**이고,
아래 숫자를 보고 축을 고른 것이 아니다 — 축 선택의 근거는 구조적인 것이다
(등급은 3단계라 방향을 잃는다). 이 문서는 그 구조가 실제 데이터에서 얼마나
나타나는지를 **세어 둔 것**이라 판정 문장이 없다.

재실행: `cd agent && uv run python eval/pending32_vector_basis/count_bases.py`
(GPU·영상 불필요 — 이미 측정된 `eval/pending21_hip_rotation/before_rubric_clips.csv`
를 읽고 production 의 `grade_for`·`score_for` 를 import 만 한다.)

## 1. 7 과 6 은 **둘 다 맞다** — 서로 다른 양이다

축구 인스텝 슈팅 루브릭:

| | 수 |
|---|---|
| 채점 항목 (`criteria`) | **6** — `grade.football.instep_shot.*` 가 6행인 이유 |
| 그 항목들이 쓰는 지표 (`measured_by` 합집합) | **7** |

둘이 갈리는 자리는 `follow_through` 하나다 — **한 항목이 지표 둘**을 쓴다
(`swing_hip_flexion_after_impact_deg` · `follow_through_duration_frames`).

`ho` 32번 표의 열 이름이 **「쓰는 지표」**였으므로 7 은 그 열에서 맞는 값이고,
`jin` 28번이 본 6 은 **항목 수**로 맞는 값이다. 표는 안 틀렸지만, 그 표를
**차원 근거로 읽으면** 둘 중 어느 것이 차원인지가 안 정해져 있다는 것이
이번에 드러났다. (인사이드 패스도 같다: 항목 **5** · 지표 **6**.)

## 2. 🔴 「루브릭이 쓴다」와 「실제로 재진다」가 다르다

축구 인스텝 18편의 지표별 보유율:

| 지표 | 보유 |
|---|---|
| `plant_knee_angle_at_impact` | 18/18 |
| `swing_knee_angle_at_impact` | 18/18 |
| `trunk_forward_lean_deg_at_impact` | 18/18 |
| `swing_hip_flexion_after_impact_deg` | 18/18 |
| `follow_through_duration_frames` | 18/18 |
| `hip_rotation_range_deg` | **15/18** |
| **`plant_foot_to_ball_offset`** | 🔴 **0/18** |

`plant_foot_to_ball_offset` 은 **공 검출이 있어야 나오는 값**이고, 이 표본에서는
한 번도 안 나왔다 — 그 항목(`plant_foot_position`)은 이 18편에서 매번
`skipped[]` 로 빠진다(가중치는 재정규화된다 — 0점이 아니다).

#### 🔴 정정 (2026.09.11 같은 날) — 「실측된 적이 없다」고 쓴 것을 바로잡는다

처음에 **「7번째 지표는 실측된 적이 없다」**고 적었는데 **틀렸다.** 그날 저녁
실서버 로그에서 그 항목이 실제로 채점됐다:

```
0등급  디딤발 위치   디딤발이 공과 수평으로 어깨너비 0.216배(약 11cm) 떨어져 나란하다.
```

**공 검출은 살아 있다**(COCO 32 → `sports_ball`, `MIN_TOOL_CONFIDENCE = 0.8` ·
`MIN_CONFIDENT_FRAMES = 3`). 0/18 은 **이 골든셋 18편의 성질**이지 기능의
성질이 아니다 — 방송·데이터셋 클립이라 공이 작거나 안 보이는 프레임이 많다.

🔴 **표본의 성질을 기능의 성질로 일반화한 것이 이 오류의 형태다.** 「이 표본에서
0/18」과 「실측된 적이 없다」는 다른 문장이고, 뒤엣것은 내가 안 본 모집단
(실사용자 업로드)까지 말한다. 위 3절의 차원 논의에는 영향이 없다 — 거기서
필요한 것은 **이 표본에서 축을 채울 수 있는가**였고 그건 그대로다.

`hip_rotation_range_deg` 의 3편 결측은 `ho` 21번의 처방이 보이는 것이다
(못 쟀으면 **키를 안 넣는다**. 0.0 으로 지어내던 것을 고쳤다).

🔴 **그래서 결측은 루브릭 사이에만 있는 것이 아니라 한 루브릭 안에도 있다.**
`jin` 28번 설계의 「같은 `rubric_code` 안에서는 모든 행의 꼬리가 똑같이 0 이라
코사인에 영향이 없다」는 전제가 **이 자료에서는 안 선다** — 꼬리가 클립마다
다르게 빈다.

## 3. 축 후보 셋 — 고유 벡터 수

전 축이 채워진 **15/18편** (항목 5 · 지표 6):

| 축 | 고유 벡터 | |
|---|---|---|
| **(A) 측정 지표값** (연속, 물리 단위) | **15/15** | 겹침 없음 |
| (B) 항목별 등급 (0/1/2) | **12/15** | 🔴 **3편이 남과 구분되지 않는다** |
| (C) 항목별 `stat` (연속 0~100) | 15/15 | 겹침 없음 |

15편에서 이미 20%가 겹친다. 항목 5개 × 3단계면 표현할 수 있는 자리가 243개뿐이고
실제 등급은 가운데로 몰리므로, **모집단이 커질수록 겹침은 늘어난다**(이 문장은
추론이지 측정이 아니다).

## 4. 무엇이 남았나

**(B) 등급은 축이 아니다** — 위 겹침 때문이고, 그 전에 구조적으로 3단계다.

**(A) 와 (C) 는 겹침으로는 안 갈린다.** 갈리는 자리는 **방향**이다:
`stat` 은 「이상 구간에서 얼마나 떨어졌나」라 **과하게 돈 선수와 덜 돈 선수가
같은 값**으로 간다. 「비슷한 플레이 스타일」을 찾는 자리에서 그 둘은 안 닮았다.
그래서 (A) 가 스타일 축이고 (C) 는 **수준** 축이다 — 이건 세어서 나온 결론이
아니라 정의에서 나온 것이라 여기서는 재지 않았다.

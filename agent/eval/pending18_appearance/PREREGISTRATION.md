**작성 2026.09.09 · 정상호 · 프로토타입 코드보다 먼저 고정한다.**

미결 18번이 남긴 것: **닻은 다인 10건 전수에서 10/10 맞았는데, 이어가기가
3건에서 다른 사람으로 갈아탄다.** 배선은 2026.09.09에 끝났으므로
(`paik` 6번) 남은 것은 이 처방 하나다.

## 무엇이 고장났는지는 이미 안다

지금 이어가기는 **순수 IoU 탐욕 연결**이다(`pose.py`의 `walk`). 실패 구조도
항목에 적혀 있다 — **크고 가만히 선 사람이 IoU 흡인원**이다. 타자는 빠르게
움직여 자기 직전 박스와의 IoU가 낮아지는데, 심판은 서 있어서 근처 무엇과도
잘 겹친다. `3R1kvNrGJK0`에서 105프레임에 두 박스가 겹치고 112부터 선택이
심판 위에 있다.

처방 (가)는 **겹침에 외양(색 히스토그램)을 곱한다.** 프론트
`personTrack.ts`가 이미 그렇게 하고 있고, **겹침만으로는 부족하다는 결론을
이미 낸 코드**다. 새 의존성이 없다(`cv2`·`numpy`는 이미 쓴다).

## 🔴 이 회차가 하지 않는 것

| | |
|---|---|
| **`src/` 를 고치지 않는다** | 조사 회차다. 프로토타입은 `eval/` 안에 두고 production 은 **import 만** 한다 |
| **채택하지 않는다** | 합격해도 그것은 「다음 회차에서 구현할 근거가 생겼다」까지다 |
| **임계값을 결과에 맞추지 않는다** | 가중치·문턱은 아래에 **미리 박는다**. 한 클립을 통과시키려고 손보는 것이 이 프로젝트가 반복해서 겪은 형태다 |
| **「정확해졌다」고 쓰지 않는다** | 정답이 없다. 달라진 것이지 나아진 것이 아니다 |

## 프로토타입 규격 — **데이터를 보기 전에 박는다**

닻 프레임의 선택 박스 안에서 **HSV 색 히스토그램**을 만들고, 이어갈 때
후보 점수를 이렇게 매긴다:

```
score(cand) = IoU(previous, cand) × ( APP_FLOOR + (1 - APP_FLOOR) × sim(anchor_hist, hist(cand)) )
```

| 상수 | 값 | 왜 이 값인가 (결과를 보기 전) |
|---|---|---|
| `H_BINS × S_BINS` | 32 × 32 | OpenCV 예제의 관례값. 조명에 덜 민감하도록 V는 뺀다 |
| `sim` | `cv2.compareHist(..., HISTCMP_CORREL)` 을 0~1로 자른 값 | 상관은 -1~1이라 음수는 0으로 |
| `APP_FLOOR` | **0.3** | 외양이 완전히 어긋나도 겹침이 압도적이면 이어갈 수 있게 남기는 바닥. 0으로 두면 외양 하나가 거부권을 갖는다 |
| 히스토그램 갱신 | **하지 않는다** (닻의 것을 끝까지 쓴다) | 갱신하면 갈아탄 뒤의 외양을 학습해 **잘못된 대상에 고착된다** — 지금 결함을 더 굳히는 방향이다 |

🔴 **가중치를 결과를 보고 바꾸지 않는다.** 이 값들로 불합격이면 「이 설정의
외양 모델로는 안 된다」가 결과이고, 다른 설정은 **별도 회차**로 사전 등록한다.

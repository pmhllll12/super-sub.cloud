# 사전 등록 — ㉳ (다) 드리블 터치 간격을 **잰다**

**작성 2026-09-21, 측정 스크립트를 쓰기 전.** 이 문서를 커밋한 뒤에 짠다.
상수·합격선·판별 규칙·예측은 여기서 굳고 **결과를 보고 고치지 않는다.**

## 무엇을 묻나

㉳ 1·2회차가 `L`(구간 길이) 표에서 **10·15 프레임을 굵게** 뒀다. 그 근거는
*「초당 두세 번 × 30fps」* 라는 **가정**이고, 항목이 스스로 이렇게 적어 뒀다:

> 🔴 **재 보지 않았습니다 — 드리블 클립이 없습니다.**

**드리블 클립이 생겼다.** 46번이 SoccerNet 방송 클립 경로를 열었고
`/mnt/d/sports_dataset_probe/soccernet` 에 **100편**이 있다. 그래서 묻는다:

> **연속한 두 터치 사이는 실제로 몇 프레임인가. 10~15 가 그 안에 드는가.**

## 계기 — 복제하지 않는다

🔴 **11회차(`pending18_ball_proximity/measure_proximity.py`)를 고치지 않고
`import` 한다.** `detect_clip` · `analyse` · `foot_point` · `NEAR` ·
`NEAR_SWEEP` · `MIN_BALL_COVERAGE` 를 그대로 쓴다. 복제하면 두 회차의 계기가
조용히 갈라진다(미결 10번의 형태). 🔴 **`src/`·`rubrics/` 는 0줄.**

`analyse` 가 내는 `rows` 는 프레임마다 `t`(인덱스)와 `d_min`(가장 가까운
후보의 발 지점까지 거리 ÷ 키높이)을 담는다. 이 회차는 **그 위에 에피소드만
얹는다.**

## 정의

| | |
|---|---|
| **근접 프레임** | `d_min ≤ NEAR` (주 값 0.25 키높이) **이고 그 프레임에 공이 잡혀 있을 것** |
| **터치 에피소드** | 근접 프레임의 **연속 덩어리**(사이에 비근접 프레임이 없는 최대 구간) |
| **간격** | 연속한 두 에피소드의 **시작 프레임 차이** |
| 🔴 **끊긴 구간은 버린다** | 두 에피소드 **사이에 공이 안 잡힌 프레임이 하나라도 있으면 그 간격은 안 센다.** 공 추적이 끊긴 것을 「간격이 길다」로 읽으면 분포가 위로 늘어난다 |
| 🔴 **30fps 로 환산한다** | SoccerNet 원본이 **25fps** 다. 프레임 수를 그대로 비교하면 **1.2배** 어긋난다. `간격_30 = 간격_프레임 × 30 / sampled_fps` |
| 클립 관문 | `ball_coverage ≥ MIN_BALL_COVERAGE`(0.30). 미만 클립은 제외하고 **몇 편이 빠졌는지 보고한다** |

## 기준

| | | 실패하면 |
|---|---|---|
| **A** (관문) | 간격 표본 **≥ 30개** | 🔴 **판별불가.** B·C·D 를 **보지 않는다** — 분모가 없으면 분포가 없다 |
| **B** | 간격의 중앙값·Q1·Q3 (30fps 환산) 보고 | — |
| **C** (판정) | **10~15 가 Q1~Q3 안에 드는가** | 안 들면 「가정이 틀렸다」 |
| **D** (민감도) | `NEAR_SWEEP`(0.15·0.25·0.35·0.50) 네 값에서 **C 의 답이 안 뒤집히는가** | 뒤집히면 결론을 문턱에 업은 것 |
| **E** (짝 기준) | 🔴 **야구 39편(phaseA)에서 간격 표본 < 10** | 드리블이 없는 표본에서 간격이 쏟아지면 계기가 **딴 것을 세고 있다** |
| **F** | `src/`·`rubrics/` **0줄** · `pytest -q` 통과 | — |

🔴 **의존 관계를 먼저 적는다** (3회차에서 멈춤 규칙을 잘못 건 반성):
**A 는 B·C·D 의 선행**이다. **E 는 A 와 독립**이라 A 가 실패해도 따로 본다 —
계기가 헛도는지는 표본 수와 무관하게 알아야 한다. **F 도 독립.**

## 예측 — 돌리기 전에 박는다

| | 예측 | 근거 |
|---|---|---|
| **P-1** | A 통과 (표본 ≥ 30) | 12회차가 **40편**에서 발치 프레임 198개·9클립을 냈다. 여기는 **100편**이다 |
| **P-2** | 🔴 **중앙 간격이 15보다 클 것** | 방송 화면은 공이 한 사람 발치에 계속 있지 않다 — 패스·경합·이동이 섞인다. 「초당 두세 번」은 **드리블 중인 사람만 클로즈업으로 볼 때**의 그림이다 |
| **P-3** | E 통과 (야구 < 10) | 46번 실측에서 야구 39편의 발치 프레임이 **44f · 1클립**(0.4%)이었다 |
| **P-4** | 클립 관문에서 **절반 이상**이 빠질 것 | 12회차에서 주 층에 든 클립이 **9/40** 이었다 |

🔴 **P-2 가 맞으면 1·2회차의 굵은 표시(`L`=10·15)가 틀렸다는 뜻**이고, ㉳ 가
「구간 길이」를 다시 골라야 한다. **그 자체가 이 회차의 값이다.**

🔴 **문턱을 옮겨 판정을 만들지 않는다.** D 가 뒤집히면 「문턱에 업혀 있다」고
적고 끝낸다 — 11회차가 그렇게 했다.

## 하지 않는 것

- 🔴 **「축구 드리블에서 몇 %」로 일반화하지 않는다.** 표본은 **방송 화면**이고
  우리 서비스 입력(사용자가 찍은 영상)과 화각이 다르다. 넘는 것은 **간격의
  크기 감각**이지 비율이 아니다
- 🔴 **`src/` 를 안 고친다.** 조사 회차다
- 🔴 **(나) 밴드를 이 회차에서 정하지 않는다.** 간격을 알아야 밴드를 말할 수
  있지, 간격을 재는 김에 밴드까지 정하면 **같은 표본으로 재고 맞추는 것**이 된다

# 사전 등록 — 실영상 fps 불변성 (기준선 수립)

작성 2026-09-09 · 미결 `ho` 7번 · `ho` 34번(검증 기준 재정의)
**측정 코드보다 먼저 커밋한다.**

## 1. 왜 또 재나 — 기존 자료와 무엇이 다른가

`eval/pending7_fps/` 는 **외부 포즈 시계열을 솎아** 60→30/20/15/12 를 만들었다.
포즈 추정과 디코딩이 빠진 **모의**다. 거기서 나온 「60↔30 최종 등급 37% 변동」이
지금까지 인용돼 온 값이다.

여기서는 **실영상을 다시 인코딩해 전 구간을 태운다** — 디코딩·샘플링·포즈
추정까지 포함한다. 사용자가 실제로 하는 일이 이쪽이다.

🔴 **두 값이 다르게 나와도 어느 쪽이 틀린 것이 아니다.** 서로 다른 것을 잰다.
모의는 「격자만 바뀌면」이고 이쪽은 「파일이 바뀌면」이다.

## 2. 🔴 이것은 판정이 아니라 **기준선 수립**이다

`ho` 34번이 fps 불변성을 검증 지표로 제안했지만 **아직 PM 판단 전**이다.
그래서 **합격선을 여기서 정하지 않는다.** 값을 내고 그 판단에 넘긴다.

합격선을 지금 만들면 내가 낸 숫자에 맞춰 선을 긋는 것이 되고, 그것은
「분포에 맞춰 긋기」와 같은 잘못이다.

## 3. 표본과 조작

| | |
|---|---|
| 클립 | 재현성 측정(`pending34_repro`)과 **같은 4편** — 축구 3 + 농구 1. 같은 표본이어야 「가만두면 0.00, fps 바꾸면 얼마」를 나란히 말할 수 있다 |
| 원본 fps | 24 · 23.976 · 29.97 · 23.976 (전부 낮다) |
| 조작 | 원본 · **1/2** · **1/3** 로 **하향** 재인코딩 (`ffmpeg -r`) |

🔴 **상향은 하지 않는다.** 24fps 를 60fps 로 만들면 프레임이 복제될 뿐
**「같은 장면을 60fps 로 찍은 것」이 아니다.** 그것을 재고 「60fps 에서 이렇다」고
적으면 없는 정보를 지어낸 것이 된다. 하향은 저fps 촬영을 실제로 근사한다.

## 4. 무엇을 보고하나

원본 대비, 변형마다:

- **총점 차이**(절대값)와 **최종 등급이 바뀌었는가**
- **항목별 등급 벡터**가 바뀐 항목 수
- **품질 게이트 결과**가 갈렸는가 (원본은 되는데 저fps 에서 반려되는가)
- 참고: `sampled_fps` · 분석에 쓰인 프레임 수

## 5. 예상 — 그리고 예상이 판정을 바꾸지 않는다

**총점이 움직일 것으로 본다.** 미결 7번이 원인을 확정해 두었다 — 임팩트를
고르는 argmax 의 승자 마진이 얇고(p10 1.12배), 격자가 바뀌면 승자가 갈린다.

🔴 **예상과 다르게 「거의 안 변한다」가 나와도 그대로 적는다.** 클립이 짧고
(2.5~6초) 원본 fps 가 낮아(24~30) 기존 모의(60fps 기준)보다 조작 폭이 작다 —
그 경우 **「변동이 작다」가 아니라 「이 표본에서는 작다」로 적는다.**

## 6. 하지 않을 것

- 🔴 합격선을 만들지 않는다 (2절)
- 🔴 결과를 보고 표본을 늘리거나 줄이지 않는다
- 🔴 **기존 37% 를 이 값으로 대체하지 않는다.** 다른 것을 재므로 둘 다 남긴다
- 판정 모델을 부르지 않는다 — 등급은 `grade_for` 가 정한다
  (`pending34_repro` 기준 E 에서 확인)

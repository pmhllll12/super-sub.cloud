# 사전 등록 — 구간이 짧아지면 **무엇이 먼저 깨지는가** (미결 `ho` 45번 5회차)

작성 2026.09.18 · **돌리기 전에 굳힌다.** 결과를 보고 아래를 고치지 않는다.

## 왜 이 회차인가 — 4회차가 이름을 붙여 둔 질문이다

4회차가 구간(`window`)을 받게 만들면서 기준 **D** 로 22건을 세었고, 항목에
이렇게 적었다.

> 🔴 **이벤트가 촘촘하면 구간이 짧아지고, 짧아지면 구간 분할 자체가 성립하지
> 않는다.** … 간격이 짧을 때 무엇을 할지는 다음 회차의 질문이고 지금 추측으로
> 답하지 않는다(`2` 를 낮추면 그 순간 새 상수라 F 불합격이다).

**그 질문을 그대로 연다.** 🔴 다만 4회차의 문장에는 **검증 안 된 인과가 하나
들어 있다** — 「짧아져서 안 된다」이다. 22건은 **클립을 반으로 자른** 창에서
났고, 반 클립은 보통 50~150프레임이라 **경계 검사가 요구하는 5프레임을 한참
넘는다.** 그러니 그 22건이 길이 때문일 수는 없다. 이 회차는 **길이와 자리를
가른다.**

## 🔴 재는 대상 — 경계 검사 한 줄이다

```python
first = int(np.argmax(usable))
last  = int(len(usable) - 1 - np.argmax(usable[::-1]))
if impact - first < 2 or last - impact < 2:
    raise InsufficientQuality(...)
```

창을 주면 `usable` 이 그 구간으로 좁아지므로, 위 `first`·`last` 는 **창의
경계**가 된다. 그래서 창 안에서 고른 `impact` 가 **창 가장자리 2프레임 안에
앉으면 실패**한다.

**두 해석이 있고 처방이 전혀 다르다.**

| | 해석 | 그러면 처방은 |
|---|---|---|
| **(가)** | 창이 짧아서 실패한다 | 🔴 `2` 를 낮추거나 최소 길이를 새로 두는 길 — **새 상수**다 |
| **(나)** | **창에 이벤트가 없어서** 실패한다 — 신호가 단조로운 구간에서는 국소 `argmax` 가 **가장자리에 앉는다** | 🔴 경계 검사는 **이미 「이 창에 이벤트가 없다」를 잡는 계기**다. 바깥이 창을 이벤트 주위에 두면 그만이고 **새 상수가 0개**다 |

(나)가 맞으면 드리블(㉳)의 벽은 파이프라인이 아니라 **이벤트 검출**로 옮겨
가고, 그건 1~3회차가 이미 재고 있는 자리다.

## 🔴 이 회차가 **하지 않는 것** — 먼저 적는다

| 안 한다 | 왜 |
|---|---|
| `src/`·`rubrics/` 고치기 | **조사 회차**다. production 을 **import 만** 한다 |
| `2` 를 다른 값으로 재 보기 | 값을 바꿔 가며 최적을 찾는 순간 이 표본이 훈련셋이 되고 합격이 뜻을 잃는다(52번 1회차의 「하지 말 것」과 같은 형태) |
| 「드리블이 된다/안 된다」 말하기 | 표본에 드리블이 **0편**이다. 재는 것은 **경계 검사의 성질**이지 드리블 성능이 아니다 |
| 이벤트 검출 규칙 건드리기 | 1~3회차의 영역이다. 여기서 섞으면 어느 쪽이 결과를 냈는지 못 가른다 |
| 분석 창(`DEFAULT_MAX_SECONDS`) 손대기 | 사용자에게 보이는 값이고 `ho` 30번 결정 전이다 |

## 표본과 절차

**표본**: `eval/phaseA/cache_target30/` 의 **39클립**(저장소 사본, 🔴 **GPU
불필요** · 🔴 **전처리 경로와 무관하다** — 키포인트를 이미 뜬 사본이라 47·49번의
갈림이 이 회차에 안 닿는다). 설정 셋은 4회차와 같다:
`(leg, extension_peak)` · `(arm, extension_peak)` · `(arm, distal_apex)`.

🔴 **표본이 야구다**(`ho` 39번 종목 정리 전의 평가 자산). 재는 성질이 **신호의
모양과 경계 검사의 산수**라 종목을 넘지만, 🔴 **이것으로 축구·드리블 성능을
말하지 않는다.**

**절차** — (클립 × 설정)마다:

1. `window=None` 으로 **기준**을 뜬다. 성공하면 그 `impact` 를 **알려진
   이벤트** `e` 로 삼고, 유효 구간 `[first, last]` 를 얻는다.
   🔴 **기준이 실패하는 (클립 × 설정)은 층 나누기에서 뺀다** — 알려진 이벤트가
   없으면 층 E/N 을 정할 수 없다. 뺀 수는 결과에 **분모와 함께** 적는다.
2. `[first, last]` 를 길이 `L` 의 창으로 **겹치지 않게 타일링**한다
   (`first` 부터 차례로, 🔴 **끝의 자투리 타일은 버린다** — 길이가 다르면
   같은 `L` 의 비교가 아니다).
   `L ∈ {60, 40, 30, 20, 15, 12, 10, 8, 6, 5}`.
3. 타일마다 `segment_phases(window=(a, b))` 를 부르고 결과를 **사유로** 남긴다:
   `ok` · `boundary`(경계 검사) · `empty`(구간에 유효 프레임 없음) ·
   `other`(그 밖의 예외 이름 그대로).
4. 타일을 **두 층**으로 가른다.
   - **층 E** — `e` 를 담은 타일 (`a ≤ e < b`). 타일마다 정확히 하나다
   - **층 N** — 나머지 타일

## 🔴 산수로 미리 아는 것 — 층 E 의 기댓값

층 E 의 타일은 전역 `argmax` 를 담으므로 **창 안 `argmax` 도 그 프레임**이다
(부분집합의 argmax = 전역 argmax, 전역 argmax 가 그 부분집합에 있을 때).
타일 경계는 이벤트와 무관하게 정해지므로 `e` 가 타일 안 어디에 앉는지는
사실상 균등하고, **양 끝 2프레임씩이 실패**한다. 따라서

```
층 E 성립률 ≈ (L - 4) / L
```

**이것은 예측이 아니라 산수다.** 층 E 가 이 값에서 크게 벗어나면 **계기가
고장 난 것**이지 발견이 아니다 — 아래 기준 B 가 그것을 센다.

## 사전 등록된 예측 — 결과를 보기 전에 적는다

| | 예측 | 어떤 분포에서 나왔나 (13회차에서 배운 것) |
|---|---|---|
| **P1** | 층 N 성립률이 층 E 보다 **낮고**, `L` 전체에서 **같은 방향** | 신전 각속도 곡선은 임팩트 한 번에서 뾰족하고 나머지는 완만하다고 보기 때문이다. 완만한 구간의 국소 최대는 가장자리로 밀린다. 🔴 **곡선 모양을 실제로 그려 본 적은 없다** — 이 예측의 근거는 `extension_peak` 의 정의뿐이다 |
| **P2** | 층 N 의 실패 중 `boundary` 비중 ≥ **80%** | `empty` 는 검출 실패가 창 전체를 덮어야 나는데 캐시 사본은 검출률이 높다 |
| **P3** | 층 N 성립률이 `(L-4)/L` 보다 **20%p 이상** 낮은 `L` 이 **하나 이상** 있다 | P1 이 사실이면 어딘가에서 갈라져야 한다. 🔴 `L` 을 안 고르고 「하나 이상」으로 적는 것은 **어느 `L` 에서 갈릴지 모르기 때문**이고, 보고 나서 고르지 않으려고 미리 이렇게 적는다 |

### 🔴 G — 짝 기준: **층 N 이 산수와 구별되지 않으면 불합격이다**

D·E 만으로는 부족하다. **층 N 은 층 E 보다 타일 수가 훨씬 많아** 작은 차이도
「유의해 보이게」 만들 수 있고, 무엇보다 **`(L-4)/L` 자체가 이미 `L` 이 작아지면
급격히 떨어진다**(L=5 면 20%). 그래서 「층 N 도 낮더라”는 것만으로는 (나)의
근거가 안 된다 — **산수만으로 그렇게 될 수 있기 때문**이다.

**(나)가 서려면 층 N 이 산수보다 더 낮아야 한다.** 그것이 F 이고, F 가
안 서면 **D·E 가 서더라도 이 회차는 (가)/(나) 를 못 가른 것**으로 적는다.

🔴 **그리고 그 반대도 미리 적는다** — F 가 서도 **층 N 의 실패가 특정 클립
몇 편에 몰려 있으면** 그것은 신호의 성질이 아니라 그 클립들의 성질이다.
**클립별 층 N 성립률을 함께 내고**, 🔴 **하위 3편을 빼도 F 가 유지되는지**를
같은 표에 적는다. 안 유지되면 **판별불가**다.

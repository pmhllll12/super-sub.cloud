# 사전 등록 — D: **판독 계기를 고친다** (미결 23번)

**코드에 손대기 전에 커밋한다.** 결과를 보고 기준·예측을 고치지 않는다.

🔴 **이 회차는 제품을 안 고친다.** `src/` 도 `rubrics/*.yaml` 도 안 건드린다.
고치는 것은 **재는 자**다.

## 1. 무엇이 문제인가 — 같은 문장인데 숫자가 달랐다

C 회차의 대조군(C0)은 B 회차와 **같은 파일·같은 문장**이다. 그런데

| | B 판독 | C 판독 |
|---|---|---|
| D 방향 오독 | **3/30** | **5/30** |
| E 잘함 오독 | **0/22** | **1/22** |

문장도, 판정 규칙(「반대 조각의 방향을 주장하는 절을 포함하면 오독」)도,
판독자(Claude 세션)도 안 바뀌었다. **판독만 달랐다.**

**놓친 자리 셋이 전부 같은 모양이다** — 첫 문장은 맞고 **뒤 문장이 반대**다:

> `follow_through` **79.2** (= 과한 마무리 조각)
> *"…79.2도로 패스보다 슈팅처럼 과도하게 뻗은 마무리다."* ✅
> *"**추가 굴곡이 부족해** 공이 공중에 뜨는 느낌이 강하다."* 🔴

> `follow_through` **125.8**
> *"…과도하게 뻗었다."* ✅ *"**추가 굴곡이 부족해** …"* 🔴
> *"**더 깊은 각도**나 지속 시간을 확보하면 …"* 🔴

🔴 **규칙이 틀린 것이 아니라 규칙을 다 적용하지 않았다.** 겨냥한 어구가
사라진 것을 확인하고 **첫 마침표에서 멈췄다.** 「포함하면」이라는 낱말이
**모든 절을 봐야** 성립하는데, 읽는 사람이 그것을 보장할 방법이 없었다.

## 2. 무엇을 바꾸는가 — **문장 단위 → 절 단위**, 그리고 열거를 강제한다

계기를 셋으로 나눈다. 앞의 둘은 **코드**라 재현된다.

| | | 재현되는가 |
|---|---|---|
| ⑴ **절 쪼개기** | 문장을 종결·연결 어미로 쪼갠다 (`split_clauses.py`) | ✅ 결정론적 |
| ⑵ **자리마다 맞는 방향 붙이기** | `grades_plain[등급][조각]` 을 루브릭에서 읽어 나란히 놓는다 | ✅ 결정론적 |
| ⑶ **절마다 방향 판정** | 사람(이번엔 Claude)이 절 하나씩 본다 | ❌ 판단이다 |

**산출물이 「wrong/ok」 한 글자가 아니라 「절 목록 + 절마다 판정」이다.**
그래야 나중에 누가 다시 볼 때 **어느 절에서 갈렸는지** 짚을 수 있다.
지금은 3/30 과 5/30 중 무엇이 맞는지 **문장 단위라 따질 자리가 없었다.**

🔴 **쪼개기는 과하게 쪼개는 쪽으로 틀린다.** 덜 쪼개면 절이 숨고, 그것이
지금 고치는 결함 자체다. 과하게 쪼개면 판정이 늘 뿐 숨는 것은 없다.

## 3. 무엇을 재는가 — 결과 전에 고정

**대상**: `evidence_other_levels.json`(C0) 의 **D 30자리**. B·C 가 서로
다르게 읽은 **바로 그 표본**이다. 🔴 **문장을 다시 만들지 않는다** — 같은
파일을 읽는다. GPU 를 안 쓴다.

**두 번 읽는다.** 2차는 **순서를 섞고** 자리 이름(항목·값)을 **가린 채** 읽는다.

| | 기준 | 합격선 |
|---|---|---|
| **A** | 🔴 **1차·2차 불일치 자리 수** | **≤ 1/30** |
| **B** | C 회차가 잡은 5자리를 1차가 **전부 잡는가** | **5/5** |
| **C** | 자리마다 절이 **1개 이상**이고 판정이 **절에 붙어 있는가** | 30/30 |
| **D** | 쪼개기가 **결정론적인가** (같은 입력 두 번 → 같은 출력) | 동일 |
| **E** | `pytest tests/ -q` | 569 통과 (`src/` 무변경) |

🔴 **「오독 수가 줄어야 한다」를 합격선에 두지 않는다.** 이 회차는 **재는
자**를 고치는 것이라 **숫자가 늘어도 정상**이다. 줄어야 한다고 적어 두면
결국 덜 잡는 판독을 고르게 된다 — 그게 지금 고치는 결함이다.

## 4. 짝 기준 — 결과 전에 박는 예측

| | 예측 | 왜 |
|---|---|---|
| **P-1** | 1차 오독이 **5보다 늘어난다** | 절을 다 보면 지금까지 지나친 뒤 절이 더 나온다 |
| **P-2** | 불일치 **≤1** (기준 A) | 절 단위면 판단할 단위가 작아 흔들릴 여지가 준다 |
| **P-3** | 새로 잡히는 자리는 **「앞 절 맞고 뒤 절 반대」** 형태에 몰린다 | 놓친 셋이 다 그 모양이었다 |
| **P-4** | 🔴 **C 가 잡은 5자리는 1차에서도 전부 잡힌다** | 안 잡히면 새 계기가 **덜 보는** 것이고, 그건 실패다 |

## 5. 🔴 이 회차가 **증명하지 못하는 것**

- **2차는 1차 기억에 오염된다.** 같은 세션의 같은 판독자다. 순서를 섞고
  이름을 가려도 문장 자체는 기억한다. 그래서 기준 A 의 불일치 수는
  **재현성의 낙관적 상한**이지 재현성 자체가 아니다. 🔴 **「재현된다」고
  적지 않는다** — 「이 조건에서 이만큼 갈렸다」로 적는다
- **절 판정이 정답이라는 뜻이 아니다.** AI 판독이고, 로드맵 2절대로
  **정답으로 승격하지 않는다.** 얻는 것은 **갈린 자리를 짚을 수 있게 되는
  것**이지 옳음이 아니다
- **앞 회차 숫자가 소급해서 고쳐지지 않는다.** 가-2·가-3·A·B 의 D 는 옛
  계기로 잰 것이고, 이 회차는 **그것들을 다시 재지 않는다**(C0 만 읽는다)

## 6. 하지 말 것

- 🔴 **`src/` 와 `rubrics/*.yaml` 을 안 고친다** — 제품이 아니라 계기다
- 🔴 **문장을 다시 만들지 않는다.** 같은 JSON 을 읽는다 — 새로 만들면
  B·C 불일치의 표본이 아니게 된다
- 🔴 결과를 보고 **절 쪼개는 규칙을 바꿔 다시 재지 않는다**
- 🔴 **앞 회차의 D 숫자를 새 계기로 다시 재서 갈아 끼우지 않는다.** 옛
  숫자는 옛 계기의 기록으로 남는다 (로드맵 4절에 적어 둔 그대로)
- 🔴 이 회차에서 **영어 혼입·판정 메타언어 누출을 같이 세지 않는다** —

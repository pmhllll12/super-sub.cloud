# 사전 등록 — 처방 가-2: 수준 설명을 **숫자 없이, 조각마다**

미결 23번. **이 파일은 코드에 손대기 전에 커밋한다.** 결과를 보고 아래
기준·문구·정규식을 고치지 않는다. 고치면 이 회차의 합격이 뜻을 잃는다.

## 1. 무엇을 묻는가

프롬프트에 **숫자 없는 수준 설명을 조각마다** 주면
⑴ 루브릭 경계 숫자 베끼기와 ⑵ 방향 오독이 줄어드는가.

## 2. 왜 지금인가

2회차(2026.09.07)가 가-2 를 남기면서 미룬 이유가 *"지도자 검수(미결 2번)에서
수준 문구를 다시 쓸 때 함께 넣는 편이 싸다"* 였다. **2026.09.17 에 검수 없이
가기로 했다**(미결 2번). 더 싼 시점은 안 온다.

## 3. 무엇이 문제인가 — 2026.09.17 판독이 찾은 기전

`build_prompt` 는 세 등급의 `grades[g]` 를 전부 프롬프트에 넣는다. 양방향
구간의 `grades[g]` 는 두 방향을 **한 문자열**에 담는다:

```
1 | 170도 초과(굴곡 부족) 또는 135~150도(과굴곡)
```

측정값이 어느 조각인지는 안 준다. **모델이 고르고, 틀린다** — 64문장 중
양방향에 앉은 14문장에서 5문장이 반대 조각의 말을 썼다.

🔴 **그리고 표본이 반쪽이었다.** `football_evidence.py` 의 `value_in_band` 가
`bands[grade][0]` — **첫 조각만** 뽑는다. 양방향 등급 8곳의 **두 번째 조각은
한 번도 물어본 적이 없다.**

## 4. 무엇을 바꾸는가 (구현 전에 고정)

| | |
|---|---|
| 루브릭 | 항목마다 **`grades_plain`** 추가 — `grades` 를 **숫자 없이** 다시 쓴 것. 양방향 등급은 **조각마다 하나씩**(`titles`·`card_lines` 와 같은 모양) |
| 프롬프트 | `grades[g]` 대신 `grades_plain[g]` 를 쓴다. **이번 판정 등급은 측정값이 앉은 조각의 문장 하나만** 넣는다. 나머지 두 등급은 조각들을 `" 또는 "` 로 이어 넣는다(무엇이 더 낫고 아쉬운지의 맥락) |
| 적재 | 조각 수와 문장 수가 다르면 **`RubricError`** (`titles`·`card_lines` 와 같은 규칙 — 어긋나면 반대로 말한다) |
| 표본 | `value_in_band` 가 **모든 조각**을 뽑는다. 66 → **82문장** |
| 🔴 안 건드리는 것 | `bands` · 가중치 · `grade_for` — **B-6 재실행을 부르지 않는다** |

### C — R2′ 의 정의 (지금 고정한다)

문장의 숫자 토큰 중, **그 항목의 밴드 경계값**(모든 등급의 유한한 `lo`·`hi`)과
같으면서 **준 측정값과는 다른** 것. 측정값과의 비교는 R3 와 같은 허용오차
**0.55** 를 쓴다.

> 왜 새로 만드나 — 기존 R2 는 `a~b` **두 수를 이은 표기**만 본다.
> *"기준 상한 **170도** 미만"* 처럼 **단일 임계값**으로 새면 R2 를 피해
> R3(보고만)로 간다. 🔴 **R2 정규식은 안 고친다** — 그건 앞선 회차의 판정
> 기준이고, 결과를 보고 고치지 않는다는 규칙이 그것에도 걸린다. **더하는 것**이다.

### D — 사람이 읽는다는 뜻

"감점을 칭찬으로 서술했는가"는 문장 **뜻**의 문제라 문자열로 안 갈린다.
🔴 **AI 판독은 정답으로 승격하지 않는다**(`agent/CLAUDE.md`). 그래서
**건수를 합격선으로 쓰지 않고**, 사례를 남겨 사람이 확인하게 한다. 다만
**악화는 판정할 수 있다** — 늘면 불합격이다.

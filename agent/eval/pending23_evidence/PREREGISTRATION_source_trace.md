# 사전 등록 — C: `hip_rotation` **85.8 의 말은 어디서 오는가** (미결 23번)

**코드에 손대기 전에 커밋한다.** 결과를 보고 기준·예측을 고치지 않는다.

## 1. 무엇을 모르는가

B 회차(`RESULTS_other_levels.md`)에서 수준 문구를 **판정 등급 하나만** 남겼다.
그런데 `inside_pass/hip_rotation` **85.8**(= 과회전 조각)은 여전히

> *"인사이드 면이 공에 충분히 **닿지 않아**"*

라고 쓴다 — **덜 열림 방향**의 말이다. 출처로 짚었던 [아쉬움] 수준 문구를
**뺐는데도 같은 말을 한다.** 남은 경로가 셋이다.

지금(B) 프롬프트 전문:

```
평가 항목: 골반 돌리기

항목 취지: 인사이드 면을 공에 대려면 골반이 열려야 한다. 다만 슈팅만큼 크게 돌면 방향 제어를 잃는다.

이번 판정 수준:
- [보통] 골반을 지나치게 많이 돌린다

근거 문장 예시 (수준에 맞는 어투를 그대로 따릅니다):
- [잘함] 골반 회전 범위 24.0도 → "골반 회전 24도로 인사이드 면이 공을 향해 열렸다"
- [보통] 골반 회전 범위 45.0도 → "회전 45도로 골반을 지나치게 많이 돌렸다"
- [아쉬움] 골반 회전 범위 5.0도 → "회전 5도로 골반이 닫혀 발끝으로 밀게 된다"

측정값 (이 숫자와 단위만 신뢰할 것):
- 골반 회전 범위: 85.8도

이번 판정은 [보통]입니다. 골반 회전 범위 85.8도가 그 근거입니다.
```

| | 후보 경로 | 프롬프트의 어디 |
|---|---|---|
| **ㄱ** | **항목 취지** | *"**인사이드 면을 공에 대려면** 골반이 열려야 한다"* |
| **ㄴ** | **옆 등급 앵커** | [잘함] *"**인사이드 면이 공을 향해** 열렸다"* · [아쉬움] *"골반이 **닫혀** 발끝으로 밀게 된다"* |
| **ㄷ** | **모델 자신** | 프롬프트 밖 — 축구 상식 |

🔴 **구조적으로 눈에 띄는 것 하나.** 이 항목의 앵커 사다리는 **값에 대해
단조가 아니다**: 잘함 **24** → 보통 **45** → 아쉬움 **5**. 「좋은 것부터」
늘어놓으면 값이 24↑45↓5 로 오르내린다. 그리고 측정값 **85.8 은 세 앵커 중
어느 것보다도 크다** — 남은 두 옆 등급 앵커가 **둘 다 「덜 열림」 쪽의 말**을
담고 있다. 양방향 구간에서는 이 배치가 예외가 아니라 기본값이다.

## 2. 설계 — **2×2 제거 실험**

🔴 **조사 회차다. `src/` 를 고치지 않는다.** 루브릭은 **데이터**이므로,
`dataclasses.replace` 로 항목의 **사본**을 만들어 `judge_criterion` 에 넘긴다.
제품 프롬프트(`build_prompt`)도 루브릭 파일도 B 그대로다.

| 팔 | 항목 취지 | 옆 등급 앵커 | |
|---|---|---|---|
| **C0** | 있음 | 있음 | B 그대로 — `evidence_other_levels.json` 을 **재사용**한다 |
| **C1** | 🔴 **없음** | 있음 | ㄱ 을 끈다 |
| **C2** | 있음 | 🔴 **없음** | ㄴ 을 끈다 |
| **C3** | 🔴 **없음** | 🔴 **없음** | 남으면 **ㄷ(모델 자신)** 이다 |

- 「옆 등급 앵커 없음」 = **판정 등급·판정 조각의 앵커 하나만** 남긴다
  (가-3 이 이미 고르는 바로 그것). 앵커를 통째로 없애지는 않는다 — 어투
  본보기가 0개인 팔은 이 회차가 재려는 것과 다른 것을 잰다.
- **측정값은 네 팔이 모두 같다.** 채우는 값(`filler`)도 **원본 항목**으로
  구한다 — 앵커를 지운 사본으로 구하면 계기가 팔마다 달라진다.
- 계기는 `football_evidence.py` 의 `FRACTIONS`·`value_in_band`·`filler` 를
  **import 해서** 쓴다. 베껴 쓰지 않는다 — 베끼면 한쪽만 고쳐진다.

🔴 **C2·C3 는 제품에 넣지 않는다.** 1회차에서 앵커를 줄였다가 **잘함 문장
8건 중 4건**이 무너졌다. 이 회차는 **어디서 오는지 알아내는 것**이지 처방이
아니다. 처방은 결과를 보고 **새 사전 등록**으로 연다.

## 3. 무엇을 재는가 — 결과 전에 고정

**주 계측(자동)**: 문장에 **「인사이드 면」** 이라는 어구가 들어가는가.
`inside_pass/hip_rotation` 의 **8문장 전부**(2등급 22.0·28.0 · 1등급 10.4·12.6 ·
1등급 85.8·129.2 · 0등급 2.8·5.2)에 대해 팔마다 센다.

🔴 **여기서 문자열을 세는 것은 정당하다.** 이 회차가 재는 것은 문장의
**뜻**(칭찬인가 지적인가)이 아니라 **특정 어구가 어느 입력에서 전파되는가**다.
뜻은 아래 D 처럼 사람이 읽는다. 23번 본문의 「문자열로 가르려 하지 말 것」은
**뜻**에 대한 규칙이고, 어구 추적에는 해당하지 않는다.

| | 기준 | 합격선 |
|---|---|---|
| **A** | R1 「등급」 낱말 | **0건** — 네 팔 모두 |
| **B** | R2 구간 표기 | **0건** — 네 팔 모두 |
| **C** | R2′ 경계 숫자 누출 | **0건** — 네 팔 모두 |
| **D** | 방향 오독 30문장 판독 | 🔴 **보고만** |
| **E** | 잘함 문장 오독 | 🔴 **보고만** |
| **F** | 밴드값·등급이 C0 과 동일 | **80/80** — 팔마다 |
| **G** | `pytest tests/ -q` | **569 통과** (`src/` 를 안 고치므로 변할 이유가 없다) |

🔴 **D·E 에 합격선을 두지 않는다.** 제거 실험이지 처방이 아니다. 합격선을
두면 「C3 이 제일 낫다」로 읽히고, **그게 1회차에서 밟은 자리다** — 앵커를
줄이면 재는 축 하나는 좋아지고 안 재는 축이 무너진다.

**재현 확인**: C0 을 다시 돌리지 않고 B 의 파일을 쓴다. 대신 `hip_rotation`
**8문장만** 같은 프롬프트로 다시 만들어 그리디가 **같은 문장**을 내는지 본다.
🔴 **다르면 이 회차의 대조가 성립하지 않으므로 중단한다** — 팔 사이의 차이를
디코딩 흔들림과 못 가른다.

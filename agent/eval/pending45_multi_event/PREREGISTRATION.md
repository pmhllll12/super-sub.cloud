# 사전 등록 — 파이프라인이 이벤트를 **여럿 실어 나르게** 한다 (미결 `ho` 45번 4회차)

작성 2026.09.14 · **구현 전에 굳힌다.** 결과를 보고 아래를 고치지 않는다.

## 왜 이 회차인가 — 앞 셋과 **다른 층**이다

1~3회차는 전부 **이벤트를 찾는 쪽**이었다(공-발 거리 · 공 가속 · 공 궤적
연속성). 지금 서 있는 자리는 **공만으로 18편 중 12편(67%)** 이고, 여기서
더 나아가는 길 둘은 **내 판단만으로 못 간다** — 박민호 님의 제품 판단(67%로
열 것인가)과 실서버 사용자 영상 사용 허가다.

**그런데 45번이 적어 둔 「막는 것 셋」 중 ⑴ 이 아직 그대로다.**

| | 지금 | |
|---|---|---|
| ⑴ **임팩트가 하나** | `_peak_frame` 이 `argmax` **하나**. `Phases.impact` 도 int 하나 | 🔴 **제 몫인데 미착수** |
| ⑵ 분석 창 10초 | `ho` 30번, 박민호 판단 대기 | 남의 결정 |
| ⑶ 리포트 1:1 | schema 2.0, 정어진 (A/B/C) | 남의 영역 |

**찾는 것이 완벽해져도 ⑴ 이 그대로면 두 번째 이벤트를 실어 나를 곳이 없다.**
그리고 🔴 **㉳(드리블)이 막힌 이유가 정확히 이것**이다 — 로드맵이
*"파이프라인이 「클립당 임팩트 한 번」을 전제한다 … ㉲ 와 **같은 빈틈**"*
이라고 적어 두었다. **이 회차는 검출 성능과 독립이고, 67% 판단과도 독립이다.**

## 🔴 이 회차가 **하지 않는 것** — 먼저 적는다

| 안 한다 | 왜 |
|---|---|
| **이벤트를 찾는 규칙을 건드리기** | 1~3회차의 영역이다. 이 회차는 **실어 나르는 것**만이다. 둘을 한 회차에 섞으면 어느 쪽이 결과를 냈는지 못 가른다 |
| **리포트 봉투를 바꾸기** | `schema_version` 2.0 은 **정어진 님 합의 전**이다(항목의 A/B/C). 봉투를 먼저 바꾸면 적재·읽기·화면이 배포 뒤 실서버에서만 깨진다(`jin` 27번이 정한 것) |
| **이벤트가 하나일 때 결과를 바꾸기** | 🔴 바뀌면 **B-6 재실행**이고 그때까지의 평가가 전부 무효다. 이 회차의 존재 이유가 「안 바뀐다」이다 |
| **루브릭·임계값·새 상수** | 무변경. 아래 기준 F 가 이것을 센다 |
| **분석 창(`DEFAULT_MAX_SECONDS`) 손대기** | 사용자에게 보이는 값이고 결정 전이다(`ho` 30번). 창이 10초면 두 번째 이벤트가 애초에 창 밖일 수 있는데, **그건 이 회차가 풀 문제가 아니다** |

## 무엇을 한다 — **구간을 받게 한다**

「한 영상에 이벤트 N개」를 **「구간 N개에 지금의 파이프라인을 N번」**으로
바꾼다. 새 경로를 만들지 않고 **지금 경로에 창을 하나 얹는다.**

```python
def segment_phases(kps, swing, limb="leg", event="extension_peak",
                   window: tuple[int, int] | None = None) -> Phases
def extract_features(..., window: tuple[int, int] | None = None)
```

| `window` | 하는 일 |
|---|---|
| `None` (기본) | 🔴 **지금과 정확히 같은 코드 경로.** 한 줄도 안 달라진다 |
| `(a, b)` | `usable` 을 `[a, b)` 로 제한한 뒤 **지금과 같은 규칙**으로 임팩트·구간을 찾는다 |

🔴 **`argmax` 를 「상위 N개 고르기」로 바꾸지 않는다.** 그러면 「몇 개인가」와
「어디인가」가 한 함수에 섞이고, 새 상수(`N`·`최소 간격`)가 붙는다. 구간을
누가 정하는지는 **바깥**(이벤트 검출)의 일로 남긴다 — 그쪽은 1~3회차가 이미
따로 재고 있다.

**프레임 인덱스는 절대값 그대로 둔다.** `Phases.impact` 가 클립 기준 프레임이라
`_ball_at(ball, t)`·`timebase` 초 환산이 그대로 맞는다. 구간 안에서 0부터
다시 세면 그 둘이 조용히 틀린다.

## 사전 등록된 판정 기준

**표본**: `eval/phaseA/cache_target30/` 의 **39클립**(저장소 사본, 🔴 **GPU
불필요**). 설정 셋 — `(leg, extension_peak)` · `(arm, extension_peak)` ·
`(arm, distal_apex)`. **최대 117개 산출.**

🔴 **표본이 야구다** — 축구 단일 종목 전환(`ho` 39번) 뒤라 제품 표본이
아니다. 그래도 이 회차가 재는 성질(**같은 입력에 같은 출력**)은 **종목과
무관**하고, 축구 클립은 캐시가 없어 GPU 가 필요하다. 🔴 **이것으로 검출
성능을 말하지 않는다** — 말할 수 있는 것은 「안 바뀌었다」뿐이다.

| 기준 | 내용 | 합격선 |
|---|---|---|
| **A** | `window=None` 에서 `extract_features` 산출이 **비트 동일** (변경 전 값을 먼저 떠서 비교) | 🔴 **불일치 0** |
| **B** | `window=None` 에서 `Phases`(takeback·impact·follow_through) 동일 | 불일치 0 |
| **C** | 구간을 주면 `impact` 가 **그 구간 안**에 있다 | 위반 0 |
| **D** | 구간이 좁아 구간 분할이 성립 안 하면 **지금과 같은 예외**(`InsufficientQuality`) | 🔴 조용히 빈 결과를 내면 불합격 |
| **E** | `cd agent && uv run pytest -q` | **410 이상** 통과 |
| **F** | 🔴 **새 상수 0개** · `rubrics/*.yaml` 무변경 | 하나라도 늘면 불합격 |
| **G** | 🔴 **짝 기준 — 아래** | 90% 이상 |

### 🔴 G 를 두는 이유 — A 는 **아무것도 안 하면 통과한다**

A·B 는 「안 바뀌었다」를 재므로 **코드를 한 줄도 안 고쳐도 만점**이다. 이
저장소가 세 번 덴 형태(커버리지 100%가 좋은 신호가 아니다)와 같은 계열이라
**짝 기준을 함께 박는다** — 「그래서 실제로 여럿을 실어 나르는가」.

**사전 예측** (결과를 보기 전에 적는다): 각 클립의 유효 구간을 **반으로**
잘라 두 구간을 주면,

- 전체 `argmax` 는 **둘 중 정확히 한 구간**에 들어 있다
- **그 구간의 임팩트 = 전체 임팩트**
- **다른 구간의 임팩트 ≠ 전체 임팩트** (그 구간 안의 다른 최대값)

**두 구간이 다 경계 검사를 통과한 클립 중 90% 이상**에서 이 셋이 성립해야
한다. 🔴 **하나라도 「두 구간이 같은 프레임을 냈다」가 나오면 창이 실제로
안 걸린 것**이고, A 가 만점이어도 불합격이다.

## 🔴 미리 적어 두는 함정

- **`follow_through` 가 구간 끝에서 잘린다.** 창을 걸면
  `swing_hip_flexion_after_impact_deg` 가 구간 안에서만 최대를 찾는다 —
  **의도한 것이다**(두 번째 이벤트의 마무리가 첫 이벤트 구간까지 끌려가면 안
  된다). 🔴 그런데 이것이 **`window=None` 에서는 절대 안 일어나야** 한다.
  A 가 그것을 잡는다
- **경계 검사(`impact - first < 2`)가 좁은 구간에서 자주 걸린다.** 그게 맞는
  동작이다 — 억지로 통과시키려고 `2` 를 낮추면 **그 순간 새 상수**이고 F
  불합격이다. **몇 건이 걸렸는지를 보고**하고 넘어간다
- 🔴 **「구간을 나눈다」를 이 회차가 정하지 않는다.** G 의 반 나누기는 **계기를
  시험하려고 쓰는 것**이지 제품 규칙이 아니다. 결과에 그렇게 적는다
- 🔴 **계기 검사 셋을 다 본다** (로드맵 5절): 이 **양**이 내가 묻는 것인가 ·
  이 **표본**이 내가 묻는 대상인가 · **내 앞 단계가 맞게 돌고 있는가**.
  세 번째는 1회차가 놓쳐 회차 하나를 날린 것이다 — 여기서는 「캐시된
  키포인트가 실제로 읽히는가」를 산출 개수로 확인한다(117 예상)

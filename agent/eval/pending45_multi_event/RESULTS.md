## 1. 무엇을 고쳤나 — **31줄, 그중 대부분이 주석이다**

`src/supersub_agent/features.py` 한 파일.

```python
def segment_phases(kps, swing, limb="leg", event="extension_peak",
                   window: tuple[int, int] | None = None) -> Phases
def extract_features(..., window: tuple[int, int] | None = None)
```

실제 로직은 **다섯 줄**이다 — 구간 밖을 「검출 실패」와 **같게** 다룬다.

```python
if window is not None:
    outside = np.ones_like(usable)
    outside[max(0, window[0]):max(0, window[1])] = False
    usable = usable & ~outside
    if not usable.any():
        raise InsufficientQuality(...)
```

🔴 **이 형태를 고른 것이 이 회차의 설계다.** 임팩트 탐색·경계 검사·구간 분할을
**한 줄도 안 고쳤다** — 그것들이 이미 `usable` 위에서만 돌기 때문이다. 그래서
`window=None` 의 비트 동일이 **검사로 확인되는 성질이 아니라 구조적으로
보장된다**(A 가 0/117 인 이유).

### 🔴 `argmax` 를 「상위 N개」로 바꾸지 않았다

사전 등록에 적은 대로다. 그렇게 했으면 **「몇 개인가」와 「어디인가」가 한
함수에 섞이고** 개수·최소 간격 같은 상수가 여기 붙었을 것이다. 지금은
**바깥이 구간을 정하고 안은 하나씩 받는다** — 1~3회차가 재고 있는 검출 쪽과
**층이 갈린다.**

### F — 새 상수 0개

늘어난 리터럴은 `max(0, window[0])` 의 **`0`** 뿐이고 이것은 **손잡이가 아니라
경계 클램프**다. 돌릴 수 있는 값이 하나도 안 생겼다. `rubrics/*.yaml` 무변경.

## 2. 🔴 G(짝 기준)가 이 회차의 값이다 — A 는 **아무것도 안 해도 만점**이다

A·B 는 「안 바뀌었다」를 재므로 **코드를 한 줄도 안 고치면 100%** 다. 그래서
사전 등록에 짝 기준을 박아 두었고, **결과를 보기 전에 예측을 적었다**:

> 유효 구간을 반으로 자르면 전체 `argmax` 는 **둘 중 정확히 한 구간**에 있고,
> 그 구간의 임팩트 = 전체 임팩트, **다른 구간은 다른 프레임**을 낸다.

**92/92 = 100%.** 예측대로다. 🔴 **하나라도 「두 구간이 같은 프레임」이 나왔으면
창이 실제로 안 걸린 것**이고, A 가 만점이어도 불합격이었다.

🔴 **반 나누기는 제품 규칙이 아니다** — 창이 걸리는지 보려고 쓴 **계기**다.
구간을 실제로 어떻게 나눌지는 이 회차가 정하지 않았다(아래 4절).

## 3. 🔴 D 의 22건이 그냥 통과가 아니다 — **다음 자리를 가리킨다**

좁은 구간에서 경계 검사(`impact - first < 2 or last - impact < 2`)가 **22번**
걸렸다. **맞는 동작이다** — 억지로 통과시키려고 `2` 를 낮추면 그 순간 새
상수이고 F 불합격이다.

**그런데 크기를 보아야 한다.** 두 창이 다 성립한 것이 **92** 쌍이고 걸린 창이
**22** 개다. 클립을 **반**으로만 잘랐는데도 그렇다 — 🔴 **이벤트가 촘촘하면
구간이 짧아지고, 짧아지면 지금 규칙으로는 구간 분할 자체가 성립하지 않는다.**

㉳(드리블)이 **정확히 그런 동작**이다. 반복 터치 사이 간격이 반 클립일 리
없다. **이 회차가 ㉳ 를 연 것은 맞지만 「열렸다」가 「된다」는 아니다** —
간격이 짧을 때 무엇을 할지는 다음 회차의 질문이고, 지금 추측으로 답하지 않는다.

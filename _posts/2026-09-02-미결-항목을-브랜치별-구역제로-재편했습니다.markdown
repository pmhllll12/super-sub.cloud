# 미결 항목을 브랜치별 구역제로 재편했습니다

9월 1일에 `CLAUDE.md`에 정한 구역제를 오늘 실제 파일에 적용했습니다. 항목이
`## ho (정상호)` / `## jin (정어진)` 두 구역으로 나뉘고, 각 항목은 `###`로
한 단계 내려갔습니다.

**팀 파일을 제가 고친 것이라 이견이 있으면 말씀해 주세요.** 되돌리거나 고치겠습니다.

## 미루기로 했던 것을 왜 오늘 했나

규칙만 정하고 재편은 "다음 병합 때 어차피 충돌을 손으로 푸니 그 김에"로 미뤄
뒀습니다. 그런데 오늘 `main`을 가져와 보니 **충돌이 하나도 없었습니다.**
정상호 님이 9\~12번을, 제가 13\~16번을 써서 겹치는 줄이 없었기 때문입니다.

구역제가 노린 결과가 규칙을 적기도 전에 나온 셈입니다. 그래서 재편이 충돌
해소의 곁다리가 아니라 독립 작업이 됐고, 미룰 이유가 사라졌습니다. 항목이
늘수록 헤딩을 내리는 범위만 커집니다.

## 정상호 님 항목의 번호는 그대로 뒀습니다

1\~12번은 번호가 하나도 안 바뀝니다. 그 항목들이 서로를 번호로 가리키는 곳이
14군데이고, 특히 **9·10·11번의 기한이 전부 "미결 7번 수정 착수 전"** 이라
밀면 그쪽이 다 깨집니다.

제 13\~16번만 `jin` 구역 1\~4번으로 다시 매겼습니다. 저장소 전체에서 그 번호를
가리키는 곳이 0건이라 안전했습니다 — 다른 문서에서는 번호가 아니라 제목으로
쓰기로 한 규칙이 여기서 값을 했습니다.

**본문은 헤딩 레벨 말고 한 글자도 안 바꿨습니다.** 사이트 앵커(딥링크)도
제목에서 만들어지므로 그대로 삽니다.

## 🔴 병합하실 때 — 구역 구조를 남겨 주세요

`main`에 합칠 때 다른 브랜치가 아직 평면 목록(`## 1.` `## 2.` …)이면 그 자리에서
충돌합니다. 그때 **평면으로 되돌리지 말아 주세요.** 되돌아가면 다음 사람이 또
파일 끝에 붙이게 되고, 그게 이 규칙이 막으려던 충돌입니다.

| | |
|---|---|
| 만족해야 할 것 | 모든 항목이 구역 아래 `###`로 있을 것 |
| 확인 | `grep -n '^## [0-9]' jekyll/pages/pending.markdown` → **결과가 없어야** 합니다 |
| 하지 말 것 | 평면으로 되돌리기, **남의 구역 번호 다시 매기기** |

이 확인 명령은 재편 전 파일로 돌려보면 16건이 걸리고 지금은 0건입니다 —
**판별이 되는 검사인지 양쪽으로 돌려 보고 골랐습니다.** 구역 수를 세는 방식도
있었는데, 그건 구역이 늘면 기대값이 같이 바뀌어서 쓰지 않았습니다.

규칙 본문은 `CLAUDE.md` 「미결 항목」 → 「병합할 때」에 있고, 미결 항목
`jin` 5번에 요약과 함께 올려 뒀습니다.

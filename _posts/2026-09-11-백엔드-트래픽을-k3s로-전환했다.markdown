운영 백엔드가 3일 넘게 옛 커밋에 멈춰 있었던 것을 발견하고 정리했습니다. 자세한
경위·확인 절차는 [미결 항목](/pending/) `jin` 31·32번, `min` 14번에 있습니다.

## 무슨 일이 있었나

라이브 재점검에서 운영 systemd 백엔드가 최신 코드보다 커밋 12개·마이그레이션
8개 뒤처져 있는 걸 발견했습니다. 원인은 pgvector 확장이 운영 호스트에
OS 레벨로 설치돼 있지 않아 k3s 쪽 자동 배포가 계속 실패하고 있었던 것입니다.

## 무엇을 했나

1. 운영 호스트 PostgreSQL에 pgvector 설치 + 확장 생성 — 이걸로 밀려 있던
   마이그레이션이 자동으로 전부 적용됨
2. k3s 파드가 정상 기동하는 것 확인
3. nginx가 옛 systemd(:8000) 대신 k3s 파드(:8080)를 보도록 전환, 스모크 테스트
   통과 확인
4. 옛 systemd 서비스는 **disable만 하고 지우지 않음** — 문제 생기면 즉시 되돌릴 수 있게

## 다음에 할 것

지금 도는 k3s 배포 설정이 서버에만 있고 저장소에 커밋돼 있지 않다는 걸
확인 중에 발견했습니다(`jin` 32번). 서비스에는 지장 없지만, 서버가
재구성되면 그 설정도 같이 사라지는 상태라 다음 배포 작업 때 저장소로
옮겨 담기로 했습니다.

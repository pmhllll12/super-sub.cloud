## 분석 워커 — 백엔드 쪽은 서버에서 돕니다

미결 `ho` 17번(S3 에 영상이 올라와도 분석이 안 돈다)의 절반입니다.

```
POST /internal/analysis-jobs/claim      가장 오래된 queued → running
PATCH /internal/analysis-jobs/{id}      succeeded | failed
```

**워커가 가져갑니다(pull).** GPU 인스턴스가 자동 종료되므로 밀어 주는 방식은
대상이 꺼져 있으면 실패하고, 루브릭을 고르려면 종목이 필요한데 그건 S3 가 아니라
DB 에 있습니다.

**멈춘 작업은 자동 회수됩니다** — 처음 멈추면 `queued`, 또 멈추면 `failed`.
한 번만 되살리는 이유는 **워커를 죽이는 클립**(4K 에서 host RAM 이 터지는 것,
미결 `ho` 9번)이 큐를 영원히 돌게 되기 때문입니다.

**정상호 님께 폴링 루프를 넘겼습니다** — 미결 `jin` 18번, 인터페이스는
`fastapi/docs/worker-interface.md` 하나에 모아 두었습니다.

## 오늘 배운 것

**변이 검사가 제 주석이 거짓인 것을 잡았습니다.** 회수 코드에 "두 UPDATE 의
순서를 바꾸면 깨진다"고 적어 두고 뒤집어 봤더니 전부 통과했습니다 — 되돌리는 쪽이
`status` 를 바꿔서 애초에 겹치지 않았습니다. **없는 위험을 막고 있었습니다.**

**규칙은 규칙이 있는 층에서 검사해야 합니다.** 카드 한 줄의 길이 제한을
자르기로 바꾸는 변이가 계약 테스트를 전부 통과했습니다 — Pydantic 이 앞단에서
막아 도메인 규칙까지 요청이 안 갔습니다.

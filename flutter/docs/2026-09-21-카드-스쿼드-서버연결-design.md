# 앱의 카드·스쿼드를 서버에 붙인다 — 설계

> **상태:** 설계 · 2026-09-21 · **담당:** 백성검 (프론트·웹/앱) · 브랜치 `paik`
> **앞 문서:** `www/docs/2026-08-31-앱-이식-지침.md`(지킬 것 여섯) ·
> `flutter/CLAUDE.md`(리포지토리 뼈대) · `fastapi/docs/api-contract.md`(계약의 정본)

## 0. 왜 — 앱은 지금 자기 데이터를 모른다

앱은 2026-09-15 이후로 멈춰 있고 그사이 웹은 1.11~1.18까지 나갔다. 화면(스쿼드
판·선수 카드)은 이미 옮겨져 있는데 **데이터가 하나도 안 붙어 있다.**

| 지금 | 그래서 |
|---|---|
| 스쿼드 판이 「내 카드 한 장 + 빈 자리」를 **붙박이로** 그린다 | 웹에서 만든 팀·팀원이 앱엔 안 뜬다 |
| 붓자국 씨앗이 `user.id` 다 (웹은 `card.public_slug`) | 🔴 **같은 카드가 웹과 앱에서 다른 무늬다** |
| 카드 꾸미기(`style`)를 아예 안 읽는다 | 웹에서 꾸민 카드가 앱에선 기본 모습이다 |
| `SquadSlot(…, mine: true)` 로 내 자리가 포메이션에 **박혀 있다** | 웹이 2026-09-16에 뒤집은 **옛 방식**이다(아래 2-2) |

## 1. 두 단계로 자른다

**1단계(배선) → 실기기 확인 → 2단계(꾸미기 렌더).** 한 번에 하지 않는 이유는
1단계가 틀리면 2단계 렌더를 아무리 다듬어도 뜻이 없기 때문이다. 1단계만 끝나도
「웹에서 만든 팀이 앱에 뜬다」가 눈에 보인다.

## 2. 1단계 — 데이터 계층

`flutter/CLAUDE.md` 의 뼈대를 그대로 따른다: **화면은 인터페이스만 알고, 구현체
교체는 `*_providers.dart` 한 줄**이다. 🔴 화면·컨트롤러에서 `Mock…()` 을 직접
만들지 않는다.

### 2-1. 새로 만드는 것

```
lib/features/card/data/models/player_card.dart    PlayerCard · CardStyle · CardTitle
                     card_repository.dart          인터페이스
                     card_repository_mock.dart
                     card_repository_api.dart
                     card_providers.dart           🔴 교체 지점
lib/features/team/data/models/squad.dart          Squad · SquadMember
                     squad_repository.dart  … _mock  … _api
                     squad_providers.dart          🔴 교체 지점 (sport 와 따로 둔다)
lib/features/team/seats_from_squad.dart           자리 배치 순수 함수 (2-2)
test/contract/card_repository_contract.dart       mock·api 양쪽에 물린다
test/contract/squad_repository_contract.dart
```

인터페이스가 가지는 것:

| | |
|---|---|
| `CardRepository` | `myCard()` — 🔴 **404 `CARD_NOT_FOUND` 는 예외가 아니라 `null`** 이다(카드는 가입만으로 안 생긴다) · `createMyCard()`(`POST`, 멱등) · `cardBySlug(slug)`(인증 불필요) |
| `SquadRepository` | `squadOf(teamId)` — **404 `SQUAD_NOT_FOUND` 도 `null`**(「안 만든 것」과 「비어 있는 것」은 다르다) |

🔴 **`GET /me` 가 이미 `teams[]` 를 준다.** 지금 `_fetchMe()` 가 그걸 버리고 있을
뿐이라 **내 팀을 얻을 새 경로가 필요 없다.** `AppUser` 에 `List<TeamMembership>`
(`teamId`·`name`·`region`·`sportCode`·`role`·`joinedAt`)을 싣는다. `left_at` 이 널인
행만 오므로 나간 팀은 애초에 안 온다.

### 2-2. 자리 배치는 순수 함수 하나로 — 웹 로직을 **재해석하지 않는다**

웹 `SquadPanel.tsx` 의 `seatsFromSquad` 를 `lib/features/team/seats_from_squad.dart`
로 옮긴다. 세 단계이고 **순서가 곧 규칙**이다:

| 단계 | 무엇 |
|---|---|
| 0 | **내 등재를 먼저 집는다**(`card_public_slug == 내 슬러그`). 칸이 있으면 그 칸에 `mine`. 🔴 이름표(`mates`)에는 **안** 넣는다 — 넣으면 내 카드 대신 이름표가 선다 |
| 1 | **칸(`grid_col`·`grid_row`)이 저장된 등재** — 그 칸이 곧 자리다. 찬 칸이면 건너뛴다. 🔴 그 칸에 있는 자리를 **먼저** 쓰고, 없을 때만 남는 자리를 옮겨 온다(아무 자리나 끌어오면 카드가 겹쳐 사라진다) |
| 2 | **칸이 없는 등재**는 포메이션 기본 자리에 **포지션으로** 맞춰 앉힌다. 🔴 **여기서 `me` 를 빼면 안 된다** — 빼면 「수락해서 들어온 사람 전부가 자기 판에서 자기를 못 본다」(2026-09-18 웹이 데인 것) |

- 포지션은 **저장된 `position_code`** 를 쓴다. 손으로 정했을 수 있어 행에서
  역산하면 안 된다
- 🔴 2단계에서 **저장하지 않는다.** 판을 여는 것만으로 서버가 바뀌면 안 된다
- `formation` 은 서버 값으로 시작하고 **모르는 값·`null` 이면 5:5**(2026-09-18
  이전 스쿼드가 `null` 이다)

🔴 **그래서 `SquadSlot(…, mine: true)` 를 걷는다.** 내 자리는 고정이 아니라
**등재했을 때만, 내가 앉힌 칸에** 선다 — 안 앉히면 판에 없다(「나는 안 뛴다」가
그렇게 표현된다).

### 2-3. 팀원 카드는 **보일 때 한 장씩** 받는다

스쿼드 응답은 `card_public_slug`·`nickname`·`position_*` 만 준다. 그 사람의 카드를
그리려면 `GET /cards/{slug}` 를 따로 불러야 한다(웹 `SquadPanel` 1008줄과 같다).

- 🔴 **목록을 그릴 때 줄마다 부르지 않는다.** 받은 것은 슬러그로 캐시하고, 같은
  슬러그를 두 번 받지 않는다
- 응답이 카드 모양이 아니면(`public_slug` 가 문자열이 아니면) **버린다** — 없는
  값을 읽다가 카드 자리가 통째로 깨진다

### 2-4. `accepted_at` — 계약 문서에 없는 값

웹은 `SquadMember.accepted_at` 을 읽어 「오기로 했는가」를 가른다. 그런데 **계약
3-7절에는 그 필드가 없다**(계약 60으로 들어왔는데 문서 반영이 덜 됐다).

앱도 웹과 같게 둔다 — **안 오면 수락된 것으로 본다.** 그 시절엔 팀원만 앉을 수
있어 앉은 것이 곧 온 것이었다. 새 응답에서 비어 있으면 그때는 정말 대기중이다.
→ 정어진에게 **문서 보강**을 미결 항목으로 올린다(코드 변경 요청이 아니다).

## 3. 2단계 — 카드 꾸미기(`style`) 렌더

### 3-1. 카드 기하 — 모든 `%` 의 기준

| | |
|---|---|
| 기준 폭 | **380**, 비율 **3 : 4.1** → 높이 **519.33** |
| 축소 | 380으로 그린 뒤 통째로 줄인다(`FittedBox`) — 앱이 **이미** 그렇게 한다 |
| 레이어 | 자국 → 사진/인물 → 머리글·별명 |

🔴 **`text_*`·`brush_y` 의 % 는 이 380×519.33 박스 기준이다.**

### 3-2. 필드별 사양

| 필드 | 무엇 | 단위·기준 | 기본 |
|---|---|---|---|
| `bg` | 카드 바탕 | 색 | `#91ea92` |
| `logo` | 워드마크 **색만** | 색 | 없으면 `text_color` 로 떨어진다 |
| `text_color` | 🔴 **별명 + 획(stroke) + 머리글(70%) + (logo 없을 때)워드마크 + 기본 붓자국**을 한꺼번에 | 색 | `#0b0b0b` |
| `text_x` / `text_y` | 별명의 **중심** 좌표 | 폭 380 / 높이 519.33 대비 % | 50 / 34 |
| `brush` | 자국 종류 번호 | 정수 | 0 |
| `brush_color` | 자국 색 | 색 | 없으면 `text_color` |
| `brush_scale` | 자국 배율 | 배수, 원점 **center** | 1 |
| `brush_x` / `brush_y` | 자국 이동 | 카드 폭/높이 대비 % | 0 |
| `photo_scale` | 사진 배율 | 배수, 원점 **center bottom** | 1 |
| `photo_x` / `photo_y` | 사진 이동 | **그림 칸** 크기 대비 % | 0 |
| `mode` | `cutout` / `full` | | `cutout` |
| `photo_key` | 저장용 — **그리기에 안 쓴다** | | `null` |

🔴 **변환 순서는 translate → scale 이고, translate 의 %는 배율에 안 곱해진다.**
Flutter 에서 `Transform` 을 겹칠 때 이 순서를 뒤집으면 자국이 엉뚱한 데로 간다.

🔴 **`text_color` 를 자리마다 따로 칠하지 않는다.** 한 값이 다섯 곳을 움직이므로
따로 칠하면 반드시 빠지는 곳이 생긴다.

### 3-3. 별명 — 「비웠다」와 「안 정했다」를 `style` 로 가른다

```dart
String aliasOf(PlayerCard c) => c.tagline ?? (c.style != null ? '' : 'THREE LUNGS');
```

| `tagline` | `style` | 결과 |
|---|---|---|
| 문자열(빈 것 포함) | — | 그대로 |
| `null` | 있음 | **일부러 지운 것** → 글자를 **아예 그리지 않는다**(빈 자리가 남으면 인물이 밀린다) |
| `null` | 없음 | 한 번도 안 꾸민 카드 → `THREE LUNGS` |

서버는 `null` 과 `"   "` 를 똑같이 다루므로 `tagline` 만으로는 못 가른다. `style` 이
있다는 것은 **저장을 한 번 거쳤다**는 뜻이고, 그때 글자 칸에는 카드에 보이던 값이
들어 있었다 — 그래서 비어 있으면 지운 것이다.

- `style` **없으면** 흐름 배치(위에서 `margin-top: 52`), **있으면** 절대 배치
  (`text_x`·`text_y` 중심, `max-width: 86%`)
- 글자 크기는 380 폭에서 **52px 고정**. 획은 stroke Paint 로 한 번, fill 로 한 번
  겹쳐 그린다(앱이 이미 그 방식이다)

### 3-4. 자국 — 번호는 **영구 계약**이다

| `brush` | 무엇 |
|---|---|
| 0 | **절차적 붓자국**(`player_card_brush.dart` — 이미 있다) |
| 1 | 없음 — 아무것도 안 그린다 |
| 2 ~ 18 | `marks/01.png` ~ `marks/17.png` — 🔴 **파일 번호 = `brush − 1`**, 두 자리 |
| 그 밖 | 아무것도 안 그린다(저장된 값이 목록보다 클 수 있다) |

- 🔴 **번호를 밀지 않는다.** 배열에서 항목을 빼면 그 뒤 번호가 당겨져 **남의 카드가
  말없이 다른 그림이 된다.** 거둘 때는 자리를 남기고 **고르는 칸에서만** 숨긴다
  (웹 `HIDDEN_MARKS = {7, 8}` — 앱도 같은 값을 숨긴다)
- 🔴 **PNG 는 그림이 아니라 알파 마스크다**(8-bit gray+alpha). 반드시
  `brush_color` 로 칠한다 — `Image.asset(color: …, colorBlendMode: BlendMode.srcIn,
  fit: BoxFit.contain)`, 가운데 정렬. **안 자르고 안 늘인다**
- `mode == 'full'` 이고 `brush == 0` 이면 **아무것도 안 그린다**(사진 위의 기본
  검은 자국은 더럽다). 사람이 **고른** 자국(2 이상)은 full 에서도 그린다
- 절차적 붓자국은 `viewBox 100×140` 을 **cover·가운데**로(380 폭에서 배율 3.8,
  위아래 각 6.3px 잘림). 씨앗은 **`public_slug`**

### 3-5. 사진 / 기본 인물

- 🔴 **그릴 주소는 `photo_key` 가 아니라 응답의 `photo_url`**(사전 서명, 만료 있다)
- 🔴 **`grayscale(1) contrast(1.06)`** 를 빠뜨리지 않는다 — 컬러로 나오면 다른
  카드다. 앱에 이미 같은 `ColorFilter.matrix` 가 있다
- 칸: 좌우 **16%** 안쪽, `top: 50%`, `bottom: 0`, `cover`, `top center`
- 변환은 **칸이 아니라 그림에만** 건다. 칸에 걸면 클립 범위까지 움직여 카드 밖으로
  넘친다
- **사진 없음 + cutout**: 칸이 좌우 **−25%**(폭 150%), `top: 38%`, **`contain` +
  `center bottom`** — 자르지 않고 카드 바닥에 앉힌다. 넘친 팔 끝은 카드가 자른다

### 3-6. 에셋 — 앱에 없는 것 둘

| 무엇 | 왜 |
|---|---|
| `marks/01~17.png` (17장, 약 1.14MiB) | 자국 그림. 🔴 **PNG 를 손으로 고치지 않는다** — `www/scripts/bake-marks.py` 가 다시 구우면 덮인다 |
| `player_default.webp` | 🔴 앱의 `player_cutout.png` 는 웹이 1.18에 **교체하기 전의 옛 인물**이다(워터마크가 남아 있고 얼굴 자리가 다르다). 안 바꾸면 카드 얼굴이 웹과 다르다 |

`pubspec.yaml` 에 등록한다. 웹에서 **파일을 그대로** 가져오고 다시 굽지 않는다.

## 4. 🔴 하지 말 것

- 웹 `seatsFromSquad` 의 3단계를 **재해석하지 않는다.** 단계마다 「왜 그런가」가
  실제 사고에서 나왔고, 줄이면 그 사고가 돌아온다
- **화면에서 `useMockProvider` 를 읽어 분기하지 않는다.** 분기가 화면에 새면
  「provider 한 줄 교체」가 깨진다
- **Mock 을 즉시 성공하게 만들지 않는다.** 지연·실패·빈 목록을 흉내내야 로딩·오류
  화면을 실제로 만들게 된다
- **카드에 수치를 그리지 않는다**(부록 D.5) — 점수·등급·진행률. 웹은
  `PlayerCardView.test.tsx` 가 지키고 있고, 앱도 위젯 테스트로 **같이 옮겨야**
  그 방어가 유지된다
- 붓자국 난수를 건드리지 않는다. `player_card_brush_test.dart` 가 웹에서 뽑은 값과
  대조한다

## 5. 열린 것 둘 — 미결 항목으로 올린다

1. **`mode: 'full'` 의 폭.** 웹 주석은 「카드 전체를 덮는다」인데 실제 CSS 는 좌우
   16%가 안 풀려 **폭의 68% 띠**로 그려진다. 버그로 보이지만 코드만으로는 판정할 수
   없다. **이번엔 웹과 픽셀 동일(68%)로 옮기고**, 웹을 고칠 때 앱도 같이 고친다
2. **`accepted_at` 이 계약 문서에 없다**(2-4). 정어진에게 문서 보강 요청

## 7. 이번 범위 밖

빈 자리(+) 시트(AI 추천·지인 찾기) · 카드 끌어 옮기기·빼기 · **카드 꾸미기 편집
화면** · 팀 매칭 한 줄 · 받은 초대 · 알림함. 이식 지침 §4 의 「알려진 재설계 1건」
(오른쪽으로 펼치는 추천 판 → 바텀시트)은 빈 자리 시트를 할 때 함께 푼다.

# 앱에 「내 영상」을 붙인다 — 설계

> **상태:** 설계 · 2026-09-22 · **담당:** 백성검 (프론트·웹/앱) · 브랜치 `paik`
> **앞 문서:** `www/docs/2026-08-31-앱-이식-지침.md`(지킬 것 여섯) ·
> `flutter/CLAUDE.md`(리포지토리 뼈대) · `fastapi/docs/api-contract.md` 3-1·3-6절 ·
> **옮겨 오는 원본** `www/src/app/(app)/me/MyVideos.tsx`(1,038줄) ·
> `www/src/components/analysis/ReportView.tsx`

## 0. 왜 — 앱에는 영상 흐름이 **하나도** 없다

`flutter/lib/features/video/` 에 있는 것은 목업 채팅 판뿐이고, `/videos` 화면의
「바로 찍기」·「앨범에서」는 둘 다 `준비 중입니다` 다. 프로필 화면 머리말도
「⚠️ 아직 안 옮긴 것: 영상 칸」이라고 적어 두었다.

웹에는 이것이 `/me` 의 **오른쪽 칸**으로 다 있다 — 두 갈래 탭 · 플레이어 ·
넘기기 · 스트립 · 업로드 · 삭제 · 전체 공개 · 대표 영상 · 분석 리포트.

## 1. 자리 — 프로필의 요약 블록 + 전용 화면

웹은 좌우 두 단인데 **폰에는 옆으로 펼 자리가 없다**(이식 지침 §2-2).

```
[프로필]                          [내 영상 화면]
 ┌ 내 선수 카드 ─────┐             (분석영상)(업로드영상)  [⬆ 업로드]
 ┌ 소속 ───────────┐             ┌────────────────┐
 ┌ 내 영상 ─────────┐   ──탭──▶   │    ▶ 플레이어     │
 │ [대표] 분석 3·업로드 5 ▸│         └────────────────┘
 └─────────────────┘              🗑   ◀ 2/5 ▶   ★ 공개
 ┌ 정보 ───────────┐              [1][2][3][4][5]  ← 스트립
 ┌ 내 경기 ─────────┐               「분석 리포트 보기」
```

프로필 블록은 **요약만** 진다 — 대표 영상 썸네일 · 갈래별 편수. 전용 화면은
카드 꾸미기(`CardEditorScreen`)와 같이 `Navigator.push` 로 민다.

## 2. 데이터 계층 — 네 번째 교체 지점

`flutter/CLAUDE.md` 의 뼈대 그대로. **화면은 인터페이스만 알고, 교체는
`video_providers.dart` 한 줄**이다.

```
lib/features/video/data/
  models/my_video.dart             MyVideo — 계약 `GET /videos` 한 줄
  models/video_report.dart         VideoReport · ReportResult — 화면이 쓰는 모양
  video_repository.dart            인터페이스
  video_repository_mock.dart       일부러 느리고 일부러 실패한다
  video_repository_api.dart
  video_providers.dart             🔴 교체 지점 (네 번째 — auth·chat·sport 다음)
lib/core/network/presigned_upload.dart   S3 직접 PUT (카드 사진도 이걸 쓴다)
lib/features/video/presentation/
  my_videos_controller.dart        목록의 정본 · 낙관적 갱신 없음
  screens/my_videos_screen.dart
  screens/report_screen.dart       리포트 전용 화면
  widgets/report_view.dart         레이더 포함
test/contract/video_repository_contract.dart      mock·api 양쪽에 물린다
```

### 2-1. 인터페이스가 가지는 것

| | |
|---|---|
| `myVideos()` | `GET /videos`. 최근 것이 앞 |
| `playbackUrl(id)` | `GET /videos/{id}/playback-url`. 🔴 **404 는 `null`** — 비공개 남의 클립과 없는 클립을 서버가 같게 답한다. 만료값(`expires_in` 900)이라 **캐시하지 않는다** |
| `uploadClip({file, meta, analyze})` | 계약 3-6절 **세 단계를 한 덩어리로.** 웹이 `lib/uploadClip.ts` 로 묶은 것과 같은 판단 — 두 벌로 두면 계약이 바뀔 때 한쪽만 고쳐진다 |
| `patchVideo(id, {isPublic, title, description, isFeatured})` | 🔴 **보낸 것만 바뀐다.** 응답이 바뀐 한 줄이다 |
| `deleteVideo(id)` | `204`. 되돌릴 수 없다 |
| `report(id)` | 🔴 **예외가 아니라 갈래로 돌려준다** — 아래 2-2 |

### 2-2. 🔴 `report` 만 `ReportResult` 로 돌려준다

계약이 **404 를 세 뜻으로** 쓴다.

| code | 뜻 | 다시 물어보면 |
|---|---|---|
| `REPORT_NOT_READY` | 분석 중 | **바뀔 수 있다** |
| `ANALYSIS_FAILED` | 분석이 실패로 끝났다 | **절대 안 바뀐다.** `message` 가 곧 사유다 |
| `VIDEO_NOT_FOUND` | 없거나 남의 영상 | — |

앱의 「404 는 `null`」 규칙으로 뭉개면 **영영 안 될 실패가 곧 될 것처럼** 보인다.
웹이 실제로 겪어서(사용자가 「다시 확인」을 무한 반복) 갈라 놓은 자리다.

```dart
sealed class ReportResult {}
class ReportReady   extends ReportResult { final VideoReport report; }
class ReportNotReady extends ReportResult {}
class ReportFailed  extends ReportResult { final String reason; }
class ReportMissing extends ReportResult {}
class ReportError   extends ReportResult { final String message; }
```

### 2-3. 갈래를 가르는 기준은 `analysis_job_id` 다

```
분석 영상  analysis_job_id != null      분석을 걸어 둔 것
업로드 영상 analysis_job_id == null      분석 없이 올리기만 한 것
```

🔴 **`analysis_status` 로 가르지 않는다** — 분석을 걸었지만 아직 대기 중인
클립이 「그냥 올린 것」 쪽으로 새어 나간다. 🔴 **반려된 클립은 업로드 쪽**이다
(분석을 아예 안 하므로 작업이 없는 것이 사실이다).

## 3. S3 직접 PUT — `ApiClient` 에 넣지 않는다

`ApiClient` 는 **「계약 모양 JSON + Authorization + UTF-8 디코딩」** 창구인데
S3 는 셋 다 아니다 — 토큰을 실으면 서명이 깨지고, 응답이 JSON 이 아니라
`_decode` 가 통째로 헛돈다. `core/network/presigned_upload.dart` 로 따로 둔다.

- 🔴 **바이트를 다 읽지 않는다.** `file.readAsBytes()` 면 상한인 200MB 가
  통째로 램에 올라간다. `StreamedRequest` + `openRead()` + `contentLength`
- 🔴 **`Content-Type` 은 `upload-url` 에 보낸 값 그대로** — 서명에 들어 있어
  다르면 S3 가 거절한다
- **카드 사진 올리기(작업일지 「다음에 할 것」 2번)가 같은 것을 쓴다.** 그래서
  `features/video/` 가 아니라 `core/network/` 다

## 4. 재는 것 — 이미 있는 `video_player`

계약이 `duration_ms`·`width`·`height` 를 **클라이언트가 재서** 보내라고 한다
(서버가 재려면 원본을 받아야 하고 그러면 PER-002 가 무너진다).

`VideoPlayerController.file(f)` → `initialize()` → `value.duration` · `value.size`.

- 🔴 **재고 나서 반드시 `dispose`** — 안 하면 고를 때마다 디코더가 쌓인다
- 🔴 **형식·용량만 미리 거른다**(웹 `checkClip` 이식: mp4·mov, 200MB).
  길이·해상도는 **서버가 반려 사유로 남겨야 하는 것**이라(SFR-001) 화면이
  미리 막으면 그 사유가 사라진다

## 5. 상태 — 웹의 기교 넷이 통째로 없어진다

웹은 목록이 서버 컴포넌트 prop 이라 다시 못 받아서 `added` · `removed` ·
`pubIds` · `featured` 를 **화면이 따로 기워 붙인다.** 앱은 컨트롤러가 목록의
정본을 쥐므로 **`PATCH` 응답(= 바뀐 한 줄)으로 그 줄만 갈아 끼우면 된다.**

🔴 **순서는 그대로 지킨다 — 서버가 바꾼 뒤에 화면을 바꾼다.** 먼저 바꾸고
나중에 부르면 실패했을 때 「공개 안 됨」으로 보이는데 **남에게는 계속 보인다.**
되돌릴 수 없는 쪽으로 틀리는 것이라 지우기·대표 세우기도 같은 순서다.

## 6. 🔴 폰에서 성립 안 하는 두 곳 — 여기가 재설계다

| 웹 | 앱 | 왜 |
|---|---|---|
| 리포트가 **왼쪽 칸을 덮는 판** | **전체 화면으로 민다** | 이식 지침 §2-2. 시트로 하면 레이더+항목+장면이 길어 내내 끌어야 한다 |
| 스트립이 `<video preload=metadata #t=0.1>` **N개** | **순번 칸** — 웹이 재생 주소가 없을 때 쓰는 폴백과 같은 모양 | `VideoPlayerController` N개 = 디코더 핸들 N개. 안드로이드는 동시 디코더가 몇 개 안 된다 |

⚠️ 진짜 썸네일이 필요해지면 **서버에 포스터 이미지를 요청**하는 것이 맞다
(클립마다 첫 프레임 한 장). 그때 미결 항목으로 올린다 — 앱에서 N개를 디코딩해
만드는 길로 가지 말 것.

## 7. 리포트 그림 — 웹 `ReportView` 를 그대로

오버롤 등급 칩 · 총점 · 요약 문장 · 칭호+문장 짝 · **레이더** · 「이렇게 본 장면」.

- 🔴 **칭호는 `title_earned` 가 참인 것만** 그린다. `title` 은 **모든 등급에
  있다** — 0등급도 「무너지는 축」 같은 문구를 받는다. 유무로 선을 그으면 못한
  항목에 호칭을 달게 된다(CCC 47)
- 🔴 **`skipped` 항목은 뺀다.** 0 으로도 빈 문장으로도 그리면 못한 것으로 읽힌다
- 🔴 레이더 축 색 여섯은 웹 `--ss-axis-1~6`(`#00ad64` `#0b84ff` `#d97300`
  `#8b5cf6` `#ff2d87` `#ae8c00`) **그대로 옮긴다.** 돌려 쓰지 않는다 — 넘치는
  축은 마지막 색을 쓰되 번호가 둘을 가른다
- 🔴 **이름을 축 끝에 놓지 않는다** — 한국어 이름은 길이가 제각각이라 6축에서
  서로 파고든다. **번호로 잇고** 범례에 이름을 적는다
- 🔴 구현 전에 `dataviz` 스킬을 한 번 돌린다
- ⚠️ 축이 셋 미만이면 다각형이 안 된다 — 안 그린다
- **카드 화면으로는 이 값들을 옮기지 않는다**(부록 D.5 — 카드에 수치를 안 그린다)

## 8. 안 하는 것 — 밝혀 둔다

- **분석 걸기(`analyze: true`)는 여기 없다.** 웹 `/me` 도 `analyze: false` 만
  올린다. 그래서 앱의 「분석 영상」 갈래는 **웹에서 분석한 것만** 뜬다 —
  앱 `/videos` 분석 화면은 계속 「준비 중」이다
- `POST /videos/{id}/keep` 도 분석 화면 몫이라 안 붙인다
- ⚠️ **중복 안내(`duplicate_of_video_id`)는 등록 응답에만 실린다** — 그 자리에서
  한 줄 띄우지 않으면 다시 볼 방법이 없다(웹 `lib/duplicateNotice.ts` 이식)

## 9. 시험

- `test/contract/video_repository_contract.dart` — **Mock·API 둘 다**에 물린다
- 업로드 **세 단계 순서** · 🔴 **반려(`201` + `passed: false`)가 예외가 아닌 것**
  (status 가 아니라 `passed` 로 분기) · `report` 404 **세 갈래**
- 화면: 탭 전환 · 넘기기가 끝에서 도는 것 · **대표가 서버 뒤에 바뀌는 것** ·
  삭제가 한 번 더 묻는 것
- 🔴 **되돌려서 빨개지는 것까지 본다**(앞 회차에서 「시험이 다 통과하는 것이
  위험 신호」였다)
- 🔴 `my_videos_screen_test.dart` 는 **`useMockProvider` 를 덮는다** — 앞 회차에
  홈 시험이 실제 네트워크를 부르고 있었다

## 10. 새 의존성

`image_picker` — 앨범 + 카메라. Android `READ_MEDIA_VIDEO`, iOS
`NSPhotoLibraryUsageDescription` · `NSCameraUsageDescription` 를 같이 넣는다.

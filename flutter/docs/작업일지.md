# 작업 일지

## 2026-09-22 — 「내 영상」을 붙였다 (다음에 할 것 1번)

**한 일** — 앱에 영상 흐름이 **하나도** 없던 것을 열었다. 프로필에 「내 영상」
요약 블록(대표·갈래별 편수)을 두고, 본체는 밀고 들어가는 전용 화면이다.
두 갈래 탭 · 플레이어 · 넘기기 · 스트립 · 업로드 · 삭제 · 대표 영상 ·
전체 공개 · 분석 리포트까지 웹 `MyVideos.tsx`(1,038줄) 전부를 옮겼다.
커밋 5개, 테스트 341 → **423**, `flutter analyze` 0건, APK 빌드 통과.

붙인 계약 경로 여덟 — `GET /videos` · `POST /videos/upload-url` ·
`PUT <S3>` · `POST /videos` · `GET /videos/{id}/playback-url` ·
`PATCH /videos/{id}` · `DELETE /videos/{id}` · `GET /videos/{id}/report`.

### 🔴 아직 **눈으로 못 봤다**

실기기도 `adb` 도 이 세션에 없었다(`flutter devices` 가 macOS·Chrome 만).
**시험과 빌드까지만 확인한 상태다** — 앞 회차의 「화면 버그는 추측으로 고치지
말고 기기에서 값을 찍는다」가 아직 안 끝났다는 뜻이다. 폰을 붙이면 먼저 볼 것:

1. 앨범에서 고르기가 실제로 열리는가(Android 13+ `READ_MEDIA_VIDEO`)
2. 올린 뒤 목록 맨 앞에 오는가 · 반려 사유가 그 자리에서 보이는가
3. 넘길 때 플레이어가 안 쌓이는가(몇 편 넘긴 뒤에도 열리는가)
4. 레이더가 6축에서 안 잘리는가

### 🔴 폰에서 **성립 안 해서 바꾼 둘** — 되돌리지 말 것

이식 지침 §2-2 를 어기는 자리라 그대로 옮기면 **동작을 안 한다.**

| 웹 | 앱 | 왜 |
|---|---|---|
| 리포트가 **왼쪽 칸을 덮는 판** | **전체 화면으로 민다** | 폰엔 옆이 없다. 시트로 하면 레이더+항목+장면이 길어 내내 끌어야 한다 |
| 스트립이 `<video>` **N개** | **순번 칸** | `VideoPlayerController` N개 = 디코더 핸들 N개. 안드로이드는 동시 디코더가 몇 개 안 돼서 목록이 길면 판이 통째로 안 열린다 |

⚠️ 진짜 섬네일이 필요해지면 **서버에 포스터 이미지를 요청하는 것**이 맞다
(클립마다 첫 프레임 한 장). 앱에서 N개를 디코딩해 만드는 길로 **가지 말 것.**

**이 회차에서 가장 중요한 것 셋**

- 🔴 **`report` 만 예외가 아니라 갈래(`ReportResult`)를 돌려준다.** 계약이
  404 를 **세 뜻**으로 쓴다(`REPORT_NOT_READY`·`ANALYSIS_FAILED`·
  `VIDEO_NOT_FOUND`). 앱의 「404 는 `null`」 규칙으로 뭉개면 **영영 안 될
  실패가 곧 될 것처럼** 보인다 — 웹에서 사용자가 「다시 확인」을 무한 반복하는
  것을 실제로 겪었다. 그래서 화면도 **「아직」에만 다시 볼 단추를 주고
  「실패」에는 안 준다.**
- 🔴 **웹의 그림자 상태 넷이 통째로 없어졌다.** 웹은 목록이 서버 컴포넌트
  prop 이라 다시 못 받아서 `added`·`removed`·`pubIds`·`featured` 를 화면이
  기워 붙인다. 앱은 컨트롤러가 목록의 정본을 쥐므로 **`PATCH` 응답(= 바뀐 한
  줄)으로 그 줄만 갈아 끼우면 된다.** 대신 **낙관적 갱신을 하나도 안 뒀다** —
  서버가 바꾼 뒤에 화면을 바꾼다(먼저 바꾸면 실패했을 때 「공개 안 됨」으로
  보이는데 **남에게는 계속 보인다**).
- 🔴 **S3 직접 PUT 은 `ApiClient` 에 안 넣었다**(`core/network/presigned_upload.dart`).
  그쪽은 「계약 JSON + Authorization + UTF-8」 창구인데 S3 는 셋 다 아니다 —
  토큰을 실으면 **서명이 깨진다.** 🔴 그리고 **바이트를 다 읽지 않는다**:
  상한 200MB 를 `readAsBytes()` 로 받으면 통째로 램에 올라가 폰에서 죽는다.
  **카드 사진 올리기(다음 2번)가 같은 것을 쓴다** — 그래서 `core/` 에 있다.

### 🔴 이번에 데인 것 — 다시 밟지 말 것

- 🔴 **라우터 시험이 실제 네트워크를 부르고 있었다.** `useMockProvider` 를
  안 덮어서 카드·스쿼드가 API 구현체를 잡고 있었는데, 프로필에 영상 블록이
  붙으며 「트리를 버린 뒤에도 타이머가 남았다」로 **비로소 터져서 드러났다.**
  앞 회차에 홈 시험이 겪은 것과 **같은 결함**이 다른 파일에 남아 있었다 —
  새 화면을 물릴 때 그 파일의 override 부터 본다
- 🔴 **되돌려서 빨개지는 것까지 봤다** 셋: 「대표는 사람당 하나」(그 로직 제거) ·
  「호칭은 `title_earned` 가 참인 것만」(`title != null` 로 되돌림 — 0등급도
  「무너지는 축」 같은 문구를 받는다) · 「대표·공개 단추의 갈래 분리」
- ⚠️ **Riverpod 3.4 에 `AsyncValue.valueOrNull` 이 없다** — `value` 가 이미
  널 허용이다. 옛 코드를 보고 따라 쓰면 컴파일이 안 된다
- ⚠️ **레이더 색은 눈으로 고르지 않았다.** `dataviz` 검사기를 어두운 바탕으로
  돌려 여섯 전부 통과(최악 인접쌍 ΔE 10.4 deutan, 기준 8). 🔴 **8축이 되면
  (공 검출기가 붙어 `deferred:` 둘이 풀리면) 색 둘을 미리 만들지 말고 여덟을
  다 놓고 다시 돌린다** — 기존 여섯의 간격도 함께 바뀐다

**새 의존성** — `image_picker`(앨범+카메라). Android `READ_MEDIA_VIDEO`
(13+ 에서 갈라진 권한 — 옛 이름만 두면 **앨범이 비어 보인다**) · `CAMERA` +
`uses-feature required="false"`(안 두면 카메라 없는 기기가 스토어에서
걸러진다) · iOS 사진/카메라/마이크 설명 문구(🔴 **없으면 권한 거부가 아니라
크래시다**).

**안 한 것 — 밝혀 둔다**

- **분석 걸기(`analyze: true`)는 여기 없다.** 웹 `/me` 도 `analyze: false` 만
  올린다. 그래서 앱의 「분석 영상」 갈래는 **웹에서 분석한 것만** 뜬다 —
  앱 `/videos` 분석 화면은 계속 「준비 중」이다
- `POST /videos/{id}/keep` 도 분석 화면 몫이라 안 붙였다

설계는 `2026-09-22-내-영상-design.md`.

**다음에 할 것** (앞 회차 목록에서 1번을 지웠다)
1. **카드 사진 올리기** — S3 사전 서명 두 단계(`POST /me/card/photo-upload-url`).
   🔴 `presigned_upload.dart` 가 이미 있으니 그걸 쓴다
2. **내 경기** — `GET /teams/{id}/matches` (지금은 「다가오는 경기가 없습니다」 고정)

## 2026-09-21 — 카드·스쿼드를 서버에 붙였다 (1단계)

**한 일** — 앱이 자기 데이터를 모르던 상태를 끝냈다. `GET /me`(teams) ·
`GET /me/card` · `GET /teams/{id}/squad` · `GET /cards/{slug}` 넷이 붙어서,
**웹에서 만든 팀·팀원·카드가 앱 홈 판에 그대로 뜬다.** 이어서 자동 착석 ·
자리 끌어 옮기기 · 판에서 빼기(⊗) · 카드 꾸미기(읽기+편집) · 내 프로필 화면까지
붙였다. 커밋 22개, 테스트 117 → **341**, `flutter analyze` 0건.

### 🔴🔴 하루에 다섯 번 헤맨 것 — **판의 자리는 격자 위를 돌아다닌다**

카드를 끌어 옮기면 **내 카드가 사라지고** 남의 카드를 옮기면 **다른 카드가
딸려 갔다.** 사용자가 실기기에서 세 번 돌려보내는 동안 나는 네 번 고쳤고
**앞의 셋은 엉뚱한 데를 고쳤다.**

원인은 **웹 구조를 잘못 읽은 것**이다. 포메이션(`kFormations`)을 「자리가 이
다섯 칸에 있다」로 옮겼는데, 웹은 그걸 **처음 배치**로만 쓰고 자리 자체가
격자(3열×4행) 위를 옮겨 다닌다. 그래서 FW·MF·DF 줄은 **세 칸 다** 쓸 수 있고
골키퍼 줄만 가운데 하나다.

`seatsFromSquad` 의 1단계는 「그 칸에 자리가 없으면 남는 자리를 옮겨 온다」
폴백을 갖고 있는데 **0단계(내 등재)에만 없었다.** 그래서 내 카드를 포메이션에
없던 칸으로 옮기면 판에서 사라졌다.

🔴 **어떻게 잡았나 — 기기에 로그를 찍었다.** 목업 시험은 셋 다 초록이었다.
실기기에 `print` 를 넣은 빌드를 올리고 나서야 한 줄로 드러났다:

```
drop from=(1,0) to=(col:2, row:0)
build ... 백성검@2,0        ← 5:5 에 (2,0) 자리가 없다
```

🔴 **화면 버그는 추측으로 고치지 말고 기기에서 값을 찍는다.** 처음부터
그렇게 했으면 네 번이 한 번이었다.

⚠️ **고치다 반대쪽으로도 지나쳤다** — 「자리 위에만 놓기」로 막았더니 격자
12칸에 자리가 다섯뿐이라 **사실상 못 옮기게** 됐다(사용자: 「아예 못 옮기게
만들면 어떡해」). 규칙은 **놓을 수 없는 칸만 막는 것**이다(골키퍼 줄 양옆).

설계는 `2026-09-21-카드-스쿼드-서버연결-design.md`, 계획은
`plans/2026-09-21-카드-스쿼드-서버연결-1단계.md`(1단계 배선까지만 적혀 있다 —
그 뒤 다섯은 계획 없이 이어 갔다).

**이 회차에서 가장 중요한 것 셋**

- 🔴 **붓자국 씨앗이 `user.id` → 카드의 `public_slug` 로 바뀌었다.** 그동안
  같은 카드가 웹과 앱에서 **다른 무늬**였다. 이제 같다.
- 🔴 **내 자리가 포메이션에 박혀 있던 것을 걷었다.** 웹이 2026-09-16 에 뒤집은
  규칙인데 앱은 그 이전 상태였다 — 등재하지 않은 사람도 판에 서 있었다. 이제는
  등재했을 때만, 내가 앉힌 칸에 선다.
- 🔴 **내 팀을 얻는 데 새 경로가 필요 없었다.** 계약이 이미 `GET /me` 에
  `teams[]` 를 실어 주는데 `_fetchMe()` 가 버리고 있었다. **없는 줄 알고 요청을
  올릴 뻔했다** — 계약 문서를 먼저 읽어서 막았다.

**HTTP 공통을 `ApiClient` 로 끌어올렸다**(`lib/core/network/api_client.dart`).
토큰 보관 · UTF-8 디코딩 · 에러 `code` · `Retry-After` 가 `ApiAuthRepository`
안에만 있었는데 카드·스쿼드가 같은 것을 필요로 한다. 복붙하면 세 벌이 되고,
특히 「`response.body` 를 쓰면 한글이 깨진다」를 한 곳이라도 빠뜨리면 **거기서만**
글자가 깨진다. `ApiException` 에 `status` 를 실은 것은 **404 를 「오류」가 아니라
「없음」으로 다뤄야 하는 자리**가 있어서다.

🔴 **404 만 `null` 로 바꾸고 401·403·500 은 그대로 올린다.** 삼키면 「로그인이
풀렸다」·「소속이 아니라 못 본다」가 「아직 안 만들었다」로 보여, 화면이 빈 카드를
그리며 조용히 잘못된 상태에 머문다.

**자리 배치는 웹 `seatsFromSquad` 를 순수 함수로 옮겼다**(3단계: 내 등재 → 칸이
저장된 등재 → 칸 없는 등재). **재해석하지 않았다** — 단계마다 실제 사고에서 나온
이유가 있다.

### 🔴 이번에 데인 것 — 다시 밟지 말 것

- 🔴 **시험이 통과하는 것만으로는 모자라다.** 자리 배치를 옮긴 뒤 18개가 다
  초록이었는데, 진짜 붙드는지 보려고 **두 가지로 되돌려 봤다**: ⑴ 2단계에서
  `me` 를 건너뛰게 하면 「칸 없는 내 등재도 앉는다」가 빨개진다(웹이 2026-09-18 에
  데인 그 버그) ⑵ `copy()` 를 빼면 「포메이션 상수를 더럽히지 않는다」가 빨개진다.
  **둘 다 빨개지는 것을 본 뒤에야** 옮기기가 끝난 것으로 쳤다
- 🔴 **홈 시험이 실제 네트워크를 부르고 있었다.** `cardRepositoryProvider` 를
  override 안 해서 API 구현체가 잡혔다. 교체 지점이 `useMockProvider` 하나라
  거기만 덮으면 둘 다 따라온다 — 시험이 서버 상태에 따라 흔들리면 안 된다
- ⚠️ **Mock 지연이 줄줄이 걸린다.** 로그인이 끝나야 `teams` 를 알아 스쿼드를
  부르고, 스쿼드가 와야 팀원 카드를 부른다. 300ms × 3 이라 위젯 시험에서
  흘려보내는 시간이 모자라면 「트리를 버린 뒤에도 타이머가 남았다」로 깨진다 —
  **화면 잘못이 아니다**
- ⚠️ **기존 시험 셋이 옛 동작을 재고 있었다**(내 자리가 판에 박혀 있던 시절).
  기대를 뒤집으면서 **왜 뒤집는지를 그 시험 주석에** 적었다 — 안 적으면 다음
  사람이 「왜 이렇게 되어 있지」에서 멈춘다
- ⚠️ **폰이 또 끊겼다.** `adb devices` 가 비면 `ADB_LIBUSB=1` 로 adb 서버를
  다시 띄운다(2026-09-15 에 적어 둔 그 함정 — 이번에도 그걸로 풀렸다)

커밋 66개, 테스트 83개 통과, `flutter analyze` 0건. `paik` 브랜치에 푸시 완료.

**작업 범위** — `flutter/` 폴더 안만. `jekyll/`·`_config.yml` 등 저장소의 다른 파일은
건드리지 않는다(1인 1브랜치, 다른 담당자 영역).

**구조의 핵심 — 백엔드 없이 만든다**
- 화면은 리포지토리 **인터페이스만** 안다. Mock이 데이터를 준다.
- API가 나오면 `*_providers.dart`의 **provider 한 줄**만 바꾼다(auth/sport/chat 세 곳).
- 그게 진짜 되는지는 `test/contract/`의 계약 테스트가 보증한다 — 나중에 같은 파일을
  API 구현체에 그대로 물린다.
- Mock은 지연·실패·빈 목록을 흉내낸다. 즉시 성공하면 로딩·오류 화면을 안 만들게 된다.

**연출은 `com.sumworship`에서 가져왔다** — 잉크 번짐(인트로·화면 전환), 굴절 유리(로그인
시트·홈 카드·하단 바), 하단 바와 그 메뉴. 두 셰이더의 규칙이 **정반대**라 헷갈리지 말 것:
잉크는 `Paint.shader`라 논리 픽셀에 가드가 필요 없고, 유리는 `ImageFilter.shader`라 물리
픽셀에 `isShaderFilterSupported` 가드가 필수다.

**되풀이해 걸린 함정 셋**
- **유리 안에 유리를 넣지 않는다.** 안쪽이 아직 안 끝난 바깥을 읽어 내용이 프레임째로
  사라진다. 층을 내려면 흐림 없이 색만 얹는다(로그인 버튼·채팅 말풍선이 그 방식).
- **위젯 테스트에서 `pumpAndSettle` 금지.** 무한 애니메이션(도는 테두리 빛, 인디케이터)이
  있어 안 멎는다. `pumpWidget` → 트리거 → `pump(500ms)` 관용구를 쓴다.
- **`pumpWidget` 전에 Mock Future를 await하지 않는다.** 가짜 시계가 안 흘러 10분
  타임아웃까지 멈춘다.

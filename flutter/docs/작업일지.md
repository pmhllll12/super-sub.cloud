**작업 범위** — `flutter/` 폴더 안만. `jekyll/`·`_config.yml` 등 저장소의 다른 파일은
건드리지 않는다(1인 1브랜치, 다른 담당자 영역).

**구조의 핵심 — 백엔드 없이 만든다**
- 화면은 리포지토리 **인터페이스만** 안다. Mock이 데이터를 준다.
- API가 나오면 `*_providers.dart`의 **provider 한 줄**만 바꾼다(auth/sport/chat 세 곳).
- 그게 진짜 되는지는 `test/contract/`의 계약 테스트가 보증한다 — 나중에 같은 파일을
  API 구현체에 그대로 물린다.
- Mock은 지연·실패·빈 목록을 흉내낸다. 즉시 성공하면 로딩·오류 화면을 안 만들게 된다.

**연출은 `com.sumworship`에서 가져왔다** — 잉크 번짐(인트로·화면 전환), 굴절 유리(로그인
시트·홈 카드·하단 바), 하단 바와 그 메뉴. 두 셰이더의 규칙이 **정반대**라 헷갈리지 말 것:
잉크는 `Paint.shader`라 논리 픽셀에 가드가 필요 없고, 유리는 `ImageFilter.shader`라 물리
픽셀에 `isShaderFilterSupported` 가드가 필수다.

**되풀이해 걸린 함정 셋**
- **유리 안에 유리를 넣지 않는다.** 안쪽이 아직 안 끝난 바깥을 읽어 내용이 프레임째로
  사라진다. 층을 내려면 흐림 없이 색만 얹는다(로그인 버튼·채팅 말풍선이 그 방식).
- **위젯 테스트에서 `pumpAndSettle` 금지.** 무한 애니메이션(도는 테두리 빛, 인디케이터)이
  있어 안 멎는다. `pumpWidget` → 트리거 → `pump(500ms)` 관용구를 쓴다.
- **`pumpWidget` 전에 Mock Future를 await하지 않는다.** 가짜 시계가 안 흘러 10분
  타임아웃까지 멈춘다.

# 08. 테스트 및 검증 계획

## 테스트 전략

### 1) 단위 테스트 (Unit Test)
- 각 모듈(인증, 매칭, 실력분석 등)의 함수/로직 단위 검증
- 목표 커버리지: [TBD]%

### 2) 통합 테스트 (Integration Test)
- API 간 연동, DB 트랜잭션 검증
- 매칭 → 평가 → 실력분석 반영까지 end-to-end 플로우 검증

### 3) 사용자 테스트 (User Test)
- 베타 사용자 그룹(예: 실제 동호회 [TBD]팀) 대상 시범 운영
- 사용성(UI/UX), 매칭 성사율, 실력분석 만족도 피드백 수집

### 4) 부하/성능 테스트
- 동시 접속/검색 요청에 대한 응답 시간 측정
- **측정 방식**: API 서버가 요청 지연을 히스토그램으로 수집해 표준 관측 형식
  (Prometheus)으로 내보내고, P95·P99 는 그 히스토그램에서 분위수로 산출한다.
  분석은 비동기이므로 작업 소요 시간(PER-001)은 작업 상태 레코드가 별도로 기록한다.
- 목표 지표: 조회·검색 P95 500ms 이내(PER-003), 분석 작업 목표 소요 시간은 정식
  서빙 환경에서 재측정해 확정(PER-001)

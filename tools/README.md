# `tools/` — 사이트 페이지·그림을 **만들어 내는** 스크립트

여기 있는 것은 **공개 사이트에 커밋된 결과물을 생성한 원본**입니다.
`jekyll/progress/` 의 세 페이지, `06-시스템설계.markdown` 1절, `assets/erd/` 의
ERD 그림 9장은 **손으로 쓴 것이 아니라 여기서 나왔습니다.**

🔴 **그래서 그 페이지들의 그림·수치는 페이지를 직접 고치지 마십시오.** 다음에
누가 여기를 다시 돌리면 조용히 덮입니다. 값이 바뀌었으면 **스크립트를 고쳐서
다시 만듭니다.**

> 2026-09-18 에 저장소 밖(git 추적 대상이 아닌 개인 작업 폴더)에서 옮겨 왔습니다.
> 전에는 만든 사람 PC 에만 있어서, **페이지는 팀 것인데 고칠 방법은 한 사람만
> 갖는** 상태였습니다. 담당은 정어진이지만 누구나 돌릴 수 있어야 하는 것이라
> 여기 둡니다.

Jekyll 빌드에서는 빠져 있습니다(`_config.yml` 의 `exclude:`) — `fastapi/`·`www/`
와 같은 처리입니다. **git 에는 그대로 있으니 `pull` 하면 받습니다.**

## 공통 규칙

- **파이썬 표준 라이브러리만** 씁니다(`tools/erd/dump_schema.py` 만 예외 — 아래).
  `python3 <파일>` 로 그냥 돌아갑니다.
- **저장소 루트는 스크립트가 자기 위치에서 구합니다**(`Path(__file__).resolve().parents[2]`).
  🔴 **절대경로를 박지 마십시오** — 사람마다 체크아웃 경로가 다르고, 박아 두면
  남의 PC 에서 **오류도 없이** 엉뚱한 곳에 쓰거나 아무것도 안 씁니다. (옮겨 오기
  전까지 여섯 파일 전부가 그랬습니다.)
- **어느 디렉터리에서 돌려도 결과가 같습니다.** `cd` 로 맞출 필요 없습니다.
- 파일을 쓸 때는 `newline="\n"` 을 명시합니다 — 이 저장소는 LF 입니다.

## 돌리기 전에 — 지금 페이지를 그대로 재현하는지 먼저 봅니다

🔴 **이것이 이 폴더에서 제일 중요한 습관입니다.** 스크립트와 페이지가 어긋나
있으면(누가 페이지를 손으로 고쳤다든지) 다시 돌리는 순간 **그 사람 수정이
사라집니다.** 그래서 **고치기 전에 한 번 그냥 돌려 봅니다.**

```bash
git status --porcelain          # 먼저 깨끗해야 합니다(되돌릴 수 있어야 하므로)
python3 tools/pages/gen_overview.py
python3 tools/pages/gen_backend.py
python3 tools/pages/gen_system_design.py
git status --porcelain          # 🔴 여기가 비어야 "재현됨" 입니다
```

**비지 않으면 스크립트를 고치기 전에 그 차이부터 봅니다** — 페이지가 앞선 것인지
스크립트가 앞선 것인지 정하고 나서 손댑니다.

## `tools/pages/` — 페이지 생성기 (다시 돌려도 됩니다)

| 파일 | 만드는 것 |
|---|---|
| `gen_overview.py` | `jekyll/progress/10-프로젝트전체그림.markdown` · `12-진행현황.markdown` |
| `gen_backend.py` | `jekyll/progress/11-백엔드파이프라인.markdown` |
| `gen_system_design.py` | `jekyll/chapters/06-시스템설계.markdown` 의 **1절만** (`## 1) 시스템 구성도` ~ `## 2) 데이터베이스 설계` 직전) |

셋 다 **멱등(같은 입력이면 같은 출력)** 입니다 — 2026-09-18 에 확인했습니다.

- 수치는 스크립트 안에 상수로 박혀 있고, **그 수치를 다시 뽑는 명령은 해당
  페이지 하단**에 있습니다. 값을 갱신할 때는 그 명령을 돌려 얻은 값을 스크립트에
  넣고 다시 만듭니다.
- 🔴 `gen_system_design.py` 는 **1절만** 건드립니다. 3·4절(파이프라인·AI 에이전트)은
  정상호 영역이라 손대지 않습니다.
- 그림 색은 `dataviz` 검증기를 통과한 값입니다. 사람별 색은 팀 `CLAUDE.md` 의
  팀 구성 순서에 맞춰 고정돼 있습니다 — 바꾸면 세 페이지가 서로 어긋납니다.
- 🔴 인라인 SVG 에는 `viewBox` 폭과 같은 `width` 속성을 줍니다. `max-width:100%`
  만 있으면 넓은 화면에서 1,200px 까지 커집니다(2026-09-17 에 겪었습니다).

## `tools/erd/` — 부록 D 의 ERD 그림

```bash
# 1) ORM 메타데이터를 JSON 으로 뽑습니다 (DB 접속은 필요 없습니다)
fastapi/.venv/bin/python tools/erd/dump_schema.py /tmp/schema.json

# 2) assets/erd/ 의 SVG 9장을 다시 만듭니다
python3 tools/erd/gen_erd.py /tmp/schema.json

# 3) 🔴 무엇이 진짜로 바뀌었는지 봅니다 (아래 설명)
python3 tools/erd/compare_svg.py <옛 그림 폴더> assets/erd
```

🔴 **`dump_schema.py` 만 `fastapi/.venv` 로 돌립니다** — SQLAlchemy 와 모든
`*_orm.py` 를 임포트해야 하기 때문입니다. 나머지는 `python3` 로 충분합니다.

### 🔴 다시 돌리면 **안 바뀐 그림도 diff 가 납니다**

ORM 메타데이터 순회 순서가 실행마다 달라서, 내용이 같아도 `<g>` 조각이 **다른
순서로** 나옵니다. 그대로 커밋하면 뜻 없는 diff 가 되어 **나중에 "이 그림이 왜
바뀌었나" 를 볼 때 진짜 변경이 묻힙니다.**

그래서 **바이트 diff 를 믿지 말고** `compare_svg.py` 로 내용을 비교합니다 —
`<g>` 조각을 정렬해 집합으로 봅니다. `같음` 으로 나온 것은 되돌리고
(`git checkout -- assets/erd/<파일>`), `다름` 으로 나온 것만 올립니다.

돌리기 전에 현재 그림을 어딘가로 복사해 두면 비교가 쉽습니다:

```bash
cp -r assets/erd /tmp/erd-backup
python3 tools/erd/gen_erd.py /tmp/schema.json
python3 tools/erd/compare_svg.py /tmp/erd-backup assets/erd
```

### ⚠️ `gen_appendix_d.py` 는 **일회성이고 이미 적용됐습니다** — 다시 안 돕니다

부록 D **본문**(D.3 외래키 표 · D.7 유일 제약 표 · 사실이 바뀐 문장들)을
2026-09-17 에 실제 스키마로 맞춘 스크립트입니다. 바꿀 원문을 `assert old in s`
로 확인하고 치환하는 방식이라, **이미 적용된 지금 다시 돌리면 그 단언에서
멈춥니다**(쓰기는 맨 끝이라 저장소는 안 건드립니다).

```

```

**그래도 남겨 둡니다** — D.3·D.7 표를 `schema.json` 에서 **어떻게 계산했는지**가
여기 있어서, 다음에 부록 D 를 갱신할 때 그 계산을 다시 짜지 않아도 됩니다.
도구가 아니라 **기록으로** 보십시오.

## 여기에 없는 것

- **시연 더미 운영용 일회성 스크립트** — 운영 자원을 직접 건드리는 것이고 시연이
  끝나면 버릴 것이라 저장소에 넣지 않았습니다.
- **각자의 개인 작업 파일** — 공유 대상이 아닙니다.

## 새 생성기를 더할 때

1. 위 **공통 규칙** 을 지킵니다(절대경로 금지 · `newline="\n"` · 표준 라이브러리).
2. **만드는 파일을 이 README 표에 적습니다.** 안 적으면 다음 사람이 그 페이지를
   손으로 고치고, 그 수정은 다음 실행에서 사라집니다.
3. 생성된 페이지 하단에 **그 수치를 다시 뽑는 명령**을 답니다.
4. 🔴 공개 사이트에 나가는 내용이므로 팀 `CLAUDE.md` 의
   「공개 사이트에 인프라 식별자를 쓰지 않습니다」 검사를 거칩니다.
